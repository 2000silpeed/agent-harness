# 10. Harness: 모델을 뺀 나머지 전부

## 정의 [강의]
- **Prompt**는 지시, **Context**는 제공하는 정보, **Harness**는 실행 환경입니다. 여기에 Graph(작업, 상태, 의존)와 Loop(반복, 재시도, 종료) 관점을 더합니다.
- 하네스는 "프롬프트만으로 루프를 제어할 수 없는 부분을 프로그램으로 다루려는 것"에서 시작했습니다. 하네스부터는 대부분 코딩입니다.
- 엔지니어링 이름(프롬프트, 컨텍스트, 하네스…)에 FOMO를 느낄 필요는 없습니다. "대부분 말장난"입니다.

## 구성요소 [강의]
| 요소 | 내용 | 이 저장소에서 |
|---|---|---|
| Tools | 호출, 입력 검증 | 05 문서, `examples/stepguard.py` |
| Context | 무엇을 언제 넣나 | 01~04 문서 |
| State | 저장과 재개 | 파일·DB 영속 저장(메모리 전용 체크포인터 금지) |
| Permissions | 권한과 승인 | `.claude/settings.json`, 제안-실행 분리 |
| Budget | 호출·시간 한도 | max turns, 예산 |
| Agent Loop | 반복과 종료 | 종료 조건 필수 |
| Trace·Eval | 기록과 평가 | 13, 14 문서 |

## 실패 유형별 다음 행동 [강의]
| 결과 | 다음 행동 |
|---|---|
| PASS | 응답하고 종료 |
| 근거 부족 | 예산을 확인한 뒤 재조사 |
| 정책상 불가 | 실행하지 않고 이유를 안내 |
| 시스템 오류 | 상태를 확인한 뒤 재시도하거나 사람에게 전환 |

## 승인과 재시도 [강의]
```
처리 제안(MODEL) → 정책·권한(RULE) → 승인(HUMAN/CODE) → 쓰기 실행(API) → 결과 확인(STATE)
```
- 실행 전후에 Checkpoint와 처리 상태를 남기고, 요청 키와 외부 결과 조회로 중복을 막습니다.
- `idempotency_key`는 외부 시스템이 지원할 때만 의미가 있습니다. Checkpoint로 재개해도 exactly-once가 보장되지는 않습니다.

## 프롬프트 = 작업 계약 [강의]
"너는 환불 전문가야"는 역할만 있고 계약이 없습니다. 계약 템플릿은 [`templates/prompt-task-contract.md`](../templates/prompt-task-contract.md)입니다.

## 완성형 그림 [강의]
```
HARNESS(상태·권한·예산·Trace·복구)
  본인·권한 확인 → 의도 Router ─┬─ FAQ/단순 조회 ─────────────┐
                               └─ O-W 조사(Worker별 Context) ─┤
                                                             ▼
                      답변/처리 제안(근거 + 불확실성) → [쓰기 요청만] 공통 검증·승인 → 실행 → 결과 확인 → 응답 or 사람 전환
```

## 마지막 질문 체크리스트 [강의]
1. 업무 목표: 완료 상태는 무엇인가?
2. 작업 Graph: 순차, 병렬, 분기, 루프는?
3. Agent·SubAgent가 필요한 이유: 코드나 Skill로 충분하지 않은 이유는?
4. Context와 권한: 누가 무엇을 보고 할 수 있나?
5. 예산과 종료: 언제 멈추나?
6. 평가 근거: 무엇으로 좋아졌다고 말하나?

> "Agent 수가 아니라, 설계 이유가 결과물입니다."
