# 5. 도구와 구조화 출력

## 도구 = 이름 + 설명 + 인자 스키마 [강의]
```json
{"name": "get_weather", "description": "실시간 날씨", "args": {"location": {"type": "string", "description": "도시명"}}}
```
- **도구 호출은 메시지일 뿐이고, 실행은 런타임이 합니다.** 실행 여부, 순서, 오류 처리는 우리가 제어합니다. 오류는 ToolMessage로 명확히 돌려줍니다.
- 순서 의존이 없으면 비동기로 실행하고, 있으면 순서대로 실행하는 도구로 묶습니다.
- 구조화 출력(response_format)도 도구 호출 관점으로 봅니다. 규격이 단순하면 거의 실패하지 않습니다. **인자가 많거나, 설명이 길거나, 중첩이 깊으면** 실패율이 올라갑니다.

## 도구를 늘리지 않는다 [강의]
- Claude가 생성한 코드가 검색과 저장을 감싸는 래퍼 도구를 새로 만들어 기존 파일 도구와 역할이 겹친 사례가 있었습니다. "이런 도구를 계속 뒤로 늘리는 건 별로 좋은 방향이 아니에요."
- 개선 방향은 **기존 파일 도구에 저장 규칙과 위치만 지시하는 것**입니다. 예: `sample_data/tavily/*.json`
- 과제 프롬프트에는 "**기본 도구 외에 새 도구를 만들지 마라**"를 넣습니다.

## 코드 읽는 법 [강의]
반환부(`return`)부터 거꾸로 따라갑니다. 예: `create_deep_agent` → `create_agent` → middleware
