# 7. Workflow vs Agent: 어디에 에이전트를 둘까

## 결정권의 차이 [강의]
- **Workflow**는 코드가 정한 경로 안에서 실행합니다. **Agent**는 모델이 결과를 보고 다음 행동을 고릅니다.
- "LLM을 사용한다고, 모두 Agent는 아닙니다." 판별 기준은 도구 호출 여부가 아니라 **관찰한 뒤의 행동 선택과 종료 조건**입니다.
- "좋은 Agentic System은 모든 노드가 Agent인 시스템이 아닙니다." Workflow 안에 Agent를 넣으면 됩니다.

## 업무를 먼저 나누고, 필요한 곳에만 [강의]
- 출발점은 아키텍처가 아니라 **워크플로우**입니다. 구조를 먼저 정해 놓고 업무를 끼워 맞추지 않습니다.
- 에이전트를 둘 곳은 **사람이 지식이나 데이터를 보며 판단하는 지점**입니다. 루틴하거나 규정이 정해진 업무는 "사실 대부분 코드가 할 수 있습니다."
- 각 단계에 **판단 / 생성** 라벨을 붙입니다. 둘이 함께 있는 단계가 에이전트 후보입니다. 단, "무조건은 없다."
- 담당 구분
  - 코드: 인증, 조회, 한도, 쓰기 실행
  - 모델: 의도, 계획, 근거 종합
  - 사람: 돈이 오가거나 민감 정보를 바꾸는 일의 승인

## 제안과 실행 권한은 다르다 [강의]
```
모델의 처리 제안 → 실행 검증 게이트(정책·권한·입력, 필요하면 사람 승인) → 통과한 요청만 쓰기 도구
                                     └ 거절·보류 → 실행하지 않거나 사람에게 넘김
```
"모델은 행동을 제안하고, 시스템은 허용된 행동만 실행합니다."

## 설계 순서 [강의]
작업 목표 → 작업 Graph(순차, 병렬, 분기, 루프) → 어디에 판단을 맡길까 → Context 분리 → 검증과 운영(상태, 권한, 예산, 종료)
