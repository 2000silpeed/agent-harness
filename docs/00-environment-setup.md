# 0. 작업 환경 세팅

## 원칙 [강의]
- **CLI를 가장 추천합니다.** 데스크톱 앱의 Code 메뉴도 됩니다. VS Code 익스텐션은 세션 탭 관리가 어렵고 백그라운드 에이전트를 볼 수 없어 비추천입니다.
- Windows에서는 **WSL**에서 실행합니다. 작업 폴더를 지정하고 짧은 메시지로 응답을 확인합니다.
- 시작 설정은 **Sonnet, 노력(effort) 중간**입니다. Opus는 설계, 검토, 어려운 문제에만 씁니다.
- **권한 우회(bypass) 모드는 상시 쓰지 않습니다.** "굉장히 위험"합니다.
- Python 환경 구성은 "환경 설정 해줘" 한 줄로 맡겨도 됩니다(uv 설치, 루트 `.venv` 생성).
- **API 키는 사람이 직접 입력합니다.** `.env.example`을 `.env`로 복사한 뒤 손으로 채웁니다. "이거는 당연히 클로드랑 작업하시면 안 돼요."
- 키를 바꿨으면 커널이나 프로세스를 재시작해 다시 로드합니다.
- 무거운 멀티 에이전트, 장시간 루프, 바이너리 분석은 토큰 소모가 큽니다. 회사 계정 한도에 영향을 주지 않도록 **개인 계정이나 작은 범위에서 먼저 검증합니다.**

## 하네스 적용 [제안]
- `.claude/settings.json`이 `.env`, `.env.*`, `secrets/` 읽기와 쓰기를 거부하도록 설정되어 있습니다.
- `.claude/hooks/log-tool-use.sh`가 도구 호출을 `.harness/logs/tool-use.jsonl`에 기록합니다. 감시용이며 `.gitignore`에 포함되어 있습니다.

## 체크리스트
- [ ] CLI(또는 데스크톱 앱 Code)에서 작업 폴더를 열었다
- [ ] 모델과 effort가 작업에 맞다(대화형 작업은 Sonnet medium / Opus low, 문서 기반 장시간 작업은 high 이상)
- [ ] `.env`는 손으로 만들었고 커밋되지 않는다
- [ ] bypass 모드가 꺼져 있다
