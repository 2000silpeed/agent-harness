# 3. 멀티턴 기억 관리

## 멀티턴은 허상이다 [강의]
자기회귀 모델에는 시스템, 도구 정의, 기억, 맥락, 질문이 **하나로 펼친 텍스트**로 들어갈 뿐입니다. "멀티턴이라는 건 모델한테는 존재하지 않아요." 따라서 우리가 제어할 것은 **매번 펼친 입력에 무엇을 넣고 뺄지**입니다.

## 사용자는 멀티턴, 내부는 단일턴 [강의]
- "AI는 단일턴일 때 성능이 제일 좋다." 매 질문마다 시스템 프롬프트, 스킬, 데이터를 엮어 단일턴으로 처리합니다. 대화 세션은 파일로 모아 뒤에서 관리합니다.
- 압축(compact)만으로는 기억이 약해집니다. 압축하면 중요한 내용이 빠집니다. 압축 모델로는 보통 가장 싼 모델을 씁니다.

## 구조 [강의]
1. **한 줄 저장**: 답변을 저장할 때부터 핵심 한 줄로 줄여 둡니다. 원본 질문과 답변은 따로 DB나 파일에 보관합니다.
2. **주제 변경 감지**: 매 턴 작은 모델이나 디시전 모델이 `0`(주제 유지) 또는 `1`(주제 변경)만 출력합니다. 출력이 짧고 반복 입력은 캐시되므로 쌉니다.
3. **2단계 요약**
   - 1단계: 주제가 바뀌면 그 주제를 한 줄로 요약하고 원본 링크와 함께 메모리에 둡니다. 대부분 여기서 끝납니다.
   - 2단계: 그 주제가 다시 불리면 원본을 찾아 육하원칙식 상세 요약을 만듭니다.
4. **메모리 = 원본으로 가는 작은 표지판**: `2026-11-03 RAG production rag | samsung sds → 원본 경로`

## 메시지 이력은 사실 보증이 아니다 [강의]
- 가짜 답변을 이전 턴으로 넣으면 모델이 정정합니다. 하지만 **가짜 도구 호출 기록은 사실로 믿습니다.** 이것은 공격 수법이기도 합니다(메시지 누적 공격). 컨텍스트를 별도 세션으로 관리하면 보안 검사를 넣을 지점이 생깁니다.

## 하네스 적용 [제안]
- Claude Code 세션도 주제 단위로 끊습니다. 끊기 전에 `session-memory` 스킬로 `memory/YYYY-MM-DD-<topic>.md`를 남깁니다.
- 주제 변경 판단 프롬프트는 [`templates/closed-question.md`](../templates/closed-question.md)에 있습니다.

## 안티패턴
- 대화 전체를 계속 이어 붙이기
- 모든 대화를 미리 상세 요약하기
- 판단 단계에서 장문 출력을 받기
- 비싼 모델로 감시 루프 돌리기
