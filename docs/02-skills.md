# 2. 스킬: 조각 지식

## 배경지식 주입 방식의 변화 [강의]
1. 파인튜닝은 비용 때문에 선택지가 아닙니다.
2. 시스템 프롬프트에 지식을 길게 쓰는 것은 구버전 방식입니다.
3. 상황마다 프롬프트를 치환하면 **캐시가 깨집니다**.
4. **시스템 프롬프트는 짧게 고정하고, 지식은 뒤에 스킬로 붙입니다.** 이것이 요즘의 RAG입니다.

## 구조 (agentskills.io 형식) [강의]
```
my-skill/
  SKILL.md        # 필수: frontmatter name, description
  references/     # 선택
  scripts/        # 선택
  assets/         # 선택
```
- `description`에는 **무엇을(what)과 언제(when)** 쓰는지를 적습니다. 모델은 처음에 name과 description만 보고, 쓸지 판단한 뒤에 본문을 읽습니다(지연 로드).
- 스킬에는 **문서에 없는 현장 지식**을 씁니다. 규정 문서 자체는 데이터입니다. 휴가 스킬이라면 "추석·창립기념일 앞뒤로 붙여 쓰기" 같은 팁이 스킬 내용입니다.
- 스킬이 커지면 `팁/`, `히스토리/`처럼 하위 폴더로 쪼갭니다. 이때 SKILL.md는 **안내용 인덱스**가 됩니다.
- Skill과 SubAgent는 다릅니다. Skill은 같은 에이전트가 절차를 불러오는 것이고 제어권은 유지됩니다. SubAgent는 별도 컨텍스트에서 실행되고 반환 계약이 있습니다.

## Lost in the Middle 방어 [강의]
반복하되 똑같이 반복하지 않습니다.
- 앞에서는 짧게 예고합니다. "뒤에 이런 지식이 나올 거야, 나오면 이렇게 얘기하렴"
- 뒤에서는 앞과 연결합니다. "앞에서 이렇게 얘기했었지"

## 하네스 적용 [제안]
- 새 스킬은 [`templates/skill/SKILL.md`](../templates/skill/SKILL.md)를 복사해서 만듭니다.
- 이 저장소의 스킬은 `.claude/skills/`에 있습니다.
- 스킬 목록은 세션 중에 바꾸지 않습니다. 바꿨으면 새 세션을 엽니다.
