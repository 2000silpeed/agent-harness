# 14. 근거 남기기와 비용 관리

> "돌아가는 게 중요한 게 아니죠. 근거를 남기고 사람한테 이야기할 수 있는 구조를 갖춰야." [강의, 3일차 7강]

## 근거를 남기는 네 가지 장치 [강의]
| 장치 | 용도 | 이 저장소에서 [제안] |
|---|---|---|
| 보드 | 에이전트가 사람에게 꼭 보여야 할 것을 쓰는 게시판. 아무도 로그는 안 본다 | 작업 보고는 짧게 하고, 그림이나 다이어그램을 활용 |
| 세션 기록(trajectory) | 셀프 개선의 근거 | `~/.claude/` 세션 파일, `retro` 스킬 |
| 판단·결정 기록 | 모델 라우팅 같은 판단 | `docs/decisions/` |
| DAG 노트 | 장시간 작업을 지시할 당시의 맥락을 미래의 나에게 남김 | `templates/task-note.md` |

- 기록할 때는 가설·후보와 시도·결과를 **분리**합니다(해킹 에이전트 사례). 양식은 [`templates/hypothesis-attempt-log.md`](../templates/hypothesis-attempt-log.md)입니다. [강의, 3일차 4강]
- 트레이싱 도구로는 Langfuse를 썼습니다(무료, 온프레미스 가능). [강의]

## 비용 관리 [강의]
- **출력을 줄입니다.** 출력이 길면 여러 세션을 통제하며 읽기 어렵습니다.
- **잘못 시켰으면 바로 멈춥니다.** "정답은 멈춘다예요. 기다려봤자 쓰레기가 나올 겁니다." 멈춘 뒤 "이전 거 무시하고 …"로 정정합니다.
- **캐시**
  - 캐시는 1시간 유지되지만, 세션을 여러 개 띄우면 금방 깨집니다.
  - 서브에이전트에서는 캐시 상태를 확인하기 어렵습니다.
  - 강사는 상태줄에 캐시 상태를 표시하고, 만료 직전에 짧은 메시지를 보내 캐시를 유지했습니다(선택 사항이며 비용 대비 효과를 따져 볼 것).
- PC나 계정을 옮기면 캐시가 깨집니다. 대화 기록을 옮기는 것보다 **파일로 정리해 넘기는 편**이 낫습니다([`templates/handoff.md`](../templates/handoff.md)).
- 서브에이전트를 남발하면 캐시와 진행 상황을 확인할 수 없습니다.
- "어디까지 진행됐어?" 같은 확인 질문을 반복하거나 같은 요청을 중복 실행하면 토큰이 낭비됩니다.
