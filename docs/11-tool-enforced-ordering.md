# 11. 순서는 도구가 지킨다 (워크플로우 → 에이전트)

## 세 단계 진화 [강의, 3일차 5강]
예제는 RAG 없는 FAQ 챗봇입니다. 단계는 ① 의도 분류(판단) ② 후보 선정(판단) ③ 추가 질의(애매할 때) ④ 답변(생성)입니다.

1. **LangGraph로 먼저 만듭니다.** 순서는 노드와 엣지, 즉 코드로 정합니다. 순서형 프로세스에는 이쪽이 오히려 편합니다. 아는 코드에서 출발해야 제어 가능한 형태가 나옵니다.
2. **Deep Agent basic**: 하나의 에이전트 루프이고, 순서는 시스템 프롬프트로 지시합니다. 돌아가기는 하지만 "지금 우연히 잘 된 것뿐"입니다. **기도하는 단계**입니다.
3. **도구가 순서를 강제합니다.**
   - 각 도구가 현재 단계를 읽고, 어긋나면 거절합니다.
   - 반환값으로 다음에 부를 도구를 알려 줍니다("1번 했어, 2번 해", "끝났어, 종료해").
   - 첫 도구는 강제로 호출하게 해도 됩니다. 프롬프트에는 역할과 목록만 남습니다.

## 강사의 지시 방식 [강의]
진단과 원하는 구조를 함께 말합니다.
> "시스템 프롬프트로 전체 프로세스를 제어하는 과정이 불완전하다고 생각함. 따라서 툴을 개발해 이 프로세스의 순서를 제어하기를 원함"

## 코드 패턴
[`examples/stepguard.py`](../examples/stepguard.py)를 참고합니다. 상태에 `current_step`을 두고 단계별 허용 도구를 검사합니다. 어긋나면 `{"error": "out_of_order", "next_tool": ...}`을 반환하고, 성공하면 `{"ok": true, "next_tool": ...}`을 반환합니다. [제안]

## 작업 방식 [강의]
- 범위를 좁혀서 작게 시킵니다. 좁히지 않으면 구조가 지나치게 복잡해지고, 강사 경험으로는 "약 70%는 쓸모없다."
- 망쳤으면 버리고 빨리 다시 받습니다.
- 파일 껍데기를 먼저 만들어 지정해 주면 엉뚱한 곳에 쓰지 않습니다.
- 대화 기록은 메모리 전용(MemorySaver)에만 두지 말고 **영속 저장**하라고 따로 지시합니다.
- 작은 챗봇에 도구가 6~8개면 많은 편입니다. 다음 목표는 "최대한 컴팩트하게, 하지만 안정적으로"입니다.

스킬 `workflow-to-agent`가 이 과정을 안내합니다.
