## 2. 챗봇 방법론에 넣을 것

### C3. 지식·대화 상태·메모리

**목적:** 도우미가 사내 문서에서, 묻는 사람이 볼 수 있는 것만 찾아, 근거를 달아 답하고, 근거가 없으면 답하지 않게 한다. 여러 턴에 걸쳐 맥락을 잃지 않고 캐시를 깨지 않게 한다. C4·C5(실행 제어)와 동시에 진행한다.

표 1. 지식을 프롬프트에 넣을까, 검색할까

| 상황(신호) | 선택 | 근거 |
|---|---|---|
| 지식 전체가 작고(출처 기준 200,000 토큰, 약 500쪽 미만) 모든 사용자가 같은 것을 볼 수 있으며 자주 바뀌지 않는다 | 전체를 시스템 프롬프트에 넣고 캐시한다 | A1, A2 |
| 작더라도 사람마다 볼 수 있는 문서가 다르다 | 검색한다. 통째로 넣으면 권한을 나눌 방법이 없다 | S6, M3, `[제안]` |
| 창을 넘거나, 넣었을 때 지연·비용이 목표를 넘거나, 계속 늘어난다 | 검색한다(어휘 + 임베딩, 필요하면 재순위) | A1, A8 |
| 오류 코드, 품번, 프로그램 이름, 규정 번호처럼 정확한 식별자로 묻는다 | 어휘 검색을 반드시 포함한다 | A1, M8 |
| 답이 하루 안에도 바뀌는 값이다(재고, 결재 상태, 잔액) | 색인하지 않고 도구로 원천 시스템을 조회한다(C4) | A8 |
| 답이 합계·건수·추이 같은 집계다 | 검색이 아니라 서버에서 집계하는 질의 도구를 쓴다(C4) | A13, `[제안]` |
| 문서 여러 건을 훑어 비교·종합해야 한다 | 모델이 검색 도구를 여러 번 부르게 하고 호출 수 상한을 둔다 | A3, M9 |
| 사용자가 이 대화에 올린 파일에 대한 질문이다 | 그 대화에만 넣는다. 창을 넘으면 그 대화 범위의 임시 색인을 만들고 만료를 건다. 공용 색인에 넣지 않는다 | O1, `[제안]` |
| 전체를 넣기로 했는데 대화가 길다 | 긴 입력에서 성능이 고르지 않으므로 긴 대화 묶음으로 따로 평가한다 | P1, P2 |

**고민할 것**
1. **어떤 질문에 지식이 필요한가.** 기록된 질문을 유형으로 나누고 유형마다 표 1에서 고른다. 한 서비스 안에서 유형마다 선택이 달라도 된다. `[제안]`
2. **출처 목록과 주인.** 출처마다 소유 부서, 원천 시스템, 누가 볼 수 있는지, 갱신 주기, 폐기 규칙, 색인 포함 여부를 적는다. 주인이 없거나 권한 모델을 모르는 출처는 색인하지 않는다. 원천의 권한이 느슨하면 도우미가 그 느슨함을 그대로 드러낸다. M4, M12, S6, `[제안]`
3. **권한을 어디서 집행하나.** 인증된 요청에서 사용자와 그룹을 끌어내 모든 검색 요청에 필터로 건다. 필터 로직은 검색 API 층 한 곳에 두고 다른 코드와 모델이 저장소를 직접 조회하지 못하게 한다. 필터에 넣는 식별자는 모델이 낸 인자가 아니라 서버가 검증한 값이다. M1, M3, V2, S5
4. **생성 뒤에 거르면 왜 안 되나.** 권한 없는 구절이 컨텍스트에 들어가면 모델이 풀어 써서 답에 섞고, 출력 필터는 풀어 쓴 내용을 가려내지 못한다. 그 구절에 든 지시도 이미 읽힌 뒤다. 권한 판단을 프롬프트 문장에 맡기는 것도 같은 이유로 통제가 아니다. S5, S6, S1, `[제안]`
5. **격리 단위.** 법인·부서·프로젝트처럼 섞이면 안 되는 경계는 저장소나 네임스페이스를 나누고, 그 안의 문서별 권한은 메타데이터 필터로 건다. 나눈 경계는 삭제도 쉽다. M3, V4
6. **권한과 내용이 낡는 문제.** 내용 변경, 삭제, 권한 변경은 서로 다른 경로로 전파된다. 변경은 잡혀도 삭제는 따로 설정해야 잡히는 제품이 있고, 상속된 권한 변경은 재동기화를 불러야 반영되는 제품이 있다. 세 가지 각각의 반영 지연 목표와 담당자를 정한다. M10, M11, V3
7. **수집과 파싱.** 표, 스캔 PDF, 이미지가 든 문서를 어떻게 텍스트로 만들지 문서 종류별로 정한다. 추출 텍스트가 없는 스캔본은 인용이 안 되는 제품이 있다. 문서 구조(제목, 조항, 표)를 따라 자르고, 청크에 그 문서 안에서의 맥락을 붙인다. M5, A1, A4
8. **청크 크기와 메타데이터.** 기본값은 제품마다 다르다(한 제품은 800 토큰에 겹침 400, 다른 글은 수백 토큰). 우리 문서와 시험 질의로 정한다. 청크마다 문서 ID, 버전, 시행일·만료일, 소유 부서, 권한 그룹, 원문 위치를 붙인다. O1, A1, M6
9. **검색 방식.** 어휘 검색과 임베딩 검색을 같이 돌려 합치는 것을 기본으로 놓고, 후보를 넓게 뽑아 재순위로 줄일지는 지표로 정한다. 한국어 어휘 검색은 형태소 분석 설정에 따라 결과가 달라질 수 있다(확인 필요). A1, M8, M6, `[제안]`
10. **후속 질문.** "그건 언제부터야?" 같은 질문은 그대로 검색하면 안 맞는다. 검색 전에 대화 맥락을 넣어 독립 질문으로 고쳐 쓴다. 원 질문은 보존하고 고쳐 쓴 질의를 기록한다. 고쳐 쓰기에 드는 지연을 잰다. P10, M9, O1, M6
11. **몇 개를 어디에 넣나.** 많이 넣으면 정답이 들어올 확률은 오르지만 방해도 는다. 넣는 개수와 총 토큰 상한을 평가로 정한다. 긴 자료는 위에, 질문은 끝에 두고, 중요한 구절이 가운데 묻히지 않게 순서를 정한다. A1, A9, P1, P2
12. **근거와 인용.** 검색된 자료만으로 답하게 하고, 주장마다 출처를 붙인다. 인용은 모델이 쓴 문자열이 아니라 기계가 검증할 수 있는 위치 정보로 받는다. 인용과 JSON 스키마 출력을 함께 못 쓰는 제품이 있으므로 화면 설계(C4)와 같이 정한다. A4, A5, A6
13. **답하지 않을 때.** 검색 결과가 비었거나 질문에 답하기에 모자라면 모른다고 답하고 다음 행동(담당 부서, 사람 연결)을 안내한다. 모델은 컨텍스트가 모자랄 때도 답을 지어내는 경향이 있으므로, 기권을 지시문에만 맡기지 않고 점수 임계값이나 충분성 판정을 코드로 둔다. P7, A6, O1, `[제안]`
14. **문서끼리 다를 때, 날짜가 걸린 질문.** 폐기되거나 만료된 판은 검색 전에 메타데이터로 뺀다. 그래도 남는 충돌은 둘 다 출처·시행일과 함께 보여 주고 모델이 고르게 두지 않는다. 오늘 날짜는 메시지로 준다. S6, P8, `[제안]`
15. **검색된 내용은 자료이지 지시가 아니다.** 사내 문서도 누군가 편집할 수 있고, 올린 파일은 더 그렇다. 도구 결과 블록으로만 넣고, 종류와 출처를 표시하고, 따르지 말라는 정책을 시스템 프롬프트에 적는다. 이것만으로는 부족하므로 피해를 막는 장치는 C4·C5에 둔다. A7, S1, S6, P3, P5
16. **대화 이력을 어떻게 줄이나.** 이력은 덧붙이기만 하다가 임계값에서 한 번에 요약한다. 요약 뒤에도 살아야 하는 것을 목록으로 정한다: 사용자의 목표, 대상 시스템·객체, 확정된 제약, 이미 답한 내용의 출처, 대기 중인 승인, 거절된 요청. 이 값들은 요약문에 맡기지 않고 구조화 상태로 따로 저장해 매번 주입한다. A3, A11, O4, L1, `[제안]`
17. **세션과 사용자.** 세션 식별자는 추측할 수 없게 만들고 서버에서 인증된 사용자에 묶는다. 다른 사용자가 같은 식별자를 내밀면 거부한다. 채널을 넘어 대화를 이으려면 채널이 아니라 사용자와 대화 ID로 저장한다. 이력 보관 기한을 정한다. C2, O3, O7, L2
18. **프롬프트 배치와 캐시.** 그림 1을 따른다. 사용자 이름·부서·날짜·권한처럼 사람이나 요청마다 다른 값을 시스템 프롬프트에 넣으면 사용자 사이에 접두를 공유하지 못한다. 직원이 자리를 비웠다 돌아오는 간격이 캐시 수명보다 길면 긴 수명의 손익을 계산한다. A2, O4
19. **검색 결과를 이력에 남길까.** 남기면 후속 질문에 다시 쓸 수 있지만 이력이 빨리 커진다. 이번 턴에만 두면(캐시 지점 뒤) 이력은 작지만 후속 질문마다 다시 검색해야 한다. 어느 쪽이든 이미 보낸 턴을 나중에 고치지 않는다. A2, P2, `[제안]`
20. **장기 메모리.** 사내 도우미에서는 좁게 시작한다: 사용자가 직접 정한 설정(기본 대상 시스템, 출력 형식, 언어)만 저장한다. 사용자별로 격리하고, 사용자가 보고 지울 수 있게 하고, 문서·도구 결과에서 온 문장은 저장하지 않는다. 직원 정보도 개인정보이므로 보관 기한과 삭제 절차를 둔다. L1, A10, P6, S2, G1, G2

|---|---|---|---|

**검증**
- 검색: 표 2의 검색 지표를 시험 질의 전체로 잰다. 어휘만, 임베딩만, 둘 다, 재순위 추가를 같은 질의로 비교한다. M6, A1
- 권한: 권한이 다른 시험 계정 둘 이상으로 같은 질의를 돌려 누출 0건을 확인한다. 필터 없이 검색 API를 직접 부르는 호출이 거부되는지 본다. M1, M3, `[제안]`
- 신선도: 원천에서 문서를 고치고, 지우고, 권한을 빼앗은 뒤 각각 검색 결과에서 사라지기까지의 시간을 잰다. M10, M11, `[제안]`
- 생성: 근거 충실도, 완전성, 인용 정확도, 기권 정확도. 충실도는 높은데 정확성이 낮으면 원천 문서를 의심한다. M7, P7
- 충돌·날짜: 옛 판과 새 판이 함께 있는 질의, 시행일이 미래인 문서가 걸린 질의로 답을 본다. `[제안]`
- 주입: 지시가 든 문서와 업로드 파일을 색인·첨부해 놓고 도우미가 따르지 않는지, 인용·기록에 그 문서가 드러나는지 본다. A7, S1
- 대화: 강제로 요약한 직후 생존 목록의 값(대상 시스템, 대기 중인 승인, 제약)이 유지되는지 본다. 다른 사용자의 세션 식별자로 접근이 거부되는지 본다. A3, C2, `[제안]`
- 캐시: 캐시 읽기 비율(읽기 ÷ (읽기 + 쓰기 + 비캐시 입력))을 턴 번호별로 본다. 같은 대화의 연속 두 요청에서 [1]·[2]의 해시가 같고, 서로 다른 사용자의 첫 요청에서도 같은지 본다. A2, `[제안]`
- 메모리: 값을 쓰고 새 세션에서 읽히는지, 다른 사용자에게 보이지 않는지, 삭제 요청 뒤 조회되지 않는지, 문서에서 온 문장을 저장하려는 시도가 거부되는지 본다. A10, P6, `[제안]`

**완료 기준**
- [ ] 질문 유형마다 "넣는다 / 검색한다 / 도구로 조회한다"가 근거와 함께 정해졌다
- [ ] 출처 목록에 출처마다 주인, 권한 모델, 갱신 주기, 폐기 규칙이 적혀 있고 주인이 확인했다
- [ ] 검색 요청마다 서버가 넣은 사용자 신원으로 필터가 걸리고, 권한이 다른 계정 시험에서 누출이 0건이다
- [ ] 변경·삭제·권한 변경의 반영 지연을 쟀고 목표 안이다. 각각의 담당자가 있다
- [ ] 검색 지표(Recall@k, Precision@k, MRR, 음성 질의, 후속 질문)가 기록됐고 검색 방식·청크·개수의 선택 근거가 있다
- [ ] 답에 검증 가능한 인용이 붙고, 근거 충실도·인용 정확도·기권 정확도 수치가 있다
- [ ] 주입 문서 시험 기록이 있다
- [ ] 요약 생존 목록과 구조화 상태가 정해졌고 요약 생존 시험을 통과했다. 세션이 사용자에 묶여 있다
- [ ] 시스템 프롬프트와 도구 정의가 대화와 사용자에 따라 바뀌지 않음을 해시로 확인했고 캐시 읽기 비율이 기록됐다
- [ ] 장기 메모리를 쓴다면 저장 항목, 사용자별 격리, 보기·삭제 방법, 보관 기한이 정해졌고 시험했다 (안 쓰면 `[x] 해당 없음 — 이유`)

**흔한 함정:** 주인 없는 문서함을 통째로 색인하기, 권한을 프롬프트 문장으로 막기, 생성된 답에서 금지 내용을 걸러 내려 하기, 모델이 낸 사용자 ID로 필터하기, 내용 동기화만 만들고 삭제와 권한 변경은 빠뜨리기, 임베딩 검색만 쓰기, 후속 질문을 그대로 검색하기, 검색과 생성을 한 점수로만 재기, 답이 없는 질의를 시험에 넣지 않기, 청크를 많이 넣을수록 좋다고 믿기, 스캔 문서를 색인했다고 여기기, 사용자 이름·날짜를 시스템 프롬프트에 넣기, 지난 턴의 검색 결과를 조금씩 지워 매 턴 캐시를 깨기, 승인 상태를 요약문에만 남기기, 문서에서 읽은 문장을 사용자 메모리에 저장하기. `[제안]`

**순서와 병렬:** 출처 목록·권한 확인, 시험 질의 수집, 수집 파이프라인은 동시에 한다. 검색 평가가 먼저이고 생성 평가가 그다음이다. 캐시와 시작 로드량은 C4의 도구 정의가 동결된 뒤에 잰다. 요약 생존 시험은 C4·C5의 승인 양식이 정해진 뒤 다시 돈다. 장기 메모리는 마지막에, 측정된 필요가 있을 때 넣는다. `[제안]`

### C4. 도구·행동

**목적:** 도우미가 기간계 시스템을 조회·추출·변경할 때 요청한 직원 본인의 권한으로만 움직이고, 큰 결과가 컨텍스트를 채우지 않고, 상태를 바꾸는 호출은 사람이 본 뒤에만 실행되게 한다.

표 3. 도구 등급과 기본 정책 (등급 구분과 기본값은 `[제안]`, 근거는 오른쪽)

| 등급 | 예 | 기본 정책 | 근거 |
|---|---|---|---|
| 조회 | 객체 한 건 읽기, 검색, 소스 한 파일 보기 | 자동 실행. 반환 상한, 호출 수 제한, 기록 | S4, C3, A12 |
| 추출 | 표 대량 반출, 소스 묶음 내려받기 | 행·크기 상한과 필터 필수. 결과는 파일·핸들로. 반출 목적과 범위를 기록. 상한을 넘으면 승인 | A12, A13, S2 |
| 변경 | 소스 수정, 데이터 갱신, 설정 변경 | 변경 전 확인 필수. 멱등 키. 되돌리는 방법을 함께 제시. 실행 전후 상태 기록 | S4, S1, C3, V6 |
| 범용 조작 | 화면 직접 조작, 임의 명령·임의 질의 실행 | 가장 좁게. 가능한 작업은 업무 단위 도구로 옮긴다. 남는 것은 단계마다 확인 | S4, A12 |

**고민할 것**
1. **등급을 누가 정하나.** 도구의 등급은 서버가 낸 주석이 아니라 우리가 정해 코드에 둔다. 주석은 힌트일 뿐이고 실제 동작을 보장하지 않는다. 등급을 모르는 도구는 변경으로 취급한다. C4, C3
2. **좁은 도구와 열린 도구.** 임의 질의·임의 명령·화면 조작은 한 도구로 무엇이든 할 수 있어 통제가 어렵다. 자주 하는 작업부터 인자가 정해진 업무 단위 도구로 만들고 열린 도구의 쓰임을 줄여 간다. API를 1:1로 감싸 나열하지 않는다. S4, A12
3. **누구의 권한으로 실행하나.** 공용 서비스 계정으로 하위 시스템을 부르면 모든 직원이 그 계정의 권한을 얻는다. 요청한 직원의 신원을 하위 시스템까지 전달해 그 시스템이 본인의 권한을 검사하게 한다. 허용 여부를 모델이나 프롬프트가 판정하지 않는다. S4, S5, M13
4. **신원을 어떻게 전달하나.** 받은 토큰을 그대로 넘기지 않는다. MCP 서버는 자기를 대상으로 발급된 토큰만 받고, 하위 시스템용 토큰은 따로 받는다(토큰 교환, 대리 흐름). 대리 실행임이 토큰과 기록에 남는 방식(위임)인지, 사용자로 보이는 방식(가장)인지 정한다. 범위는 필요한 만큼만, 부족하면 단계적으로 올린다. C1, C2, C9, M13
5. **신원은 모델 밖에 둔다.** 사용자 ID, 테넌트, 토큰은 모델에 보내지 않는 실행 컨텍스트에 두고 도구 구현이 거기서 읽는다. 도구 스키마에 `user_id` 같은 인자를 두지 않는다. 자격 증명과 권한 구조를 시스템 프롬프트에 적지 않는다. O6, S5, C2
6. **접근 관리.** 직원이 서버마다 따로 승인하게 둘지, 회사 IdP가 어느 직원이 어느 서버를 쓸지 정하고 회수도 한 곳에서 할지 정한다. 퇴사·부서 이동 때 회수가 얼마나 빨리 반영되는지 확인한다. C7, C10
7. **호출 사이의 상태.** 열어 둔 세션, 추출 결과, 변경 묶음 같은 상태는 서버가 만든 핸들로 주고받는다. 핸들은 이름이지 권한이 아니므로 매 호출 사용자를 다시 검증하고, 추측할 수 없게 만들고, 보존 기한을 도구 설명에 적는다. C3, C2, C8
8. **큰 결과를 어떻게 다루나.** 소스 파일, 표 추출, 화면 덤프는 한 번에 창을 채운다. 순서대로 쓴다: 서버에서 필터·집계해 줄인다 → 범위·페이지 인자와 작은 기본값을 둔다 → 결과 전체는 파일이나 자원 링크로 두고 모델에는 요약(건수, 열 이름, 앞 몇 행)과 핸들만 돌려준다 → 여러 호출의 중간 결과를 코드 실행 환경에서 처리해 모델에는 최종 일부만 보여 준다. 잘랐으면 잘렸다는 사실과 나머지를 보는 방법을 알린다. A12, A13, A14, C3
9. **큰 자료를 모델이 옮겨 쓰게 하지 않는다.** 추출한 것을 다른 도구에 넘길 때 모델이 내용을 다시 쓰면 느리고 틀린다. 핸들을 넘긴다. 민감 값은 모델에 가기 전에 가리고 도구 사이에서만 원래 값으로 흐르게 할 수 있다. A13
10. **도구 결과는 신뢰 못 할 입력이다.** 문서 본문뿐 아니라 소스 코드의 주석과 문자열, 데이터의 텍스트 필드, 화면에 찍힌 글자에도 지시가 들어갈 수 있다. 도구 결과 블록으로만 넣고, 종류와 출처를 표시하고, JSON으로 감싸고, 우리 지시는 도구 결과에 넣지 않는다. A7, S1, P3
11. **주입이 성공해도 피해가 작게.** 민감 데이터 접근, 신뢰 못 할 내용, 밖으로 내보낼 수단이 한 흐름에 모이지 않게 한다. 신뢰 못 할 결과를 읽은 뒤의 변경·반출 호출은 자동 실행하지 않는다. 호출 여부와 대상을 신뢰 못 할 내용이 정하지 못하게, 사용자의 요청에서 나온 범위 밖의 호출은 막는다. P13, P9, A7, O5, `[제안]`
12. **변경 전 확인.** 확인 화면은 코드가 만든다: 대상 시스템, 대상 객체, 바뀌기 전과 후(차이), 영향 범위, 되돌리는 방법. 승인은 화면의 조작으로 받고, 대화 속 "네"나 모델의 "승인받았다"는 말로 대신하지 않는다. 승인된 인자와 실제 실행 인자가 같은지 서버가 대조한다. 승인 대기 중에는 실행 상태를 저장했다가 재개한다. 거절과 취소를 구분한다. C3, S1, S4, O9, C5, `[제안]`
13. **재시도와 중복 실행.** 변경 호출마다 멱등 키를 붙여 시간 초과 뒤 재시도가 두 번 실행되지 않게 한다. 키는 모델이 아니라 하네스가 대화·턴·호출에서 만든다. 같은 키에 인자가 다르면 거부한다. 하위 시스템이 멱등을 지원하지 않으면 실행 전 현재 상태를 읽어 이미 반영됐는지 확인한다. V6, C4, `[제안]`
14. **인자와 출력의 형식.** 도구 인자는 스키마로 강제한다. 화면에 그릴 것(표, 차이, 승인 요청, 인계 요약)은 스키마가 있는 구조로 받는다. 인용이 붙는 답과 JSON 스키마 출력을 한 응답에 함께 못 쓰는 제품이 있으므로 "답은 인용, 화면 부품은 도구 호출"처럼 나눈다. 모델이 만든 값을 질의·명령·경로에 넣기 전에 검증하고 인코딩한다. A15, A4, S3, `[제안]`
15. **사람에게 넘기기.** 인계를 도구로 만든다. 넘길 때 사유, 사용자의 목표, 시도한 것과 결과, 근거 문서, 대기 중인 승인을 구조화해 함께 넘긴다. 넘겨야 할 때 넘겼는지를 지표로 잰다. O8, M14, A8
16. **도구가 많을 때.** 정의 토큰이 커지면 자주 쓰는 것만 상시 로드하고 나머지는 찾아 쓰게 한다. 도구 정의는 캐시 접두의 맨 앞이므로 대화 중에 넣고 빼지 않는다. 이름은 시스템·자원 단위 접두로 나눈다. A14, A2, A12

**진행**
- 도구 명세표를 쓴다: 이름 / 등급 / 설명(언제 쓰고 언제 안 쓰는지) / 인자와 예시 / 반환(형식, 상한, 잘렸을 때 안내, 핸들) / 오류 종류 / 필요한 권한 범위 / 승인 필요 여부 / 멱등 여부 / 되돌리는 방법. A12, C3, `[제안]`
- 인증 경로를 먼저 세운다: 직원 로그인 → 도우미 → MCP 서버(대상 검증) → 하위 시스템용 토큰. 공용 계정이 남는 구간을 표로 적고 각각 없앨 계획이나 남기는 이유를 적는다. C1, C2, C9, `[제안]`
- 조회 도구부터 붙이고, 반환 상한과 페이지·필터를 넣은 뒤 추출 도구를 붙인다. 변경 도구는 확인 화면, 멱등 키, 감사 기록이 있은 뒤에 붙인다. `[제안]`
- 확인 화면과 승인 대기·재개를 만든다. 승인 기록에 누가, 언제, 어떤 인자를 승인했는지 남긴다. O9, S4
- 인계 도구와 인계 요약 스키마를 만든다. O8, M14
- 도구 개선 루프를 돈다: 현실적인 여러 호출 과제 → 실행 → 기록과 도구 지표 → 설명·스키마 수정 → 떼어 둔 과제로 확인. A12

**검증**
- 세 층으로 시험한다: 모델 없는 도구 단위 시험 → 모델이 도구와 인자를 맞게 고르는지 → 대화 전체. 대화 전체는 대화가 끝난 뒤 하위 시스템의 상태를 기대 상태와 비교해 채점하고, 같은 과제를 여러 번 돌려 매번 통과하는 비율을 본다. P12, `[제안]`
- 권한: 권한이 다른 시험 계정 둘로 같은 요청을 돌려, 권한 없는 쪽은 하위 시스템이 거부하는지 본다. 하위 시스템의 감사 기록에 요청한 직원이 남는지 본다. 다른 대상용 토큰을 MCP 서버에 내밀어 거부되는지 본다. S4, C1, C2, `[제안]`
- 핸들: 다른 사용자가 만든 핸들을 내밀어 거부되는지, 만료된 핸들에 정해진 오류가 나오는지 본다. C2, C3
- 큰 결과: 상한을 넘는 소스 파일과 표 추출로, 반환 토큰이 상한 안이고 안내가 나오며 다음 호출이 범위·필터를 쓰는지 본다. 도구 결과 토큰 분포와 상한에 걸린 비율을 잰다. A12, `[제안]`
- 주입: 문서, 소스 주석, 데이터 필드에 지시를 심어 놓고 변경·반출 호출이 승인 없이 실행된 건수를 센다. 목표 0. A7, S1, `[제안]`
- 확인: 변경 도구를 확인 없이 직접 부르는 경로가 막히는지, 승인 뒤 인자를 바꾼 실행이 거부되는지, 거절·취소 뒤 실행되지 않는지 본다. `[제안]`
- 멱등: 같은 변경 호출을 시간 초과 뒤 다시 보내 하위 시스템에 한 번만 반영되는지 본다. V6
- 인계: 넘겨야 하는 대화와 넘기면 안 되는 대화 묶음으로 적중과 오발을 세고, 인계 요약의 필수 필드가 채워지는지 본다. A8, `[제안]`
- 지표: 도구 오류율(도구별), 잘못된 도구 선택 비율, 승인 요청 대비 거절 비율, 대화당 도구 결과 토큰, 도구 정의 총 토큰. A12, `[제안]`

**완료 기준**
- [ ] 도구마다 등급, 명세(설명, 인자 예시, 반환 상한, 오류 종류, 필요한 권한 범위), 단위 시험이 있다
- [ ] 하위 시스템 호출이 요청한 직원의 신원으로 실행되고, 권한이 다른 계정 시험에서 권한 없는 요청을 하위 시스템이 거부했다. 공용 계정이 남은 구간은 목록과 이유가 있다
- [ ] 사용자 신원과 토큰이 모델 입력과 도구 인자에 없다
- [ ] 핸들이 사용자에 묶여 있고 다른 사용자의 핸들이 거부된다
- [ ] 조회·추출 도구의 반환 상한, 잘림 안내, 파일·핸들 반환이 구현됐고 상한 초과 시험을 통과했다
- [ ] 변경·범용 조작 도구는 확인 화면 없이 실행되지 않고, 승인된 인자와 실행 인자의 대조, 거절·취소 시험을 통과했다
- [ ] 변경 호출의 재시도가 한 번만 반영된다
- [ ] 주입 시험에서 승인 없는 변경·반출이 0건이다
- [ ] 인계 도구와 요약 스키마가 있고 적중·오발 수치가 있다
- [ ] 누가, 어떤 도구를, 어떤 인자로, 어떤 승인으로 실행했는지 기록이 남고, 도구 정의 총 토큰·도구 오류율·도구 결과 토큰이 적혀 있으며 평가 회귀가 없다

**흔한 함정:** 공용 서비스 계정 하나로 전부 연결하기, 받은 토큰을 하위 시스템에 그대로 넘기기, 사용자 ID를 도구 인자로 받기, 서버가 낸 "읽기 전용" 주석을 믿고 자동 실행하기, 임의 질의·임의 명령 도구 하나로 시작해 그대로 두기, 표 전체나 소스 전체를 그대로 돌려주기, 잘라내고 알리지 않기, 모델에게 큰 자료를 옮겨 쓰게 하기, 소스 주석과 데이터 값은 안전하다고 여기기, 확인을 프롬프트 지시("실행 전에 물어봐라")로만 두기, 대화 속 "네"를 승인으로 치기, 확인 화면을 모델이 쓴 문장으로 만들기, 재시도에 멱등 키가 없기, 인계할 때 이력만 넘기고 요약을 안 넘기기, 대화 중에 도구를 넣고 빼기. `[제안]`

**순서와 병렬:** 인증 경로와 도구 등급 결정이 먼저다. 조회 도구 구현과 단위 시험은 도구별로 동시에 한다. 추출 도구는 반환 상한이 구현된 뒤, 변경 도구는 C5의 승인 양식과 감사 기록이 정해진 뒤에 붙인다. 설명·이름·스키마 조정은 한 번에 하나씩 하고 선택 시험을 다시 돈다. 도구 정의를 동결한 뒤 C3이 캐시와 시작 로드량을 잰다. `[제안]`
