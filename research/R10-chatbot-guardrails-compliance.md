# R10 — 챗봇 서비스의 가드레일·개인정보·법규 조사

- 조사일: 2026-11-16
- 대상 제품: **사내 직원용 어시스턴트**다. 기본 기능은 사내 지식 검색이고, 외부 도구 서버(MCP)를 통해 ① 업무 시스템(ERP)의 소스 코드를 읽고 분석하고 **수정**하며 ② 업무 데이터를 추출하고 ③ 업무 시스템의 화면(GUI)을 직접 조작한다. 외부 고객용 챗봇에만 해당하는 항목은 2-5절 "외부 고객용일 때만"에 짧게 모았다.
- 범위: `kit/harness/METHOD.md` S5와 `kit/harness/reference/security.md`(신뢰 경계, 세 가지 능력 규칙, 층별 방어, T1~T21, RT-01~31, 판정과 강제, 도구를 거치지 않는 길, 가드 측정)에 이미 있는 내용은 되풀이하지 않는다. 챗봇이라서 **바뀌는 것과 더할 것**만 적는다. ERP 제품별 동작(이관 절차, 화면 스크립팅, 권한 객체)은 다른 조사에서 다루므로 여기서는 일반 통제 수준까지만 적는다.
- 이 파일 외에는 고치지 않았다.

읽는 법
- **[직]** 페이지 원문(HTML·PDF·마크다운)을 내려받아 해당 구절을 직접 읽었다. 일부 절만 읽은 자료는 핵심 칸에 읽은 범위를 적었다.
- **[요약경유]** 요약 도구나 검색 결과 요약으로만 확인했다. 문장을 옮겨 쓰기 전에 원문을 다시 확인한다.
- **(제안값)** 은 자료에 없는 우리 쪽 기본값, **[제안]** 은 자료에서 직접 나오지 않은 우리 쪽 설계 판단, **(확인 필요)** 는 원문이나 적용 여부를 확인하지 못한 주장이다.
- 인용문은 넣지 않았고 전부 우리말로 요약했다. 수치는 출처가 예시로 든 값만 "출처의 예시"로 적었다.
- **이 문서는 법률 자문이 아니다.** 법령 항목은 조문을 읽고 옮긴 것이고, 우리 제품에 그 조문이 적용되는지(예: 모델 API 사용이 처리 위탁인지, 대화 기록 수집이 감시 설비인지)는 판단하지 않았다. 2-4절 점검표의 모든 항목은 회사 법무·개인정보 보호책임자·내부감사 부서의 검토를 거쳐야 한다. 법령은 조사일 기준 국가법령정보센터와 EUR-Lex에 표시된 현행 판을 읽었다.

## 2. 챗봇 방법론에 넣을 것

전제 [제안]: 이 어시스턴트는 `security.md` 2절의 세 가지 능력을 전부 가진다. 비공개 데이터(업무 데이터, 소스 코드), 신뢰 못 할 입력(검색된 문서, 코드 주석, 데이터 값, 화면 글자), 상태 변경(코드 수정, 화면 조작, 내보내기). 코딩 에이전트는 네트워크를 닫아 하나를 뺐지만 여기서는 **도구 묶음을 나눠** 뺀다. 한 대화가 동시에 쓰는 묶음을 정하고(조회 묶음 / 변경 묶음), 묶음을 넘는 행동은 건마다 사람이 승인한다.

### 2-1. C0 범위 — 금지·고지·보존 정책

**고민할 것**
1. **누가 쓰나.** 임직원만인가, 파견·협력사 인력과 계열사도인가, 외부 고객도인가. 외부인이 섞이면 2-5절을 적용하고 내부 업무용 예외(K7)를 전제하지 않는다. [K7] [제안]
2. **기능과 대상 시스템의 표.** 지식 검색 / 코드 읽기 / 코드 수정 / 데이터 조회 / 데이터 내보내기 / 화면 조작을 행으로, 개발·검증·운영 시스템을 열로 놓고 칸마다 허용·승인 필요·금지를 적는다. 필요 없는 기능과 열린 도구는 넣지 않는다. [A1]
3. **누구의 권한으로 도나.** 기본은 요청한 직원 본인의 권한이다. 공용 고권한 계정은 쓰지 않는다. 쓸 수밖에 없는 기능이 있으면 그 기능만 따로 적고 보완 통제(읽기 전용, 대상 한정, 건별 승인)를 붙인다. [A1][B1][K2]
4. **데이터 등급과 목적지.** 등급(공개 / 사내 / 기밀 / 개인정보 / 민감·고유식별정보 / 공시 전 재무 정보)과 목적지(화면 표시 / 모델 컨텍스트 / 파일 내보내기 / 외부 모델 API / 대화 기록)의 표를 만들고 칸마다 허용·가림·금지를 적는다. [K1][K2][A3] [제안]
5. **외부 모델 API를 쓸 조건.** 학습 불사용이 계약에 있는가, 보존 기간, 무보존 적용 범위(모델·기능별로 다르다), 데이터 처리 주체(클라우드 경유 시 달라진다), 피드백 기능을 끌 것인가, 개인정보가 실리면 처리 위탁·국외 이전에 해당하는가(확인 필요). [P8][P9][P10][P11][O1][K1]
6. **대화 기록 정책.** 수집 항목, 목적, 보존 기간, 열람할 수 있는 사람, 삭제 요청 처리, 인사 평가·근태 감시에 쓰지 않는다는 문장. 대화 내용 기록과 감사 기록(누가 어떤 도구를 불렀나)을 따로 둔다. [K1][K2][K4][N1] [제안]
7. **직원에게 알릴 것.** AI 기반이라는 사실, 기록이 남고 누가 본다는 사실, 답변의 한계와 근거 확인 방법, 넣으면 안 되는 정보. 내부 업무용은 사전 고지 의무의 예외일 수 있어도 알리는 쪽을 기본으로 둔다. [K7][K9][A7] [제안]
8. **내부통제 대상인가.** 재무 보고에 쓰이는 시스템의 코드나 데이터를 건드리면 변경 관리·접근 통제·업무 분장 통제의 대상일 수 있다. 내부회계 담당과 내부감사에 어시스턴트를 "새 접근 경로"로 알리고 통제 설계를 맞춘다(확인 필요). [K3]
9. **절대 하지 않을 일.** 운영 시스템 직접 변경, 권한·역할 변경, 감사 기록 접근, 타인의 인사·급여 정보 조회, 상한을 넘는 일괄 추출, 승인 대행. [A1][N1] [제안]

**진행**
- 기능 × 시스템 표와 데이터 등급 × 목적지 표를 보안·개인정보·내부감사 담당과 함께 채운다. 빈칸은 금지로 둔다. [제안]

### 2-2. C5 제어·안전

**고민할 것**
1. **신원은 세션에서, 권한은 뒤 시스템에서.** 누구인지는 로그인 세션(사내 인증)에서만 읽는다. 대화에 적힌 사번·직책·"승인받았다"는 데이터다. 도구는 그 직원의 권한으로 뒤 시스템을 부르고, 허용 여부는 뒤 시스템의 인가가 판정한다. 어시스턴트 쪽 검사는 그 위에 겹치는 층이다. [A1][A4][B1] `security.md` 1절·T17의 연장
2. **위임 방식.** 대리 실행이면 "어시스턴트가 누구를 대신했다"가 토큰과 기록에 함께 남는 방식을 고른다. 받은 토큰을 그대로 뒤로 넘기지 않고, 도구 서버는 자기 앞으로 발급된 토큰만 받는다. 범위는 최소에서 시작한다. [B1][B2][B4]
3. **검색도 권한을 따른다.** 색인을 만들 때 원문의 접근 권한을 함께 싣고, 질의 시점에 요청자의 권한으로 거른다. 답변 캐시와 기억은 사용자 범위로 나눈다. [A5][A3]
4. **읽는 내용은 전부 데이터다.** 검색된 문서, 소스 코드의 주석과 문자열, 데이터의 자유 입력 값(비고, 거래처명), 화면의 글자. 도구 결과로만 전달하고 종류와 출처를 붙이고 구조화해 감싼다. 선별 모델은 보조다. 먼저 할 일은 그 대화에서 쓸 수 있는 변경·내보내기 도구를 줄이는 것이다. [P1][A2][N2][P12]
5. **행동 등급.** 0 지식 조회 / 1 업무 데이터 조회(화면 표시, 건수 상한) / 2 내보내기·대량 추출, 개발 시스템의 코드 변경 / 3 운영 반영, 화면 조작으로 하는 상태 변경, 되돌릴 수 없는 것. 2는 건별 확인과 사유, 3은 어시스턴트가 실행하지 않거나 요청자 아닌 사람의 승인을 거친다. [A1][B3][N1] [제안]
6. **직무 분리.** 변경을 요청한 사람이 유일한 승인자가 되지 않게 한다. 어시스턴트의 신원에는 승인 역할을 주지 않고, 승인은 기존 변경 관리 절차의 다른 사람이 한다. 승인은 변경 내용(차이)의 해시에 묶는다. [N1][K3] `plan-gate.md`의 연장
7. **내보내기 통제.** 건수·열 상한, 등급별 가림, 사유 입력, 목적지 제한, 다운로드 기록과 정기 점검. 여러 번 나눠 받아 상한을 넘기는 것을 사용자·기간 단위로 합산한다. [K2][K1][A3][A8] [제안]
8. **모델로 나가는 내용.** 원자료 행 대신 스키마·집계·표본을 보낼 수 있는지 먼저 본다. 등급표에서 금지인 값은 모델 호출 직전에 필드 단위로 가린다. 소스 코드 속 자격증명도 같은 길로 나간다. [P11][O1][K1] `security.md` 9절·T19의 연장
9. **감사 기록과 부인 방지.** 한 줄에 요청한 사람, 대리한 주체(어시스턴트·도구), 대상 시스템과 객체, 실제 인자, 결과, 승인자와 승인 대상 해시, 뒤 시스템 기록과 맞출 상관 ID를 남긴다. 어시스턴트와 그 관리자가 고칠 수 없는 곳에 추가 전용으로 둔다. 감사 기록에는 대화 원문이나 추출 값 자체를 넣지 않는다. [N1][B1][B3][K2]
10. **사내 규정 답변의 근거.** 규정·한도·절차 답변은 현행 공식 문서의 구절에 근거하고 문서명과 개정일을 붙인다. 근거를 못 찾으면 모른다고 답하고 담당 부서를 안내한다. 문서에 없는 승인·예외·약속을 만들지 않는다. [P3][P6][A7]
11. **생성물은 검토 전까지 신뢰하지 않는다.** 모델이 쓴 코드와 질의는 사람 검토와 자동 검사를 거친 뒤에만 반영한다. 모델이 만든 질의를 운영 데이터에 바로 실행하지 않는다. [A6][O2]
12. **화면 조작은 가장 좁게.** 화면 경로는 API 도구에 건 세밀한 제한을 비켜 갈 수 있다. 허용 화면 목록, 조회 전용 기본값, 결과가 생기는 조작의 사람 확인, 동작마다 기록, 성공 여부는 모델의 보고가 아니라 실제 상태로 확인한다. [P12][B3] 제품별 동작은 다른 조사에서 다룬다
13. **남용과 비용.** 사용자별 할당량, 입력 크기와 시간 제한, 추출 패턴의 이상 탐지. 같은 차단에 반복해서 걸리는 사용자는 자동 정지보다 보안 담당 검토로 넘긴다. [A8][P1] [제안]
14. **스트리밍과 거절.** 일부가 화면에 나간 뒤 중단될 수 있다. 중단 시 보여 줄 문구, 부분 출력의 처리, 컨텍스트 정리, 거절 수의 별도 집계를 정한다. [P5]
15. **기록 속 직원 정보.** 대화 기록을 볼 수 있는 사람을 좁히고 열람도 기록한다. 감사 대상인 관리자가 감사 기능을 관리하지 않게 한다. [N1][K2][E3]

**진행**
- 도구마다 실행 신원, 뒤 시스템의 인가 지점, 등급, 승인자, 기록 필드를 한 표에 적는다. 인가 지점이 "어시스턴트 쪽 검사뿐"인 줄은 다시 설계한다. [A1][A4]
- 사용자별 자격 위임을 먼저 붙이고 도구는 그 뒤에 붙인다. 위임이 안 되는 시스템은 조회 전용의 좁은 계정으로 시작하고 표에 예외로 적는다. [B1][K2] [제안]
- 색인 파이프라인에 권한 정보와 등급 표시를 싣고, 문서의 권한이 바뀌면 색인에 반영되는 시간을 잰다. [A5]
- 도구 묶음을 조회용과 변경용으로 나눈다. 신뢰 못 할 내용을 읽은 턴에서 변경·내보내기 도구를 부르려 하면 검토로 보낸다. 판단은 값 단위로 한다(읽은 값이 인자로 들어갈 때). [P1] `security.md` 9절
- 승인 화면에 실제 대상 시스템, 객체, 변경 차이나 추출 조건, 건수, 등급을 보여 준다. 대상 시스템은 대화가 아니라 설정에서 고정한다. [B3] [제안]
- 감사 기록 저장소를 어시스턴트 실행 계정 밖에 두고, 뒤 시스템의 자체 기록과 상관 ID로 맞춰 본다. [N1]
- 규정 답변용 지침에 근거 구절 먼저 뽑기와 근거 없으면 답하지 않기를 넣고, 답변의 인용이 실제 문서에 있는지 코드로 대조한다. [P3] [제안]
- CT 시험(2-3절)을 스크립트로 만들어 도구·모델·프롬프트·권한 설정이 바뀔 때마다 돌린다. [P1][O2]

**검증**
- 권한이 다른 시험 계정 둘로 같은 질문을 한다. 낮은 쪽에서 높은 쪽 전용 문서·데이터가 답변, 인용, 캐시 어디에도 나오지 않는다. [A5][A3]
- 대화에 다른 사람의 신원이나 승인 문구를 적고 한도 밖 행동을 요청한다. 뒤 시스템의 거부가 요청자 본인 신원으로 기록된다. [B1][A4]
- 문서·코드 주석·데이터 값·화면 글자에 지시를 심는다. 변경·내보내기 호출이 0건이다. [P1][A2]
- 어시스턴트 쪽 검사를 끄고 다시 돌려 뒤 시스템 인가가 막는지 본다. 막지 못하는 줄이 완전 매개가 안 된 곳이다. [A1] `security.md` 6절
- 임의의 변경·추출 건을 골라 감사 기록만으로 누가, 무엇을, 누구의 승인으로 했는지 재구성한다. 재구성에 걸린 시간을 잰다(목표 5분 이내, 제안값). [N1]
- 요청자와 승인자가 같은 건이 0건인지 기록에서 센다. [N1][K3]
- 정상 업무 질의 묶음으로 과잉 차단율과 검토율을 따로 잰다. 놓친 비율과 한 숫자로 합치지 않는다. `security.md` 10절 [제안]
- 가짜 민감 값을 심고 모델 공급자로 나간 요청 본문을 검사한다. [P11] RT-27의 확장

**완료 기준**
- [ ] 모든 도구 호출이 요청한 직원의 신원으로 실행되고 뒤 시스템이 인가를 판정한다. 예외는 목록과 보완 통제가 있다 [A1][B1][K2]
- [ ] 신원·역할·승인을 대화 내용에서 읽는 경로가 없음을 시험했다 [A4][B1]
- [ ] 검색 결과·인용·캐시·기억이 요청자의 접근 권한을 넘지 않음을 두 계정 시험으로 확인했다 [A5][A3]
- [ ] 문서·코드 주석·데이터 값·화면 글자에 심은 지시로 변경·내보내기가 일어나지 않았다 [P1][A2][P12]
- [ ] 행동 등급표가 있고 등급 2·3의 호출은 승인 기록 없이 실행된 건이 0건이다 [A1][B3]
- [ ] 요청자가 유일한 승인자인 변경이 0건이고, 어시스턴트 신원에 승인 권한이 없다 [N1][K3]
- [ ] 내보내기에 건수 상한·가림·사유·다운로드 기록이 있고, 나눠 받기를 합산해 잡는다 [K2][A8]
- [ ] 모델 공급자로 나가는 요청에 금지 등급의 값이 없음을 시험했다 [P11][K1]
- [ ] 감사 기록이 어시스턴트가 고칠 수 없는 곳에 있고, 임의 건을 기록만으로 재구성했다 [N1][K2]
- [ ] 규정 답변에 문서명·개정일·근거 구절이 붙고, 근거 없는 질문에 지어내지 않음을 시험했다 [P3][A7]
- [ ] 놓친 비율, 과잉 차단율, 검토율이 따로 측정돼 있다 [제안]
- [ ] 스트리밍 중단과 판정기 실패 때의 화면 동작과 대체 문구가 정해져 있다 [P5]

**흔한 함정:** 시스템 프롬프트에 "본인 데이터만 보여 줘라"고 적고 인가로 여기기, 고권한 공용 계정으로 뒤 시스템에 붙고 어시스턴트 쪽에서만 거르기, 색인에 권한 없이 전부 넣기, 주입 필터를 믿고 변경 도구를 같은 대화에 열어 두기, 승인자를 요청자 본인으로 두기, 승인 화면에 모델의 요약만 보여 주기, 감사 기록에 대화 원문과 추출 값을 통째로 넣기, 화면 조작을 "사람이 하던 것과 같다"며 제한 없이 열기, 모델이 "변경했다"고 한 것을 상태 확인 없이 믿기, 직원을 공격자로만 보고 정상 업무를 과잉 차단하기. ### 2-5. 외부 고객용일 때만

사내용에는 적용하지 않는다. 같은 어시스턴트를 고객에게 열 때 더한다.
- **답변 책임.** 회사는 챗봇이 한 말에 대해 웹사이트의 다른 정보와 같은 책임을 진다고 본 결정이 있다. 맞는 정보가 다른 페이지에 있었다는 사정은 받아들여지지 않았다. 면책 문구의 효력은 그 결정이 판단하지 않았으므로 면책 문구에 기대지 않는다. 정책·가격·자격 답변은 현행 공식 문서에 근거하고, 권한 없는 약속·할인·합의를 만들지 않는다. [L1][P6][A7] 소액 사건 결정이라 다른 관할에서의 효력은 (확인 필요)
- **AI 고지.** 한국: 생성형 인공지능 기반임을 사전 고지하고 위반 시 3천만 원 이하 과태료 대상이다. 계도기간은 보도로만 확인했다. EU: 2026-08-02부터 늦어도 첫 상호작용 시점에 알린다. 모델 공급자 정책도 세션 시작이나 화면에서의 고지를 요구한다. 미국 캘리포니아의 봇 고지법은 원문을 열지 못했다(확인 필요). [K6][K7][K10][E1][P7]
- **고위험 조언.** 의료·법률·금융·보험 등에서 개인에 대한 조언은 자격 있는 사람의 검토와 AI 사용 고지를 거친다. 일반 정보 설명과 구분한다. [P7]
- **위기·미성년자.** 자살·자해 신호에는 고정 문구와 상담 전화 안내로 응답한다. 미성년자가 쓸 수 있으면 공급자의 별도 지침과 14세 미만 법정대리인 동의 규정을 확인한다. 국내 상담 전화번호는 공식 자료로 확인해 넣는다(확인 필요). [P13][P7][K1]
- **공개 서비스의 남용.** 익명 사용자, 대량 요청, 주제 밖 사용에 대한 호출 제한과 반복 시도자 제한을 더한다. [A8][P1][O2]
- **사고 사례.** 판매점 챗봇이 사용자의 지시대로 "구속력 있는 제안"이라고 답한 사건은 보도로만 확인했다. 법원 판단은 없다. 설계 규칙은 같다: 가격과 계약은 모델이 아니라 시스템이 정한다. [L2] [제안]

### 2-6. C8 운영 — 사고 대응과 신고

**고민할 것**
1. **무엇이 사고인가.** 권한 밖 데이터 노출, 승인 없는 변경, 금지 등급 값의 외부 전송, 틀린 규정 답변으로 인한 업무 피해, 감사 기록 누락. 종류마다 통보 대상(보안, 개인정보, 내부감사, 시스템 소유자)을 정한다. [N2][K1] [제안]
2. **멈추는 단위.** 전체가 아니라 도구 묶음 단위로 끌 수 있는가(변경 묶음만 끄고 지식 검색은 유지). [A8] [제안]
3. **직원이 신고하는 길.** 틀린 답, 보여서는 안 될 내용, 이상한 동작을 신고하는 경로가 있고 사람이 본다. 평가 버튼이 대화를 공급자에게 보내는 기능이면 사내 신고와 구분한다. [O2][P9]
4. **정기 점검의 주기와 담당.** 접속기록과 다운로드 상황, 어시스턴트 도구 권한의 재인증, 요청자와 승인자가 같은 건, 대화 기록 열람 내역. [K2][N1][K3]
5. **바뀌면 다시 확인할 것.** 모델, 프롬프트, 도구, 권한 설정, 공급자 약관, 법령. 조사일 기준으로 인공지능기본법과 개인정보 보호법은 2026년에 개정이 있었다. [K1][K6][P11]

**진행**
- 사고 종류별 절차서를 만든다: 탐지 신호, 묶음 차단, 영향 범위 재구성(감사 기록), 통보, 재발 방지 시험 추가. 개인정보 유출이면 통지·신고 절차로 이어진다. [K1][N1]
- 운영에서 "통과시키면 안 됐던" 입력과 과잉 차단 사례를 라벨 세트와 CT 시험에 넣는다. `security.md` 10절 [제안]
- 보존 기간이 지난 대화 기록의 파기를 자동 작업으로 만들고 실행 결과를 남긴다. [K1]
- 법규 점검표를 분기마다(제안값) 법무와 다시 보고 조사일을 갱신한다. [제안]

**검증**
- 모의 사고 한 건으로 묶음 차단부터 영향 범위 재구성까지 걸린 시간을 잰다. [제안]
- 신고가 사람에게 닿아 처리된 기록이 있다. 파기 작업이 실제로 지웠는지 표본으로 확인한다. [O2][K1]

**완료 기준**
- [ ] 사고 종류별 절차와 통보 대상이 있고 모의 훈련 기록이 있다 [N2][K1]
- [ ] 도구 묶음 단위 차단을 실제로 해 봤다 [제안]
- [ ] 직원 신고 경로가 있고 처리 담당자가 있다 [O2]
- [ ] 접속기록·다운로드·권한·직무 분리 점검의 주기와 담당자가 있고 첫 점검 기록이 있다 [K2][N1][K3]
- [ ] 보존 기간에 따른 파기가 자동으로 돌고 결과가 남는다 [K1]
- [ ] 모델·프롬프트·도구·권한 설정이 바뀌면 CT 시험이 다시 돈다 [P1][O2]

**흔한 함정:** 사고를 모델의 오답으로만 정의하기, 끄는 스위치가 전체 하나뿐이라 끄기를 미루기, 평가 버튼을 신고 경로로 쓰기, 점검을 "기록이 있다"로 끝내고 아무도 보지 않기, 약관과 법령의 조사일을 적지 않아 바뀐 줄 모르기. [K2][P9] [제안]

## 4. 확인 못 한 것

- **열지 못한 원문.** CanLII의 Moffatt 결정 페이지(403. 심판소 사이트의 결정문 PDF로 읽었다). 캘리포니아 주의회 법령 사이트(403)라 봇 고지법(SB 1001)과 동반자 챗봇법(SB 243)의 조문을 읽지 못했다. 개인정보보호위원회 사이트의 생성형 AI 안내서 원문과 인사·노무 가이드라인 원문(연결 실패, 게시판 검색 실패). OWASP Agentic Top 10 본문. 로펌의 Moffatt 해설 한 건(429).
- **조사하지 않은 것.** 택배 회사 챗봇 욕설 사건과 뉴욕시 챗봇의 잘못된 법률 안내 보도는 검색으로 확인하지 못해 싣지 않았다. 국내 위기 상담 전화번호. 금융·공공 업종의 망 분리와 외부 서비스 이용 규정. 내부회계관리제도의 설계·운영 기준과 평가 기준(IT 일반 통제 세부). ISO/IEC 27001·42001(유료 규격). 개인정보 보호법 시행령(유출 신고 기한, 위탁 세부).
- **일부만 읽은 것.** NIST AI 600-1은 2.4·2.7·2.9절과 개요만, NIST SP 800-53은 표에 적은 통제만, MCP 인가 규격은 토큰 대상 검증 구절만, RFC 8693은 초록과 1.1절만 읽었다. Anthropic 미성년자 지침은 고지 요구 한 줄만 확인했다.
- **날짜를 확정하지 못한 것.** Anthropic Usage Policy의 시행일. 인공지능기본법 과태료 계도기간의 공식 공고와 종료일. 국가법령정보센터에 표시된 "현행" 판의 시행일을 적었으므로 그 뒤 개정은 반영되지 않았다.
- **적용 판단.** 2-4절 점검표의 "적용" 열 전부. 특히 외부 모델 API 이용이 처리 위탁·국외 이전에 해당하는지, 대화 기록 수집이 근로자 감시 설비에 해당하는지, 어시스턴트의 변경·조회가 내부회계 통제 대상인지, 외부 전송이 영업비밀의 비밀 관리에 영향을 주는지는 법무·내부감사 검토 없이는 답할 수 없다.
- **효과 수치.** 주입 선별기의 탐지율, 권한을 아는 검색의 누출률, 승인 절차의 과잉 차단율은 측정한 값이 없다. 2-2절의 시험으로 우리 수치를 내야 한다. 문서의 "(제안값)"은 근거 자료가 없는 시작점이다.
- **제품별 동작.** 사용자별 위임이 대상 업무 시스템에서 실제로 가능한지, 화면 조작 경로에 걸 수 있는 제한, 변경 이관 절차와의 연결은 다른 조사의 범위다.
