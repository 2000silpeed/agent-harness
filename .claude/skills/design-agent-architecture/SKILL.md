# design-agent-architecture

## 절차
1. 업무 목표와 **완료 상태**를 한 문장으로 확인한다. 불명확하면 질문한다(필요하면 `interview-me`).
2. 워크플로우를 **5단계 이하**로 적는다. 넘으면 범위를 줄이자고 제안한다.
3. 각 단계에 **판단/생성** 라벨과 담당(CODE/MODEL/HUMAN)을 붙인다.
   - 루틴하거나 규정이 정해진 단계는 CODE가 맡는다.
   - 돈이 오가거나 민감한 쓰기 작업은 MODEL이 제안만 하고, 실행 전에 HUMAN 또는 CODE 게이트를 거친다.
   - 판단과 생성이 함께 있는 단계만 에이전트 후보로 표시한다.
4. 상태 변수와 의존관계를 그린다. 순서는 목표 → 상태 → 작업 → 선행 조건 → 종료 조건이다. 독립적인 조회만 병렬로 둔다.
5. 실행 구조(순차/병렬/분기/루프)와 패턴을 고르고 **이유**를 적는다. 기본은 Single + Skills다.
6. 예산(max turns, 호출, 시간)과 실패 유형별 처리를 적는다.
7. 평가 지표와 기준선 계획을 적는다(`templates/baseline-log.md`).
8. `templates/architecture.md` 형식으로 `docs/architecture/<name>.md`에 저장하고, 마지막 질문 6개(docs/10-harness.md)에 답이 있는지 검사한다.
