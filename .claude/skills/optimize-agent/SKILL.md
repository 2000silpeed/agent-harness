# optimize-agent

## 전제
- 가능하면 새 세션에서 상위 모델(Opus 등)로 진행한다. **분석을 먼저 하고, 구현은 그다음**에 한다.
- 제약: **동작이 바뀌면 안 된다.** 바뀔 수밖에 없다면 멈추고 사용자에게 묻는다.

## 절차
1. 현재 기준선을 측정한다(지연, 입력/출력 토큰, 호출 수, 품질). 골드셋이 있으면 함께 쓴다.
2. 질문 체크리스트로 코드를 분석하고 후보를 낸다.
   - 컨텍스트: 도구 수를 줄일 수 있나 / 프롬프트를 줄일 수 있나 / 스킬로 뺄 지점이 있나
   - 구조: 서브에이전트로 분리하면 빨라지나 / 더 작은 모델로 되나 / 판단 구간을 디시전 모델이나 클로즈드 퀘스천으로 바꿀 수 있나 / 캐시 배치(고정 앞, 변동 뒤)가 맞나
3. 후보마다 **토글**(환경변수, 플래그)로 구현한다. 한 번에 하나씩 한다.
4. 토글을 켰을 때와 껐을 때를 같은 입력으로 비교한다. 동작 불변(도구 호출 순서 동일)을 확인한다.
5. 후보마다 `templates/optimization-log.md` 형식으로 `docs/decisions/`에 근거를 남긴다.
6. 마지막에 "진짜 개선됐는가"를 검토하고, 효과 없는 토글은 철회를 제안한다.
