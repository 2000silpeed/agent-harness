## 5일차 2강 — Claude Code 사용 기록을 Langfuse로 남기기 (측정해야 개선할 수 있다)

> 출처: 「5일차 2강 다시보기 (재업로드)」(전사·분석, 44:51), 「5일차 2강 장표 (재업로드)」(15장). SDS AX Advanced · 2026-11-06.
> 이 강의의 Claude Code 플러그인 연동은 저장소에 대응 파일이 없다. Langfuse Cloud 가입·키 발급 부분만 `Day05_new/use_cc/missions/m0.md`(준비 1)와 `Day05_new/.env.example`에 대응한다.

### 핵심 요약 (3~5줄)
- "결국 측정해야 개선을 할 수 있기 때문에" — 자기 Claude Code 사용을 `history.jsonl` 말고 별도 플랫폼에 쌓아 본 적이 없다면, 오픈소스 관측 도구 **Langfuse**로 측정 단계를 시작한다.
- Langfuse를 고른 이유: 오픈소스이고 엔터프라이즈 기능까지 무료로 풀었으며, **셀프호스팅(도커 컴포즈)으로 인프라·DB를 직접 제어**하고 데이터를 내려받아 추가 작업할 수 있다(비교 대상 LangSmith는 클로즈드 소스, 셀프호스팅은 비싼 라이선스).
- 실습: Langfuse Cloud(Japan 리전, Hobby 무료 플랜) 가입 → 조직·프로젝트 생성 → API 키 발급 → Claude Code에게 연동을 시켜 **전역·공식 플러그인** 설치 → `~/.claude/settings.json`의 `env`에 public key·secret key·base url 입력 → 재실행 후 Tracing·Sessions 화면 확인.
- 플러그인은 Claude Code가 **멈출(Stop) 때마다** 기록을 보내므로 실시간 확인은 어렵다. 그래도 "일단 데이터를 쌓는 게 가장 중요"하다.
- 한 대화 턴(약 48초)을 열어 보니 429 에러 뒤 재시도 코드를 Bash로 돌리느라 시간이 걸린 사실이 보였다 → "다음에 재시도 하지 말라" 같은 개선 힌트. Claude Code뿐 아니라 직접 만들 에이전트에도 같은 방식으로 쓴다.

### 주요 개념 (개념별 설명, 강사가 강조한 이유 포함)

**1. 도입 일화 — 컨텍스트 엔지니어링과 비용**
- 바이브 코딩 성과 측정 서비스("바이브 매트릭")를 준비하는 고등학생이 "모델도 좋은데 컨텍스트 엔지니어링을 굳이 해야 하나, CLAUDE.md 잘 쓰고 스킬 좀 잘 쓰면 되는 거 아니냐"고 물음.
- 강사 답: "비용 얼마나 중요한데. 싸게 잘 만드는 게 사실 제일 좋은 거 아니냐." Opus로 계정 여러 개 돌리면 안 느껴지지만 기업 입장에서는 비용 관리가 엄청 중요하다. 상대는 고려하지 못한 시각이라며 고마워함.
- 강조 이유: 지금 주제(측정·평가)와 맞닿아 있음.

**2. 왜 Claude Code 사용을 측정하는가**
- "클로드 코드, 나의 클로드 코드 사용을 모니터링 해보신 적이 있나요? 시스템의 history.jsonl로 쌓이는 거 말고." → 대부분 없음.
- "결국 측정해야 개선을 할 수 있기 때문에" 측정 단계를 Langfuse로 해 본다. 원래 로컬에 띄우려 했으나 시간이 오래 걸려 클라우드로 바꿨다.

**3. Langfuse — 배경과 LangSmith 비교**
- 독일에서 시작, Y Combinator 지원으로 성장, 현재 **ClickHouse**(데이터베이스 회사)에 매각됨. 스택도 ClickHouse 기반.
- 초기 경쟁: ARIS(Arize로 추정) 등 여러 ML 회사의 관측 도구가 "춘추전국 시대" → Langfuse가 평정. 이유: **무료, 오픈소스**, 그리고 약 2년 전쯤 **엔터프라이즈 기능까지 무료로 풀어버림**("얘네 미쳤나?"). 이후 그걸 클라우드로 가져가 업데이트.
- **LangSmith**와 양대산맥: LangSmith는 오픈소스가 아니고(클로즈드 소스), 1년 전까지 셀프호스팅이 어려웠으나 지금은 비싼 라이선스로 셀프호스팅을 판매. 국내에도 설치한 회사가 있고, 기술 지원·관리를 잘 해 준다고 함.
- 오픈소스 Langfuse를 고른 이유: 인프라를 다 제어할 수 있고, DB를 우리가 제어하니 **데이터를 다 다운받아 추가 작업**도 가능 → "우리가 제어권을 다 가진다."
- 셀프호스팅 = 로컬에도 설치 가능. 내 AI 에이전트 사용 기록을 나만 모아 보고 싶을 때도 도커 컴포즈 기반으로 어렵지 않다("요즘은 도커 컴포즈도 클로드한테 해줘 하면 싹 띄워줍니다").
- LangChain 연동: 예전엔 호환이 나빠 억지로 개발했으나 지금은 세팅 한 줄. "랭스미스 0줄, 랭퓨즈 1줄."
- ClickHouse 인수 후 V4 새 버전이 나와 속도가 빨라진다고 함.

**4. 트레이스·세션의 구조**
- Langfuse가 수집하는 트레이스는 **호출 하나하나**를 기록: LLM 호출도 하나의 트레이스, LLM이 요청해 도구를 호출한 것도 하나의 트레이스 → 바깥(목록)에서 하나씩 눌러 보기 불편.
- 그래서 **대화 턴(conversation turn)** 단위로 "콜, 툴, 툴, 툴, 툴"을 합쳐 보면 읽기 쉽다. Sessions 메뉴는 Claude Code 대화 한 건 단위.
- UI가 불과 두 달 전까지 "정말 못생겼었는데" 지금은 좌우 구분, 툴 콜링 표시, 턴 구분이 되어 보기 수월해졌다.

**5. 플러그인의 전송 시점 — Stop 후 전송**
- Claude Code 동작 특성상 트레이스가 남는 게 꽤 느리다. 대화 기록을 **Claude Code가 작업을 멈출(Stop) 때마다** 보낸다. 중간중간 보내면 부하가 심하고 한꺼번에 취합할 필요가 없어서.
- 그래서 대화 하나 치고 바로 Langfuse에서 보기는 어렵다. 말하는 중에는 아무리 쳐다봐도 기록이 없다. 그래도 작업 내역을 볼 수 있다는 점에서 의미가 있다.

**6. 쌓은 기록으로 할 수 있는 일**
- 회고, Claude Code용 설정 값 갱신·업데이트, eval(평가)에 큰 도움. "일단 데이터를 쌓아야 돼요. 쌓는 게 가장 중요합니다. 안 쓰고 버리더라도 일단 쌓아 놔야 뭘 하실 수가 있습니다."
- 여러 PC(맥북, 집의 맥미니 등)의 Claude Code 세션을 밖에서도 한 화면에서 확인 — 검정 화면보다 가독성이 좋다.
- 관측 도구이므로 **알람**: 긴 작업을 돌려 놨을 때 이슈 알림 등.
- 운영 사례: 예전엔 alert이 오면 사람이 다 대응 → 사람이 사전 조치를 적어 두면 **AI가 먼저 대응하고 사람에게 노티**. 그런 시스템을 구축할 때도 트레이스가 도움이 되고, 에이전트가 "혹시나 나쁜 짓을 하진 않았는지" 점검하는 데도 쓴다.

**7. 트레이스 한 턴 읽기 → 개선 힌트**
- 사용자 입력 "이번 세션 트레이스 올라왔는지 확인해줘" 턴: 전체 **48초**, 마지막 응답은 약 **11초**(강사는 "10초 정도"라고도 함), 앞의 약 38초는 에이전트가 작업에 씀. 그래프만 봐도 맨 아래 항목이 굉장히 오래 걸렸다.
- LLM 콜 → 도구 실행 → **429 에러(Too Many Requests)** — 너무 짧은 시간에 Langfuse를 호출해 거절된 것으로 보임. 이후 "또 콜하고 또 도구 실행" 반복.
- 강사 코멘트(전날 배운 내용 연결): "얘는 왜 이렇게 멍청하게 호출을 할까. 요 콜 하나에 툴 툴 툴 툴 호출할 순 없었을까." 왔다 갔다 하는 것 자체가 네트워크 부하. (중간 기록을 봐야 하는 경우라면 불가피하긴 하다.)
- 오래 걸린 Bash 툴: 파이썬 스크립트를 짰고 타임아웃을 길게 걸었으며, 설명에 "레이트 리밋 때문에 리트라이를 하겠다" — 429 때문에 재시도 코드를 짜서 돌렸고 재시도를 두 번 하며 시간을 잡아먹었다(after 2).
- "저 같으면 하지 말라고 할 것 같아요. 다음에 리트라이 하지 말라고 해야 해." → 측정했기 때문에 얻는 힌트. 눈으로(CLI에서) 보면 안 보인다. "한 땀 한 땀 읽으실 수 있겠어요? 저도 못 읽습니다" → 정리된 형태가 필요하고, AI에 분석을 맡기더라도 사람이 확인하는 과정이 있으면 더 잘 쓴다.
- "이게 클로드 코드 뿐만 아니라 여러분들이 개발하실 에이전트도 똑같이 개선하시는데 도움이 되는 거죠."

### 실습/데모 내용 (명령어, 파일 구조, 프롬프트, 코드 조각 등 원문 그대로 보존)

**A. Langfuse Cloud 가입·프로젝트 생성**
1. 구글에서 "랭퓨즈" 검색 → 사이트 오른쪽 위 파란색 **Launch App** → **Start Free**(로그인 상태면 바로 진행).
2. 리전 옵션에서 가장 가까운 **Japan** 선택 — "데이터를 보관하는 리전이 재팬." (저장소 확인: 로그인 화면의 Data Region이 프로젝트 주소가 되며 예시 `https://jp.cloud.langfuse.com`, 키와 주소의 지역이 다르면 인증이 401로 실패 — `Day05_new/use_cc/missions/m0.md:40`; `.env.example`의 기본값 `LANGFUSE_HOST=https://jp.cloud.langfuse.com` — `Day05_new/.env.example:5`)
3. 이메일 또는 Google 등 편한 방법으로 가입(강사는 Google).
4. Organization 설정(이름·닉네임 등 자유) → 프로젝트 생성(이름은 각자 달라도 됨).
5. Hobby(무료) 플랜 상태로 **Tracing** 화면에 들어가면 API 키를 만들라는 화면이 뜸 — 이 시점에서 잠시 대기. (저장소 확인: Hobby 요금제는 월 5만 unit — `Day05_new/use_cc/missions/m0.md:16`. 전사 "합의라는 일반 취미 플랜"은 Hobby로 확인)

**B. Claude Code에 Langfuse 연동 시키기**
- 터미널이든 앱이든 상관없음. 강사는 터미널로, 수업 자료 폴더에서 실행("어차피 글로벌로 설치를 할 거기 때문에" 위치 무관).
- 지시: 영어일 필요 없이 "랭퓨즈로 트레이싱을 하고 싶다", "랭퓨즈를 연동하고 싶다". 강사 화면 입력: "클로드 코드 트레이싱을 랭퓨즈로 하고 싶은 …"
- Claude Code가 `랭퓨즈/클로드 옵저버빌리티 플러그인`(Langfuse 공식 Claude observability 플러그인)을 설치하라고 찾아 줌. (수업 폴더에서 실행했다면 Langfuse 스킬을 로드했을 수 있음 — "괜찮습니다.")
- 질문 "이 프로젝트만 / 모든 프로젝트 / 공식 플러그인?" → **공식 플러그인** 선택이 좋다. 안 물어보면 "공식 플러그인이 있는지 찾아보라"고 해도 됨.
- 강사 지시: "랭퓨즈 키는 내가 직접 입력을 하겠다." / 키를 어디 넣을지 물으면 "글로벌 settings.json이라는 파일에다가 넣겠는데 내가 알아서 넣을게."
- 설치 후 Claude Code가 환경 변수를 입력해 달라고 함.

**C. 전역 settings.json에 키 넣기**
- 경로: 홈 아래 `.claude` → `settings.json`(강사 판서 "물결 슬래시 .claude" = `~/.claude/`, "글로벌 클로드 경로"). VS Code로 열어 손으로 수정. (WSL 환경 수강생도 있음 — 유저 루트, 홈 밑으로.)
- `env` 항목이 없으면 직접 작성(강사는 위쪽에 쓰는 걸 선호). Claude가 알려준 세 값을 복사·붙여넣기: **public key, secret key, base url**.
- 개인 설정(강사 화면의 다른 값)은 없어도 무방.
- Langfuse 화면으로 돌아가 **create a new api key**(검은색 버튼) → secret key, public key, `.env`용 값이 나옴.
- 주의: 그대로 붙이고 싶은 유혹이 있지만 변수명 앞에 `cc_`(CC_) 프리픽스가 붙는 경우가 있다 → 안 붙어 있으면 그대로 복사, 붙어 있으면 **값만 한 땀 한 땀** 바꿔 넣기. "특히 base url 중요합니다." (저장소 확인: 키 발급 대화 상자의 `.env` 예시 세 줄은 `LANGFUSE_SECRET_KEY`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_BASE_URL`이며 **Secret Key는 이때 한 번만 보인다** — `Day05_new/use_cc/missions/m0.md:42-43`. 단, 저장소는 이 값을 `Day05_new/.env`에 넣는 흐름이고 플러그인용 `settings.json` 변수명은 저장소에 없음)
- 수강생 질문 "CC라고 입력해야 되나요?" → "아니요. 새로 만드시면 클로드에서 그냥 랭퓨즈 퍼블릭키, 시크릿키, 베이스 URL이라고 안내해 줬을 것." 모르겠으면 "클로드한테 값을 입력할 수 있게 **껍데기 값을 입력해 놓으라고**" 해도 된다. 플러그인 설치 케이스마다 (플러그인 세팅으로 바로 들어가는 등) 조금씩 다를 수 있으나 목적은 public/secret/base url 세팅.
- 저장 후 Claude에게 "세팅했다, 체크해 달라"고 요청. 목적: "글로벌로 어디서 이 PC에서 클로드를 키더라도 트레이스가 되게."

**D. 연동 확인**
- Claude가 "Langfuse observability 플러그인 사용 중, 테스트 확인, **Claude Code 재실행해 주세요**"라고 안내 — 환경 변수를 바꿨기 때문.
- 새 세션에서: "랭퓨즈랑 클로드 코드랑 연동됐는지 테스트해 봐라" → "연동 정상" → "이번 세션에 트레이스가 올라왔는지 확인해 줘".
- Langfuse **Tracing** 메뉴: "알아들을 수 없는 내용들이 잔뜩" — `LLM 콜`, `콜배시` 등이 쌓여 있으면 세팅 성공.
- **Sessions** 메뉴: 새 세션으로 테스트했다면 두 개 세션(하나여도 무관). 클릭해 CLI에서 본 내용과 일치하는지, 읽기 쉬운지 훑어보기. 긴 설정 값은 `show more`로 — "CLI에서 볼 때보다 좀 더 예쁘게."
- 강사 세션 결과: 중간에 **429 레이트 리밋**이 걸렸다가 "이번 세션 트레이스가 랭퓨즈에 올라왔습니다", 세션 ID는 `1597`로 시작.

**E. 트레이스 한 턴 분석(강사 화면)**

### 강사 팁·주의사항
- 키 위치는 **전역**(`~/.claude/settings.json`)에 두어야 어느 폴더에서 Claude Code를 켜도 트레이스된다.
- 플러그인은 **공식 플러그인**을 고른다. 안 물어보면 공식 플러그인이 있는지 찾아보라고 시킨다.
- 키는 Claude에게 맡기지 않고 직접 입력하겠다고 지시했다. 변수명 프리픽스(`CC_`) 유무를 확인하고 값만 바꿔 넣는다. **base url이 특히 중요**하다.
- 환경 변수를 바꾼 뒤에는 Claude Code를 **재실행**하고 **새 세션**에서 테스트한다.
- 기록은 Stop 시점에 전송되므로 진행 중에는 Langfuse에 아무것도 안 보이는 게 정상이다.
- 짧은 시간에 Langfuse를 많이 호출하면 429가 나고, 에이전트가 재시도 코드를 짜며 시간을 잡아먹을 수 있다 — 트레이스에서 이런 패턴을 찾아 지침("재시도 하지 말라")으로 고친다.
- 한 번의 LLM 콜에 여러 툴을 묶어 부를 수 있었는지 본다 — 왕복 자체가 네트워크 부하.
- 일단 쌓아라 — 나중에 안 쓰더라도 쌓아 둬야 회고·평가·개선을 할 수 있다.

### 실제 프로젝트에 적용할 체크리스트 (- [ ] 행동 지침 형태, 특정 프레임워크에 묶이지 않는 원칙 위주)
- [ ] 개선을 논하기 전에 에이전트(코딩 에이전트 포함)의 실행 기록을 별도 관측 플랫폼에 쌓는 것부터 시작한다.
- [ ] 관측 도구를 고를 때 데이터 제어권(셀프호스팅 가능 여부, DB 접근, 데이터 내보내기)과 라이선스 비용을 비교한다.
- [ ] 클라우드 관측 서비스를 쓸 때 데이터 보관 리전을 의식적으로 고르고, 키와 접속 주소(base url)의 리전이 일치하는지 확인한다.
- [ ] API 키는 대화창이 아니라 설정 파일에 직접 입력하고, secret key는 발급 직후 안전하게 보관한다.
- [ ] 연동은 공식 제공 통합(플러그인·SDK)을 우선하고, 설정은 모든 작업 위치에 적용되도록 전역 범위에 둔다.
- [ ] 설정 변경 후 프로세스를 재시작하고 새 세션으로 기록이 실제로 들어오는지 확인한다.
- [ ] 기록 전송 시점(실시간/종료 시)을 파악해, 기록이 안 보일 때 전송 지연인지 연동 실패인지 구분한다.
- [ ] 트레이스는 개별 호출이 아니라 대화 턴·세션 단위로 묶어 읽는다.
- [ ] 턴별 소요 시간에서 오래 걸린 호출을 찾고, 에러(예: 429) 뒤 재시도 반복 같은 낭비 패턴을 확인한다.
- [ ] 한 번의 모델 호출로 묶을 수 있었던 연속 도구 호출이 있는지 점검해 왕복 횟수를 줄인다.
- [ ] 트레이스에서 찾은 문제는 지침·설정(예: 불필요한 재시도 금지)으로 반영하고, 반영 후 다시 기록으로 확인한다.
- [ ] 여러 장비·사용자의 세션을 한곳에 모아 보고, 이슈 알림과 에이전트의 부적절한 행동 점검에 기록을 활용한다.
- [ ] 알림 대응을 자동화할 때는 사람이 사전 조치를 문서로 정해 두고 AI가 그 범위에서 먼저 대응한 뒤 사람에게 알리게 한다.
