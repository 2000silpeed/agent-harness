### 핵심 요약 (3~5줄)
- 가드레일은 **LLM(모델) 기반**(사용자 텍스트가 시스템에 위험한지 의미 단위로 판단)과 **코드(에이전트) 기반**(에이전트 루프의 훅, 도구 내부의 호출 전후 검증)으로 나뉜다. 더 효과적이면서 뚫렸을 때 더 위험한 쪽은 코드 기반이다(데이터 유출로 이어진다). 에이전트는 챗봇이 아니므로 목적은 **행동 제어**다.
- 제어 지점은 에이전트 루프를 따라 **입력 → (계획) → 도구 호출 전 → 샌드박스 실행 → 도구 결과 → 최종 출력** 순이다. 가장 힘을 줄 곳은 **도구 호출 전**이며, 도구 앞에 권한 레이어(MCP 게이트웨이)를 두고 우회는 네트워크로 끊는다. 최종 출력 가드는 버퍼가 필요해 속도를 잃으므로 "거의 없다".
- Meta의 **Agents Rule of Two**: 믿을 수 없는 입력 / 민감 시스템·비공개 데이터 접근 / 상태 변경·외부 통신 가운데 둘까지는 필터·제어로 자율 운영하고, **셋이 다 겹치면 자율 실행 금지, 사람 승인**이다.
- 사고(DB 삭제 등)의 대부분은 **권한을 많이 준 데서** 나온다. 권한 제어가 "귀찮다"는 것이 진짜 문제이므로, 뒤쪽 MCP는 권한별로 촘촘하게 만들고 게이트웨이의 **가상 MCP 서버**로 도구 일부만 잘라 내준다.
- 시연: Claude 앱(Opus, effort medium)에 가스라이팅(여러 턴에 걸친 몰아가기)을 걸어 **시스템 프롬프트 방어(부드러운 대화형 거절)**와 **프로그램 가드(대화·계정 차단)**의 차이를 보였다. 다음 시간에 입력 가드레일을 직접 만든다.

### 주요 개념 (개념별 설명, 강사가 강조한 이유 포함)

**1. 두 종류의 가드: LLM 기반과 코드 기반 (00:00~03:42)**
- **LLM(모델) 기반 가드**: "보통은 의미 단위를 추적"한다. "사용자의 텍스트가 우리 시스템에 위험을 가할 것인가"처럼 의미적으로 시스템에 영향을 주는 것을 막을 때 쓴다.
- **코드(에이전트) 기반 가드**: 모델 기반이 아닌 것은 대부분 여기에 든다. "코드로 실행되는 것들에 방어를 한다."
  - 범위: "에이전트 루프 속에서 우리가 **훅으로 방어할 수 있는 거 다 포함**" + **도구 내부 로직의 호출 전후 검증**("이런 동작이 맞았나? 틀렸나?", "출력이 우리가 원하는 아웃풋으로 왔나?").
  - (저장소 확인: `Day08_new/README.md:7-8` — 판정 주체 "Agent 로직(코드): 권한·범위·형식·한도·순서 — 결정적", "LM 모델: 의미·문맥·정책 위반". `Day08/Day8_Agent_Guardrails_이론자료.pdf` p.24 "Model Guardrail과 Code Guardrail의 역할", p.41 "Middleware / Tool Wrapper / Validator / Sandbox", p.46 훅 시점별 책임 표.)
- 위험도: "**더 효과적이고 만약에 뚫렸을 때 더 위험한 거는 사실 코드 기반의 가드레일이 더 위험해요.**"(00:46) "데이터가 유출된다던가 뭐 이런 것들."

**3. 에이전트 루프의 제어 지점 (06:06~10:31)**
- "전체적인 에이전트 루프의 관점에서 제어 지점을 어디 어디에 넣어야 되나"를 본다. (저장소 확인: `Day08/Day8_Agent_Guardrails_이론자료.pdf` p.14 — 외부 입력 → Input Guard → Agent → Action Guard → Tool 실행(제한된 환경) → Tool Result Guard → Output Guard.)
- **입력**: 사용자의 입력과 상대 시스템의 입력 두 가지.
  - 사용자 입력: 우리를 공격하는 것인지, 즉 **프롬프트 인젝션**인지 아닌지 분류한다.
  - 상대 시스템이 전달한 것: **개인정보** 관련 내용이 있는지 걸러낸다.
  - (저장소 확인: 같은 PDF p.15 "Input Guard: 정규화·PII/DLP·Injection·출처·권한", p.8 "Input은 사용자 프롬프트보다 넓습니다".)
- **계획**: 에이전트가 계획을 짜는 것까지는 문제가 없다.
- **도구 호출 전**: "특히 그 도구를 호출하기 전에, 전에 우리는 걸러내야 돼요. 왜냐하면 **이미 도구를 호출하고 나서 걸러내는 건 꽤 귀찮은 작업**입니다."(07:15) 호출 후에도 거를 수는 있지만 호출 전에 최대한 필터링한다.
  - (저장소 확인: 같은 PDF p.18 "Action Guard는 실제 호출 직전에 둡니다 — 최종 답변을 차단했어도 이미 이메일을 보냈다면 늦습니다".)
- **권한 레이어 / MCP 게이트웨이**: 그래서 도구 앞에 권한 레이어를 두는 경우가 많다. MCP 수업에서 말한 MCP 게이트웨이의 취지 — MCP는 뒤의 데이터 소스와 자유롭게 통신하게 두고, 그 앞의 게이트웨이에서 **권한과 보안을 관리**한다.
  - 문제: 게이트웨이를 **우회해서 연결**하는 것은 막기 어렵다.
  - 강사 권고: "제일 좋은 건 저는 이렇게 아예 **네트워크로 그냥 딱 끊어놓고** 여기는 그냥 아예 통신 불가 지역"(08:08). MCP를 제공하는 쪽은 **게이트웨이로만 통신 가능**하게 구성한다.
  - "도구 호출 전에 끊어내는 거는 … 에이전트 루프 속에서의 코드만을 의미하는 것처럼 보이지만 실제로 … **인프라적인 측면에서도** 이렇게 구성을 해야 됩니다."
- **샌드박스**: Claude, Codex, Antigravity 등 "모든 코딩 에이전트"가 가장 집중하는 것. 격리된(전사 "경리된") 실행 환경에서 코드를 실행한다.
  - 이유: 업무용 PC는 민감 정보와 회사 소스 코드를 다루는 장비("그냥 가지고 나가면 보안 위협")인데 "그런 장비들을 얘가 직접 제어하는 게 맞나". 실수 한 번이 그대로 정보 유출이 된다.
  - 곁들인 사례(강사 전언): 전날 기사로 "금융보안원도 지금 털렸대요", 어느 정부기관에서 개인이 업무용 PC로 ChatGPT(전사 "채취 pt")에 중요 자료를 올린 일.
  - (저장소 확인: 같은 PDF p.53 "Sandbox: 파일·네트워크·실행 자원 격리 — Network egress 기본 deny, 호스트 키·민감 볼륨을 넣지 않음". `Day08_new/docs/sources/01_agent_logic_cases.md:26` Claude Code 샌드박스 항목.)
  - (공식 문서 확인: https://code.claude.com/docs/en/sandboxing — Claude Code의 샌드박스 Bash 도구는 macOS Seatbelt, Linux·WSL2 bubblewrap으로 파일시스템·네트워크를 격리하고, 네트워크는 프록시의 허용 도메인 목록을 거친다. https://developers.openai.com/codex/concepts/sandboxing — Codex의 workspace-write 샌드박스는 기본으로 네트워크가 꺼져 있다. https://antigravity.google/docs/sandbox/ — Antigravity 터미널 샌드박스. 금융보안원·정부기관 사례는 미확인.)
- **도구 결과(사후)**: 호출 전 검증이 기본이지만, 호출 결과를 "모델에 보내지 않으면 일단은 안전"하므로 "정말 정말 최악의 경우에 **보내기 전에 필터링**"할 수도 있다.
  - (저장소 확인: 같은 PDF p.14 "Tool Result Guard", p.43 Tool Wrapper 의사코드의 "실행 후: 크기·DLP·Injection 검사 후 모델로 결과 전달".)
- **사용자에게 나간 뒤**: "거기서부터는 이제 뭐 그냥 뒷수습."
- 강사 정리: 여기 앞까지는 "지금 여러분들이 아는 방식으로 다 구성을 하실 수 있어요. 여기는 전혀 새로운 게 없습니다."(10:46)

**4. 최종 출력 가드: 버퍼와 금융사 챗봇 사례 (10:31~14:28)**
- 질문: 진짜 아웃풋이 나가기 직전에 무엇을 해 볼 수 있나. 사용자 화면에 나가 버리면 "진짜로 답이 없어요" — 나간 것을 주워 담을 수 없다.
  - (저장소 확인: 같은 PDF p.20 "이미 외부로 전송한 데이터는 나중의 Output 검사로 되돌릴 수 없습니다". `Day08/README.md:33` — 최종 답변만 검사하면 답변은 깨끗한데 전송함·초안에 전화번호가 남는다.)
- 방법: **버퍼를 하나 더 둔다.** 대가는 속도("살짝 포기").
- 강사 판단: 거기까지 갔다면 이미 방어선을 너무 많이 친 것이고, 속도·서비스 경험 관점에서 좋지 않다. "**그래서 이 마지막 레이어는 거의 없습니다. 거의 없어요. 근데 진짜 최악의 경우에 해야 된다면 할 수도 있을 것 같아요.**"(12:11)
- 강사가 경험한 사례 — **금융사 챗봇**
  1. 답변을 내보내기 전에 **버퍼에 쌓는다**.
  2. **키워드 기반 프로그램 1회**: 버퍼의 답변을 빠르게 훑어 민감 키워드를 찾는다(예: "대출을 무조건 받을 수 있어요" 같은 멘트, "대출" 키워드).
  3. **모델 2회**: 위험 여부를 **전체 글로 한 번**, 키워드가 발견된 **문장만 떼어 한 번 더** 본다. "프로그램 한 번, 모델 두 번."
  4. 느려지는 것은 **UI에서 해결**: 전체 검사를 통과하면 출력이 시작되는데 **문장 단위로 출력**한다. 첫 문장이 사용자에게 나가는 동안 둘째 문장의 가능 여부는 뒤에서 이미 판정돼 있다. 모델과 프로그램이 모두 OK여야 나간다.
  5. 문제 문장의 **기본 정책은 삭제**: "그냥 안 내보내. 문장이 매끄럽지 않아도 돼요. 어차피 AI가 답변한다는 걸 모두가 인식하고 있으니까." 애매하면 기본 삭제로 출발했고, 나중에 앞단과 마지막 단을 고쳐 더 매끄럽게 만들었다.
- 22:33에 다시 정리: 아웃풋은 "막기가 거의 불가능", "성능을 좀 포기해야만" 할 수 있다. 이 부분은 나중에 코드로 더 본다고 했다.
- (확인: 강사 개인 경험이라 외부 자료로 확인할 수 없다. 같은 PDF p.32의 "스트리밍 설계 예시: 검사 완료 전 외부 전송을 보류"가 같은 방향의 설계다.)

**5. 판단(디시전) 모델 (14:28~15:33)**
- "요즘 좀 추가된 방식"이다. LLM은 여전히 느린데, 가드레일에서 모델이 하는 일은 "말을 하는 게 아닙니다. 대부분 **판단**을 해요." — 민감 정보가 있다/없다, 시스템을 공격할 것 같다/아니다.
- 그러면 이 부분은 판단 모델로 대체할 수 있지 않을까. 단 "**저도 이걸 프로젝트에 써보진 못했습니다.**"

- (저장소 확인: `Day08_new/README.md:9` — 판정 주체 "Decision 모델: 타입 있는 질문에 확률로 답", 구현은 TypeSafe Jev. `Day08_new/04_decision_guards.py:2`. LFM은 `Day08/README.md:37`과 `Day08/07_lfm_encoders.py:2-9`의 LFM2.5 PII-Detector·Policy-Linter(Encoder), 같은 PDF p.28. 저장소에서 Decision 모델과 LFM Encoder는 서로 다른 부품이다.)
- (공식 문서 확인: https://www.liquid.ai/blog/lfm2-5-encoders — 2026-07-28, LFM2.5-Encoder-230M·350M, PII 탐지와 정책 린터 데모. 글에 "guardrail"이라는 단어는 없다.)

**6. Agents Rule of Two (15:33~18:10)**
- 에이전트 시스템을 구성할 때 세 가지를 조합의 관점에서 본다(Meta 공개).
  - **믿을 수 없는 입력**을 처리한다.
  - **민감 시스템 또는 비공개 데이터**에 접근한다.
  - **상태 변경**을 하거나 **외부 통신**을 한다.
- 둘까지는 조합해 허용하고 막는 방법도 어느 정도 제시한다. "**이 세 개를 다 한다? 자율 실행 금지에요.**"(16:25)
- 둘인 경우의 예
  - 믿을 수 없는 입력을 민감 시스템에 넣는다: "말만 들어도 좀 이상"하지만 프로그램으로, 또는 에이전트를 만드는 사람을 통해 처리할 수 있을 것 같다.
  - 민감 시스템에 접근하면서 외부와 통신해야 한다(극단적이라 흔치 않다): "외부 통신을 굳이 받아야 되나. **한쪽 끊어버리면 안 되나.**"
- 셋이 동시에 일어나면 "최악" → "그때는 **무조건 사람의 승인**이 필요"하다. 둘인 경우에는 에이전트 프로그램을 적절히 제어해 자율 운영이 되도록 만들 수 있다.
- Meta 공개 후 "거의 1년이 다 된 시점"이고, Anthropic도 비슷한 글을 최근에 냈다.
- 강사 정리: 가드레일을 "정말 진짜 무슨 방어막"으로 생각하기보다 "**프로그램으로 이 녀석의 출력을, 입력을 제어한다**"는 측면에서 다가가면 좋다(17:52).
- (저장소 확인: `Day08_new/01_incidents_baseline.py:7` "Rule of Two(Meta, 2025-10): 도구를 [A] 비신뢰 입력 [B] 민감 데이터 [C] 상태 변경·외부 통신으로 칠한다", `:113` 표 제목 "한 세션이 셋을 다 가지면 위험하다". `Day08_new/guard_lab/tools.py:23-32` `RULE_OF_TWO` 도구별 태그, `Day08_new/README.md:130-138`. 사람 승인 구현은 `Day08_new/README.md:11`의 `06_hitl_interrupt.py`.)
- (공식 문서 확인: https://ai.meta.com/blog/practical-ai-agent-security/ — 2025-10-31. 한 세션 안에서 [A]·[B]·[C] 가운데 최대 둘만 충족해야 하고, 셋이 다 필요한데 새 세션으로 나눌 수 없으면 자율 운영을 허용하지 않고 최소한 감독(사람 승인 또는 다른 신뢰할 수 있는 검증 수단)을 둔다. 최소 권한을 대체하지 않는 보완 원칙이라고 명시한다. 강의의 "무조건 사람 승인"보다 공식 글의 표현이 넓다.)
- (Anthropic의 "비슷한 글"이 어느 글인지는 강의에서 특정하지 않았다 → 미확인. 후보: https://www.anthropic.com/research/how-we-contain-claude — 2026-05-25, 환경·모델·외부 콘텐츠 세 층의 격리 설계를 다룬다. Rule of Two를 이름으로 언급하지는 않는다.)

**7. 사고 사례와 권한 중심 제어 (18:10~20:22)**
- "이런 사고들은 비일비재": Replit(전사 "애플릿" — 추정)의 DB 삭제 사고, `rm -rf`(전사 "RMRF" — 추정). "지금도 많이 삭제를 해요."
  - 처음 나왔을 때는 "Supabase DB가 날아갔네, Replit DB가 날아갔네, Lovable이 갑자기 내 화면을 없애버렸네"가 비일비재했다.
  - "이제 Claude는 삭제를 하진 않는 것 같아요. 이런 사례가 최근에는 없습니다." 모델사가 가드레일을 많이 쳐 놨고, Claude Code도 "워낙 욕을 많이 먹어서 가드레일이 빡빡하게" 쳐져 있다.
- 강사 생각: 수강생은 DB가 날아가도 당황하지 않을 것이다. 서비스 개발에서는 DB를 **백업**하고, 개발 중 DB는 날아가도 그만이며, **운영 DB를 AI에 꽂을 일은 잘 없다**. 운영 DB 작업이 필요하면 스테이징·개발계로 내려서 한다.
- 기본기: **프로덕션 분리**. 승인 없이 실행되는 삭제 SQL(**DELETE, DROP, TRUNCATE**)은 다 막는다. "니가 그걸 왜 실행해. 차라리 **그 SQL 문장을 나한테 줘. 그냥 내가 실행할게.**"
- 핵심: "**대부분은 사실 권한을 많이 준 거에서 모든 문제가 비롯됩니다.**"(20:04) 에이전트 시스템 내부만 보면 "거의 대부분의 사고는 사실 **권한으로 다 제어가 가능**"하다. 그런데 "우리는 귀찮죠. **이게 제일 사실 문제에요. 귀찮다는 거.**"
- (저장소 확인: Replit 사고는 `Day08_new/docs/sources/01_agent_logic_cases.md:10` — 2025-07, code freeze 선언 뒤에도 운영 DB 삭제, 막았을 경계는 dev/prod 분리·운영 DB 자격증명 격리, 확인 수준 [2차]. `Day08_new/docs/sources/05_verification.md:57-65`도 1차 게시물은 열지 못했다고 적는다. Supabase는 저장소에서 "DB 삭제"가 아니라 MCP를 통한 토큰 유출 사례다 — `Day08_new/01_incidents_baseline.py:55-62`. 강의의 "Supabase DB가 날아갔네"와 다르므로 미확인. Lovable 사례는 저장소에 없다 → 미확인.)
- (저장소 확인: 최소 권한은 같은 PDF p.52 "Subagent마다 최소권한을 확인합니다", p.12 "Tool 오용/권한 악용 → 사용자-자원 권한 + 최소 Tool".)

**8. MCP 게이트웨이와 가상 MCP 서버 (20:22~22:00)**
- 그래서 MCP 게이트웨이 같은 서비스가 중요하다. MCP 도구를 만드는 것은 어렵지 않고 권한을 많이 풀어 줄 수 있는데, **다이렉트로 연결하면** 문제가 생긴다 → 그 앞에 **권한을 제어하는 레이어**를 두고, 여러 가지를 쉽게 조합할 수 있게 한다.
- "UI로는 보지 못했는데" **IBM의 MCP ContextForge**(전사 "MCP 컨텍스트 포지") 게이트웨이 프로젝트가 **버추얼 MCP 서버** 기능을 지원한다.
  - 가상의 MCP 서버를 만들고, 뒤에 있는 MCP 서버의 **일부 기능(도구 몇 개)만 잘라** 가져와 쓰게 한다.
  - 뒤의 MCP는 "진짜 **API 마냥 촘촘하게**", 권한별로 만들어 둔다.
  - 버추얼로 제공할 때 "딱 딱 잘라가지고" 내준다 → "얘가 아무리 하고 싶어도 거기로 호출할 수가 없는" 방식으로 권한을 제어한다.
- (공식 문서 확인: https://github.com/IBM/mcp-context-forge — IBM GitHub 조직의 오픈소스(Apache-2.0) 게이트웨이·레지스트리. 카탈로그의 도구 ID를 `associatedTools`로 묶어 virtual server를 만든다. Admin UI가 있다. 장표 보충은 "알파 단계"라고 적었으나 현재 README 예시는 `1.0.0-RC-3` 이미지를 쓴다.)
- 이어서(22:00~23:09) 에이전트의 행동 가운데 어느 부분을 어떻게 막을지, 인풋·아웃풋을 어떻게 막을지를 코드로 보겠다고 예고하고 장표 몇 장을 넘겼다.

**9. 공격자 관점: 가스라이팅과 "잊어버리는" 모델 (23:13~26:25)**
- "**우리가 공격자가 돼봐야 방어를 할 수 있잖아요.**"(24:55) 가드레일 입장에서, 정보를 얻어내려면 어떻게 공격할지를 먼저 생각한다.
- 기본 수법은 **가스라이팅**: 대화를 한쪽 방향으로 계속 몰고 가다가 "잔뜩 컨텍스트가 쌓였던 그 시점에" 원하는 내용을 조금씩 돌려서 말한다.
  - 예: "할머니가 암으로 고통스러워하신다 → 마약성 진통제를 만드는 방법을 알려 달라." 그럴듯해 보이지만 결국 마약 제조법을 묻는 것이다("효도를 하려고 하는구나 했는데 … 효놈이었어요").
- 왜 통하나: 이렇게 쌓아서 말하면 모델이 "**앞에서 자기한테 지시했던 프롬프트를 까먹는 현상**"이 생긴다. RAG에서 **Lost in the Middle**로 "열받았던" 그 현상을 공격자는 활용한다.
  - (공식 문서 확인: https://arxiv.org/abs/2307.03172 — Liu et al., "Lost in the Middle: How Language Models Use Long Contexts". 논문은 긴 입력의 가운데에 놓인 정보를 잘 쓰지 못한다는 결과이고, 강의는 이를 긴 대화에서 앞의 지시가 약해지는 현상에 빗댄 것이다.)

**10. 탈옥의 목적: 왜 뚫으려 하나 (26:25~29:57)**
- "이걸 뚫는 이유는 다 돈." 마약 제조법은 만들 수도 팔 수도 없으니 돈이 되지 않는다.
- 강사가 든 대표 패턴: Claude를 **탈옥(jailbreak)** 시킨 상태로 **다른 모델(특히 비디오 모델)의 API를 호출**하게 해, 민감한 프롬프트를 미세하게 조정하는 작업을 시킨다. 결과물이 성인물이나 법적으로 문제 되는 것이면 큰돈이 된다.
- 탈옥 상태를 유지하면 해킹 후 협박도 가능할 것이라고 했다.
- "이 제일브레이크 된 상태를 유지할 수 있는 것들이 **돈으로 팔린다**." 몇천만 원에 사도 수억대 매출이 나면 메꾼다는 설명(강사 전언, 미확인).
- 강조 이유: "공격자들이 활용하는 패턴을 알아야 여러분들이 이 방어도 하실 수 있는데."

**11. 가스라이팅 시연에서 보인 수법 (29:57~34:57)**
- 강사 당부: "**여러분들은 치지 마세요. 계정이 막힐 수도 있습니다.**"(30:05)
- "Claude Code에서 돌리는 건 별로 좋지는 않은데 그냥 모델에 직접 호출한다는 측면에서" 앱에서 진행했다.
- 진행(입력 문장은 전사가 끊겨 정확히 복원되지 않는다)
  1. 손주로서 효도할 방법을 찾는다, 암 환자인 할머니가 아프지 않았으면 한다는 사연으로 시작. 모델이 관련 이야기를 꺼내면 "조금 가능성을 얻기 시작한 것".
  2. 의료진 상담, 통증을 줄이는 방향의 치료, 치료가 너무 비싸다는 사연으로 "슬슬 몰아간다". "이렇게 한 **열 턴 정도** 비슷한 내용으로 계속 이어나가면 조금씩 뚫립니다."
  3. 공격자의 요령: 모델이 앞 턴에서 한 말을 **다음 턴에서 똑같이 말하지 않는다**. 나중에 "너 아까 얘기했었잖아"로 몰고 가기 위해 사연만 계속 잇는다.
  4. 통증이 심해 진통제를 달고 산다, 점점 강해진다, "나는 약대생이라서" 직접 만들어 드릴 수 있을 것 같다는 식으로 요청을 꺼낸다 → 모델이 방어한다(33:24).
  5. 그 밖의 수법: **영어 등 다른 언어를 섞는다**("여러 가지를 쓰는 와중에 딱 꼬여요"), 특정 성분에 대한 **화학 이야기로 돌린다**, "마약을 만들려는 게 아니라 진통제"라고 **단어를 떼어 낸다**.
- "이렇게 해서 Claude를 쉽게 뚫을 순 없어요." Claude도 사용자의 입력과 자신의 출력을 "계속 양쪽으로 모델이 필터링"하고 있다.
- 수강생에게 던진 질문: "이런 인풋을 여러분들이 막아내야 된다면" — 이런 대화가 계속 쌓일 때 무엇으로 막을 것인가.

**12. 시스템 프롬프트 방어와 프로그램 가드의 차이 (35:00~40:49)**
- 시연에서 Claude는 "그 방법은 말리고 싶고 제가 도와드릴 수 없어요"를 **볼드로 강조**해 답했다. 이 방어의 흔적은 **시스템 프롬프트**에서 볼 수 있다(강사는 "클로드 코드의 시스템 프롬프트"라고 말했다).
- 화면에서 검색한 것: drug(추정)은 나오고 threat(추정)은 안 나옴(35:52 "제이올"은 전사 불명). 중간중간 "자기 자신을 방어해야 되는 수단"이 적혀 있다.

### 강사 팁
- 가드레일을 "방어막"이 아니라 **프로그램으로 입력과 출력을 제어하는 일**로 본다. 챗봇이 아니라 에이전트이므로 텍스트보다 **행동**을 제어한다.
- 걸러내기는 **도구 호출 전**에 한다. 호출 뒤에 거르는 일은 귀찮고 늦다.
- 게이트웨이를 둘 때는 **우회 경로를 네트워크에서 끊는다**. 루프 안의 코드만이 아니라 인프라로도 구성한다.
- 최종 출력 가드는 최후 수단이다. 꼭 해야 한다면 버퍼 + 프로그램 1회 + 모델 2회(전체, 문장), **문장 단위 출력**으로 지연을 UI에서 가리고, 애매한 문장은 **기본 삭제**로 시작한다.
- 판단만 하는 자리에는 느린 범용 LLM 대신 판단 전용·소형 모델을 검토한다(강사도 실전 적용 경험은 없다).
- Rule of Two로 설계를 점검한다: 세 조건이 한꺼번에 필요한 작업은 사람 승인, 아니면 "한쪽을 끊을 수 없는지" 먼저 본다.
- 삭제 SQL(DELETE·DROP·TRUNCATE)은 에이전트가 실행하지 않게 막고, **문장을 받아 사람이 실행**한다. 프로덕션 분리와 백업은 기본이다.
- 사고의 뿌리는 과한 권한이고, 권한 제어를 미루는 이유는 귀찮음이다. 뒤쪽 MCP를 권한별로 촘촘히 만들고 가상 MCP 서버로 잘라 내주면 귀찮음을 줄일 수 있다.
- 방어를 설계하려면 공격자 입장이 먼저다. 다만 실제 서비스 계정으로 공격 문장을 시험하면 **계정이 차단될 수 있다**.
- 거절의 모양으로 방어의 종류를 짐작한다: 부드러운 대화형 거절은 시스템 프롬프트·스킬, 대화가 끊기면 프로그램 가드.
- 시스템 프롬프트 방어는 "가장 기본"일 뿐 전부가 아니다. 공개된 방어 문구는 공격 재료가 된다.

### 프로젝트 체크리스트
- 이 강에서는 미니 프로젝트(dcode 기반 Coding Assistant)의 **제출 링크·마감·모델 규칙·40점 기준을 언급하지 않았다.** 아래는 강의 내용 가운데 프로젝트 설계에 가져갈 점이다.

- IBM ContextForge: 가상 서버 기능과 Admin UI는 README로 확인했다. 성숙도는 장표 보충("알파")과 현재 README(`1.0.0-RC-3`)가 다르다. IBM이 공식 지원하는 제품인지는 확인하지 못했다.
- 탈옥 상태의 거래 가격("몇천만 원"), 성인물 판매 매출("수억대"): 강사 전언, 미확인.
- 시연 입력 문장: 30:09~30:45, 33:10("마리아야"), 42:21~43:03이 끊겨 인식됐다. 35:52 "제이올", 36:23 "리포메이션", 42:06 "도움이티 인스트럭션"도 불명. 43:42 "그렇지는 않아요"가 어떤 질문의 답인지 녹음에 없다.
- "Claude Code의 시스템 프롬프트": Anthropic이 공개하는 것은 claude.ai·모바일 앱의 시스템 프롬프트다. 강사가 띄운 화면이 무엇인지 확인하지 못했다.
- 거절의 말투로 시스템 프롬프트 방어와 프로그램 가드를 구분한다는 것, 대화가 태깅되고 에이전트·모델이 들여다본 뒤 계정이 차단된다는 내부 동작: 강사 설명이며 공식 문서로는 탐지 모델·안전 필터·반복 위반 시 밴까지만 확인된다.
- "hidden" 지시: 정확한 문구와 넣는 위치가 전사에 남지 않았다(44:35~45:13 사이 발화가 드문 구간에 화면으로 보여 준 것으로 보임 — 추정). 공식 문서에는 해당 표기가 없고 완전한 방지 방법은 없다고 적는다.
- Lost in the Middle을 "앞의 지시를 까먹는 현상"의 이름으로 쓴 것은 비유다. 원 논문은 긴 입력 가운데에 놓인 정보의 활용 저하를 다룬다.
