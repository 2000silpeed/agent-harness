## 하루 요약

- **통제 대상은 셋이다.** 사용자 입력, AI 출력, 내부 동작(도구 실행). 내부 동작은 최소 권한과 훅으로, 입출력은 가드로 다룬다. 힘은 입력과 도구 실행 직전에 싣고, 최종 출력 가드는 최후 수단이다.
- **"하지 마라"와 "할 수 없다"는 다르다.** 프롬프트의 금지 문장은 지침이지 실행 경계가 아니다. 사고의 대부분은 과한 권한에서 나온다.
- **모델은 위험 신호를 내고 코드가 실행을 강제한다.** 판정 주체는 코드(권한·범위·형식·한도·순서), 가벼운 범용 LLM(의미·문맥), Decision 모델(정해진 질문에 확률)이고, 싼 것부터 건다: 코드 → Decision → 애매한 것만 LLM → 사람. 판정에 실패하면 통과가 아니라 사람 검토다.
- **Rule of Two.** 비신뢰 입력, 민감 데이터, 상태 변경·외부 통신이 한 실행에 모이면 자율로 두지 않는다. 다리 하나를 끊거나 사람 승인을 받는다.
- **도구 실행 전 차단은 프로그램을 끝내지 않는다.** 사유를 붙여 모델에게 돌려주고, 몰래 고쳐 실행하지 않는다. 우회 시도는 허용하지 않는다. 호출 예산을 건다.
- **검사는 항상 지나가는 길에 둔다.** 서브에이전트는 메인이 부를지 말지 정하므로 강제 검사 자리가 아니다. 부모 미들웨어에만 둔 검사는 서브에이전트 경로에서 빠진다.
- **게이트가 못 보는 길이 있다.** 상담원(사용자) 메시지, 주모델 공급자로 나가는 값, 최종 답변(거절된 일을 "처리했다"고 하는 보고), 세션을 넘는 메모. 길마다 같은 판정 주체를 건다.
- **승인은 대상에 묶는다.** 도구·대상·금액·1회. 승인 번호나 "승인받았다"는 문구만 믿지 않는다. 검토 판정에서만 실제로 멈추고 재개한다.
- **샌드박스는 뚫릴 수 있다고 전제한다.** 에이전트가 읽을 수 있는 파일의 키는 유출로 본다. 키는 실행 환경 밖에 두고 요청 단계에서 채운다.
- **가드도 잰다.** 놓친 비율과 과잉 차단 비율을 따로, 검토로 보낸 양과 비용을 함께. 문턱값은 라벨로 고르고 holdout은 한 번만 연다.

- `Day08_new`의 사례·라벨·기록 재생 결과는 측정치가 아니다. 탐지율로 인용하지 않는다.
