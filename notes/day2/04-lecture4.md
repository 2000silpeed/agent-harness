## 2일차 4강 — 재귀적 자기 개선(RSI)과 소프트웨어 팩토리, 그리고 Claude Code·실습 환경 세팅

> 장표 제목: "스스로 개선하는 개발 환경, 실습으로 연결하기" (SDS AX Advanced · 2026-11-03 · 44:07)

### 핵심 요약 (3~5줄)
- 전날(11월 2일) 올라온 글(추가 학습 없이 가중치를 코드로 수정해 수학 문제를 풀게 한 사례)을 계기로 **재귀적 자기 개선(RSI)** 을 소개: AI가 스스로 코드와 모델 학습을 돌려 자기 세대보다 나은 후속 모델을 만드는 과정.
- 프론티어 랩 개발자들은 "내가 없어도 코드가 짜이는" 환경 개선에 집중 — 개발자의 초점이 코드에서 **에이전트가 일할 환경**으로 이동.
- 스탠포드 'Modern Software Developer' 과정은 코딩 언어 수업을 없애고 에이전트 내부·컨텍스트·스킬·보안·백그라운드 에이전트·AI 네이티브 팀을 다루며, 10주차는 **소프트웨어 팩토리**(셀프 러닝·셀프 임프루빙, 개발부터 운영까지 공장형 구조).
- 실습: Claude 로그인·플랜/사용량 확인 → 데스크톱 앱 설치 → Claude Code를 **WSL + 작업 폴더**로 설정(Sonnet, effort 중간) → 수업 저장소 클론 → "환경 설정 해줘" → VS Code에서 노트북 첫 셀 실행으로 점검.
- API 키는 강사가 발급해 전달 예정, 다음은 LangGraph 챗봇 → 딥 에이전트.

### 주요 개념 (개념별 설명, 강사가 강조한 이유 포함)
- **추가 학습 없는 성능 향상**: GPT-6 아스트라 모델이 Qwen 0.5B·0.8B 류 모델의 특정 웨이트를 코드로 수정해 못 풀던 수학 문제를 풀게 했다는 글. 결과는 작아 보여도 "모델을 추가 학습할 필요가 있을까"라는 고민의 실마리가 풀리는 것으로 봄. 학습 없이 "지식의 주입"이 가능하지 않을까라는 관점에서 눈에 띈다고 함.
- **재귀적 자기 개선(RSI)**: 스스로 자기 지능인 코드와 모델 학습을 돌려 더 나은 후속 모델을 만드는 과정. 강사는 "AGI라고 부르는 그것의 지금 현실적인 모습"으로 보며, 미국 프론티어 랩들이 이를 위해 엄청 노력 중이라고 강조.
- **개발 환경에서의 자기 개선**: RSI는 모델에만 국한되지 않음. 프론티어 랩 개발자들은 작업 지시·코드 작성은 에이전트가 하고 개발자는 "그 환경만 개선"하는 방향으로 연습 중. 트위터 등에서 일주일에 PR 2000개를 낸다는 이야기도 있으나 공개된 것은 없어 "반쯤" 믿는 수준. 많은 토큰이 든다는 점도 언급. "사람은 어차피 점점점점 코드를 읽지 않기 때문에" 이 방향으로 간다고 설명.
- **스탠포드 Modern Software Developer 커리큘럼**: 코딩 언어가 "아예 없다". 코딩 에이전트 인터널스(내부 구성), 컨텍스트 엔지니어링(컨텍스트 제어), 스킬(조각 지식으로서 컨텍스트 관점에서 다룸, 2주차 내용과 연결), 에이전트 커스터마이즈, 에이전트 레디 코드베이스, 에이전트와의 코드리뷰, 보안("너무너무 중요"), 백그라운드 에이전트, 빌딩 AI 네이티브 팀(개발자+PM, 강사는 "약간 허황된 주제"라고 평가), 10주차 소프트웨어 팩토리. 올해 초 처음 나왔고 상반기·하반기에 갱신(강사 기억으로 원래 파이썬이 있었음). 신입사원 교육이 어떻게 바뀌는지 보여주기에 소개.
- **소프트웨어 팩토리**: 소프트웨어를 건설에 비유 → 조립식이면 공장형으로 돌리자는 발상. 개발부터 운영까지 공장형 구조 구축. 우버 같은 회사가 구현했지만 아직 작은 부분일 것으로 추측. 핵심어는 **셀프 러닝·셀프 임프루빙**(RSI의 실제 구현 형태). 개발자 없는 작은 회사들이 "만들어 달라"고 요청하지만 쉽지 않다는 입장. 다만 "개떡같이 말한 요구사항도 찰떡같이 코드로 바꿔주는" 부분부터 점차 점령될 것으로 봄.
- **백그라운드 에이전트**: 계속 작업이 돌아가게 하는 에이전트. 오늘 다룰 예정. VS Code 익스텐션에서는 볼 수 없음.
- **빨라질수록 일이 늘어나는 역설**: Claude Code 도입으로 놀고먹을 줄 알았지만 결과물을 더 빨리 내야 하고, 방향이 빨리 바뀌어 다시 만들어야 함. 해결책은 "잘 모르겠다", 적응해야 한다고 언급.
- **WSL**: 윈도우에서 리눅스 환경을 가상으로 띄우는 방식. Claude가 윈도우에서 잘 동작하지 않아 매끄러운 환경을 위해 선택. 무거워서 컴퓨터가 시끄러워질 수 있음.
- **권한 무시(모든 권한 우회) 모드**: "굉장히 위험한 모드". 설정 가능 여부만 확인하고 다시 "자동"으로 되돌림(상시 사용 지시 아님).
- **UV와 .venv**: 환경 설정 후 UV가 루트 폴더에 `.venv` 가상 환경을 만들고, 노트북의 파이썬 환경으로 선택.
- **딥 에이전트**: LangGraph 챗봇을 기반으로 만들어진 에이전트 구성. 챗봇을 먼저 보는 이유는 "한 땀 한 땀 호출할 때 이런 구성으로 호출된다"를 보고 넘어가기 위해서.

### 실습/데모 내용 (명령어, 파일 구조, 프롬프트, 코드 조각 등 원문 그대로 보존)
1. **Claude 계정 확인**
   - 네이버 웍스 계정 메일함의 Claude 초대 메일로 로그인.
   - 왼쪽 하단 플랜명 확인(아마 "맥스"), 또는 **사용량** 메뉴 확인 → 0%면 정상(전날 저녁 생성 계정).
   - 설정 하단 "API 키 받기" 메뉴 확인 → 일부 계정에 보이지 않아(팀 플랜) 강사가 확인 후 전달하기로 함.
2. **사용 방식 선택**
   - 추천: CLI. CLI가 불편하면 Claude 앱의 Code 메뉴. **VS Code 익스텐션은 비추천**(세션 관리 어려움, 탭 여러 개, 백그라운드 에이전트 못 봄).
   - 추천 경로: 앱을 통해 CLI 설치. 설정 → "앱 및 확장 프로그램 다운로드" → 데스크톱 → 윈도우용 다운로드 → 다시 로그인.
   - 앱의 두 메뉴: 말풍선(채팅+코워크) 모드 / 코드(Claude Code). 수업은 코드 메뉴 위주.
3. **Claude Code 환경 설정(왼쪽 아래)**
   - 실행 위치: 클라우드가 아닌 로컬 → 수강생 PC에서는 **WSL**로 정정(26:10 이후). 새 대화 세션 열고 WSL 선택.
   - 작업 폴더: 전날 세팅한 폴더(UV가 설치된 폴더 / 클론받은 레포 폴더)를 "폴더 열기"로 지정.
   - 모델: Sonnet(Sonnet 5.5), effort(노력): 중간.
   - 권한: "자동" 클릭 → "권한 무시" 활성 여부 확인 → "모든 권한을 우회할까요?"에 무시 눌러 확인만 → 다시 "자동"으로 복귀.
   - 테스트 메시지: `야`, `하이`, `잘 되냐` 등.
   - (선택) 프롬프트: `클로드 코드 CLI 설치해 줘` (대소문자 무관)
4. **수업 자료 저장소 클론**
   - 전날 자료는 `git clone`으로 "랭그래프 V1 튜토리얼" 저장소를 받는 방식이었으나 대부분 미실시 상태였음.
   - 새 저장소: 강사 개인 GitHub(클래스 주소, 정확한 URL은 전사 불명확). Day 1~8일차 자료 포함, "뉴"가 붙은 폴더 존재.
   - 동시에 비슷한 IP로 Git 접속 시 차단되는 경우가 가끔 있음.
5. **환경 설정 프롬프트** (클론한 폴더로 이동 후)
   - `환경 설정 해줘`
   - `파이썬 그리고 노트북. 주피터 노트북 환경 설정 해줘` — "이거면 충분합니다." 모델은 Sonnet 5.5 미디움 유지.
   - UV 설치 등 승인 요청은 모두 OK. "설치하고 나서 뭘 실행할까요?"까지 물어보면 세팅 완료.
6. **VS Code 및 노트북 점검**
   - 해당 경로로 이동 후 `code .` 로 VS Code 실행(터미널 또는 Claude에게 시켜도 됨).
   - Day 01 → 파트1/챕터1 → 랭그래프 인트로덕션 노트북 → 첫 번째 셀 실행.
   - 파이썬 환경 선택: 루트 폴더의 `.venv` 선택.
   - 첫 셀이 초록색으로 실행되고 `TypedDict` 출력되는지만 확인("그래프 생성하기"는 오늘 크게 실행하지 않음).
7. **다음 준비**: 챕터2 에이전트 폴더의 두 번째 파일 "챗봇" 노트북 → API 키 필요하므로 실행 가능 여부만 확인. 15분 휴식 후 2시 재개.

### 강사 팁·주의사항
- "추천드리지 않는 거 VS 코드 익스텐션으로는 하지 마세요." — 세션 관리·탭·백그라운드 에이전트 문제.
- 실행 위치를 "이 컴퓨터"로 명시적으로 선택(기본값이 클라우드인 경우가 있음). 수강생 윈도우 PC에서는 WSL.
- 권한 무시(우회) 모드는 굉장히 위험 — 확인만 하고 자동으로 되돌릴 것.
- WSL은 무거워 컴퓨터가 시끄러워질 수 있음.
- "모든 세팅이 가장 어렵습니다." 세팅이 안 돼 있으면 세팅도 Claude에게 해달라고 하면 됨. 다만 파이썬 환경 선택 정도는 손으로 해봐도 괜찮음.
- 강의 자료를 매일 갈아엎으므로 매일 다시 클론받을 것. 수업 종료 즈음 저장소는 닫힘.
- 설치했다는 설명보다 실제 응답과 셀 실행 결과로 준비 완료를 확인(장표).
- 빨라지면 일이 줄기보다 늘 수 있다는 점을 염두.
