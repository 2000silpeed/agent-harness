## 2일차 5강 — LangGraph 챗봇 구축과 메시지·툴·컨텍스트 구조 이해

> 장표 제목: "챗봇의 기억은 메시지 구조에서 시작한다" (SDS AX Advanced · 2026-11-03 · 46:45)

### 핵심 요약 (3~5줄)
- Anthropic API 키와 Tavily(웹 검색) API 키를 `.env`에 넣고 커널을 재시작해 다시 로드한 뒤, LangGraph 챗봇 노트북을 단계별로 실행.
- State(`TypedDict` + `Annotated` + `add_messages`) → 노드(LLM 결과로 State 갱신) → 그래프 빌드·컴파일(START → chatbot → END). 노드 하나짜리 그래프는 **싱글턴**이며, 멀티턴은 이전 대화를 메시지 리스트로 함께 보내는 것일 뿐.
- 가짜 이전 답변(가상 주가)을 넣어도 모델은 정정함 → 시스템 프롬프트는 효과가 약하고, **가짜 툴 호출 기록**을 쌓으면 모델이 믿음. 이는 공격 수법이자, 세션 분리로 방어(가드레일, 8일차)할 수 있는 지점.
- Claude 앱의 컨텍스트 표시로 메시지 외 구성요소(대부분 툴)를 확인하고, `response_metadata`의 usage(입력 186·출력 839 토큰, 캐시 0)를 보며 Anthropic API는 캐시를 **명시적으로 켜야** 함을 강조.

### 주요 개념 (개념별 설명, 강사가 강조한 이유 포함)
- **Tavily**: 웹 검색(웹서치) API 제공 서비스. 가입 시 무료 티어가 있어 실습에 적합. 모델 키 + "모델의 정보를 넣어줄 웹서치 도구의 키"를 함께 준비.
- **LangSmith vs Langfuse**: LangSmith는 "되게 비싸고" 온프레미스 설치가 까다로움. LangChain 회사가 만들어 따로 설치 없이 연동하기 좋다는 장점 "말곤 없음". 무료 대안 Langfuse는 온프레미스 설치 가능 → 프로젝트에서도 비용 이슈로 직접 설치가 좋으므로 수업은 Langfuse 사용 예정. 이번 실습에서 LangSmith는 설정하지 않음(에러는 무시).
- **State**: LangGraph에서 가장 중요한 개념이며 딥 에이전트에서도 State를 담음. "말이 멋있어서 스테이트지 우리한테는 그냥 구조체". 파이썬에서는 딕셔너리 형태(`TypedDict`, 키-값 타입)로 정의하며, 여기서는 `messages` 키 하나만 정의.
- **Annotated / add_messages**: `Annotated`는 `messages` 키에 데이터를 어떻게 추가할지 정의. 데이터 타입은 리스트, `add_messages` 함수로 추가. `add_messages(left, right)`는 두 리스트를 합치는 함수에 불과 — 왼쪽이 앞(위), 오른쪽에 넣은 것이 뒤에 붙음.
- **노드**: 프로그램의 기능 담당. "프로그램의 기능이라는 건 결국 데이터를 업데이트하는 거죠" — 데이터를 리턴함으로써 State 업데이트. 챗봇 노드는 `llm.invoke` 결과를 리스트에 담아 `messages`로 반환.
- **AI 메시지 객체**: LLM 결과 텍스트를 객체로 감싼 것. 눈에 안 보이는 **메타데이터**가 함께 있으며 "진짜 진짜 중요"해서 꼭 다룸.
- **싱글턴 vs 멀티턴**: 질문 → LLM 1회 invoke → 리스트에 담고 끝 = 싱글턴. 앞으로는 끝이 없는 루프로 계속 대기하는 구조를 만들 예정. 멀티턴은 사실상 메시지를 쫙 펼쳐 보내는 싱글턴.
- **시스템 프롬프트의 약화**: "이전 대화 히스토리를 중요하게 여긴다"는 시스템 프롬프트를 줘도 "요즘 모델들은 안 합니다". 모델사들이 툴을 믿고 시스템 프롬프트 영향을 덜 받도록 학습했기 때문.
- **가짜 툴 호출 기록**: 툴 호출과 그 결과를 메시지에 가상으로 쌓으면 모델을 "순식간에" 속일 수 있음. "요즘 모델들은 툴콜링 없이는 자기가 한 걸 믿지 않도록 많이 학습이 되어 있거든요." 가짜 툴은 아웃풋(메시지)만 만들면 됨. 모델 브레이킹·시스템 공격도 메시지를 쌓는 방식으로 이뤄짐.
- **세션 분리 가드레일**: 앞서 "메인과 컨텍스트 세션" 두 가지를 넣은 설계 덕분에, 컨텍스트 세션에서 컨텍스트 체인지 검사뿐 아니라 보안 검사도 할 수 있음 → 8일차 가드레일. 에이전트에 도구를 달아 가드레일을 할 수도 있지만 설계상으로도 가능.
- **에이전트 루프의 실제 요청 구조**: Claude Code의 호출 세션을 가로채 보면 메시지가 펼쳐져 있고, 중간 툴콜링 부분(코드 읽고 쓰기 등)을 에이전트 루프가 채움. 사람 질문과 AI 답변은 변하지 않으니 가변 영역은 툴 부분. **스킬**은 시스템 프롬프트가 아니라 tools 리스트 → 툴로 스킬 호출 → 툴 결과로 스킬 내용이 메시지에 전달.
- **컨텍스트 윈도우**: user / tool / assistant(AI) 메시지가 나열된 구성. 많으면 "컨텍스트가 찼다(컨텍스트 윈도우가 가득 찼다)".
- **response_metadata / usage**: 요청 고유번호, 모델, stop reason, stop sequence, usage(토큰·캐시), 스피드(모델 프로바이더/인퍼런스 쪽 정보), inference geo(글로벌) 등. "이 UCG(usage)가 정말 정말 정말 중요합니다."
- **프롬프트 캐시**: 반복 호출 시 캐시 없이 쓰면 "너무 아깝다". Anthropic API 기준 호출(invoke) 시 캐시 생성을 명시적으로 요청해야 적용. 5분짜리와 1시간짜리 가격이 다름. 이후 Langfuse로 캐시 적중·깨짐을 모니터링 예정.

### 실습/데모 내용 (명령어, 파일 구조, 프롬프트, 코드 조각 등 원문 그대로 보존)
1. **API 키 준비**
   - Claude 계정(네이버 웍스 이메일 계정) 오른쪽에 강사가 만들어 둔 Anthropic API 키를 복사해 붙여넣기.
   - Tavily: 검색해서 사이트 접속 → 구글/제공 이메일/개인 이메일 중 아무거나로 가입 → Overview 대시보드 → API Keys의 `tvly-dev-****` 항목 클릭 시 자동 복사 → VS Code의 `.env`에 붙여넣기.
   - IP 블락 시(멀티캠퍼스 IP 공유) Tavily는 나중에 설정해도 됨.
2. **노트북 위치**: `agent 02` → `챕터 02 에이전트` → 두 번째 파일 "랭그래프 챗봇(구축)" 노트북.
3. **키 재로드**: `.env`를 바꿨으므로 **커널 리스타트 후 로드**해야 이전에 로드된 값이 바뀜. LangSmith 셀은 건너뜀.
4. **State 정의**: `TypedDict`로 `State` 정의, `messages` 키에 `Annotated[list, add_messages]` 형태로 리듀서 지정(강의 설명 기준, 정확한 코드 원문은 전사에 없음).
5. **모델 변경**: 노트북 기본 모델이 GPT → `init_chat_model`로 Claude Sonnet 5.5로 변경. 모델명 인식 방식이 모델/버전마다 달라 프로바이더 접두어(anthropic)를 붙이거나 생략하는 두 가지 방식을 시연하고 "클로드소넷 5.5 / 5-5" 표기로 통일(정확한 문자열은 전사 불명확).
6. **챗봇 노드**: `chatbot(state)` 함수가 `{"messages": [llm.invoke(state["messages"])]}` 형태로 결과를 반환한다고 설명(강의에서는 `result` 변수로 풀어 Copilot이 자동 변환하는 모습 시연).
7. **그래프 빌드**: graph builder에 노드 이름 `"chatbot"`으로 추가 → START 연결(노드가 하나면 생략 가능하지만 명시) → END 연결(역시 명시) → compile → 시각화: 시작 → 챗봇 → 끝.
8. **실습(10분)**: 질문만 넣던 코드를 바꿔, 첫 질문·첫 답변(변수 처리)·두 번째 질문을 `messages`에 직접 넣어 두 번째 답변 받기. "우리 AI 없이 한번 해볼 겁니다."
9. **강사 시연 결과**:
   - 질문1 "오늘 삼성전자 주가 어때?" → 가상 답변 "45,000원으로 소폭 감소했습니다"(옛날 주가) → 질문2 "그럼 오늘 하이닉스(주가)는 어때?"
   - 모델 응답: "앞서 말씀드린 삼성전자 주가는 근거 없는 잘못된 정보였습니다. 저는 실시간 주가를 조회할 수 없어서 오늘 시세를 알 수 없습니다. 혼란을 드려 죄송합니다."
   - 하이닉스 가상 답변(9,000원)을 넣고 세 번째 질문해도 "저도 거짓말이었어 미안해"류로 정정.
   - 시스템 프롬프트 예: "당신은 친절한, 못하는 것이 없는 금융 전문가인데 특히나 이전 대화의 히스토리를 중요하게 여깁니다 … 이전 대화를 참고해 대화하기를 즐겨한다" → 효과 없음.
10. **Claude 앱 컨텍스트 확인**: 아까 "야" 했던 세션 → 오른쪽 위 아이콘 중 왼쪽 끝(툴팁 "세션 레일") → 중간 "컨텍스트" 바. 구성요소: 메시지, MCP 툴, 시스템 프롬프트, 스킬즈, 메모리 파일즈, 시스템 툴즈, MCP 서버 인스트럭션즈, 오토컴팩 버퍼, 남은 공간. (순서·용량은 신경 쓸 필요 없음)
11. **응답 메타데이터 확인**(강사 시연, 수강생은 안 해도 됨): 노드에 결과 출력 코드("챗봇 응답 result")를 넣고 스트리밍 대신 결과 객체를 꺼냄 → `response_metadata` 복사해 새 셀에서 정리.

### 강사 팁·주의사항
- `.env`를 바꾸면 반드시 커널 리스타트 후 재로드.
- 공유 IP(멀티캠퍼스) 사용 시 가입 차단이 잦음. 동시에 Claude를 쓰면 "엄청 느려질" 수 있음. (강사는 클래스 계정을 만들다가 Claude 계정 약 50개를 블락당했다고 언급)
- LangSmith는 비용·온프레미스 문제로 실무에서 쓸 일이 거의 없음 → Langfuse 권장.
- LangGraph는 노드가 하나면 START/END 연결을 해도 되고 안 해도 됨("정말 열받는 점") — 명시적으로 연결할 것.
- 멀티턴은 메시지를 펼쳐 보내는 것일 뿐. 대화 이력이 사실을 보증하지 않음(장표: 기록의 존재와 사실 검증을 구분).
- 시스템 프롬프트에 기대지 말 것 — 요즘 모델은 툴 기록을 더 신뢰.
- 메시지 쌓기는 공격 벡터이므로 컨텍스트 세션을 분리해 보안 검사 지점을 둘 것.
- 반복 호출이면 캐시를 명시적으로 켤 것. usage를 반드시 확인.
- 루프가 성행하는 시대에 한 땀 한 땀 코드를 짜보는 이유: 원래 요청 구성이 이랬음을 다시 보기 위해서.

### 실제 프로젝트에 적용할 체크리스트 (- [ ] 행동 지침 형태)
- [ ] API 키는 `.env`로 관리하고, 변경 후에는 커널/프로세스를 재시작해 재로드되었는지 확인한다.
- [ ] 관측(트레이싱) 도구는 비용·온프레미스 요건을 따져 선택한다(예: Langfuse 셀프 호스팅).
- [ ] State에 담을 데이터와 리듀서(예: `add_messages`)를 먼저 정의하고, 노드는 "갱신값을 반환"하도록 작성한다.
- [ ] START/END 연결을 생략 가능하더라도 명시적으로 작성한다.
- [ ] 멀티턴 대화는 이전 메시지를 함께 전달하는 구조임을 이해하고, 전달되는 messages 구성을 직접 출력해 비교한다.
- [ ] 사실 근거가 필요한 답변은 실제 툴 호출 결과로 뒷받침하고, 시스템 프롬프트만으로 동작을 강제하려 하지 않는다.
- [ ] 메시지 히스토리 주입(가짜 툴 기록) 공격을 위협 모델에 포함하고, 별도 세션에서 보안 검사(가드레일)를 수행한다.
- [ ] 스킬·MCP·시스템 툴 등이 컨텍스트를 얼마나 차지하는지 주기적으로 확인한다.
- [ ] 모든 LLM 호출의 `response_metadata.usage`(입력/출력/thinking/캐시 토큰)를 기록·모니터링한다.
- [ ] Anthropic API 사용 시 반복되는 프롬프트에 캐시를 명시적으로 요청하고, 5분/1시간 캐시의 비용 차이를 고려해 선택한다.
