---
name: criteria-check
description: design/00-brief.md의 인수 기준(과제 채점표, 고객 인수 조건, 완료 정의)을 항목별로 실제 증거와 함께 자가 점검하고 design/09-release.md 표와 README 테스트 케이스의 빈칸을 찾는다. 릴리스·제출 전, 중간 점검, "기준을 다 채웠나" 질문, P9 단계에서 사용.
---

<procedure>
1. `design/00-brief.md`의 "인수 기준 체크리스트"를 읽는다. 표가 없으면 완료 정의와 성공 지표를 항목으로 나눠 쓰고 사용자 확인을 받는다.
2. 항목마다 **직접 확인**한다. 문서에 "구현했다"고 적힌 것만으로는 인정하지 않는다.
   - 코드 기준(lint, 타입, docstring)은 명령을 실제로 돌리고 출력을 붙인다.
   - 기능 항목은 README 테스트 케이스를 실행하거나, 실행된 로그·파일을 연다.
3. 근거 수준을 단다: 실행 경로에서 확인 / 코드 정의만 / 문서만 / 추정. "실행 경로에서 확인"이 아니면 위험 항목으로 표시한다.
4. 표를 채운다: 항목 | 배점·중요도 | 증거 위치(파일:줄, 로그 경로, 명령 출력) | 근거 수준 | 자가 판정(충족/부분/미충족) | 보완할 것.
5. 다른 사람이 README만 보고 재현할 수 있어야 한다. README에 해당 항목의 테스트 케이스가 없으면 구현이 있어도 "부분"으로 본다.
6. 마지막에 보완 우선순위를 중요도 순으로 3개 제안한다. 판정을 부풀리지 않는다.
</procedure>
