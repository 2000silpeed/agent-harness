## 3일차 1강 — 에이전트 루프 복습에서 컨텍스트 격리까지

> 출처: 「3일차 1강 다시보기」(2026-11-04, 44:22, 자동 전사 whisper.cpp large-v3-turbo + 분석) · 「3일차 1강 장표」(15장, SDS AX Advanced)
> 다시보기 분석 제목: "멀티에이전트 아키텍처 도입: 에이전트 루프 복습과 컨텍스트 캐시·격리"

### 핵심 요약 (3~5줄)

- 어제(2일차) 내용을 복습: RAG는 **저장·검색·활용** 세 단계, 스킬은 이름+설명(what·when)으로 사용 여부를 판단하는 **조각 지식**, 딥 에이전트는 서브 에이전트와의 작업 전달을 파일 시스템으로 풀기 때문에 **파일 시스템 도구를 기본 제공**한다.
- 모델은 Auto-Regressive(출력이 다시 입력)라 **컨텍스트 윈도우 관리가 에이전트 개발의 핵심 관건**이다.
- **KV 캐시는 텍스트 매칭**이라 띄어쓰기 하나만 달라도 깨진다 → 날짜·시간처럼 **변하는 값은 시스템 프롬프트 뒤쪽**에 둔다.
- 100만 컨텍스트도 큰 코드베이스 탐색만으로 70% 이상 차고 80%를 넘으면 품질이 떨어진다 → 오늘의 모든 멀티에이전트 아키텍처 패턴은 **'컨텍스트 격리'** 한 가지 개념에서 출발한다.

### 주요 개념 (개념별 설명, 강사가 강조한 이유 포함)

**1. RAG = 저장 · 검색 · 활용** (11:20~15:34)
- 저장: 벡터DB, 또는 파일 시스템에 **계층형**으로 저장 + **인덱스** 문서화. 인덱스는 "최대한 자세히 촘촘하게" 쓰되 "문서만큼 작성하면 안 된다" — 적당히 잘 쓰는 법은 실습에서 계속 다룸.
- 검색: 기술 자체는 거의 바뀌지 않음. 전체 읽기 vs 발췌(부분) 읽기. 발췌가 가장 좋지만 못 하는 경우가 꽤 있음.
- 활용: 검색된 내용과 지식(스킬)을 결합해 답하게 함.
- 강조 이유: 세 단계로 나누면 어디를 설계해야 하는지 보인다. 특히 "이 문서가 어떤 내용을 다루고, 어느 부분을 얼만큼 읽어야 하나"를 설계하는 것이 **가장 어려웠다**고 함.

**2. 스킬 = 조각(화된) 지식** (14:41~15:13)
- 이름과 설명만 보고 쓸지 말지 결정. 설명에는 **무엇(what)**과 **언제(when)**가 들어가야 함. 본문은 필요할 때 나중에 읽음(컨텍스트를 아끼는 조각화).

**3. 딥 에이전트가 파일 시스템 도구를 기본 제공하는 이유** (15:36~19:57)
- 도구 예: `ls`, `list`, `grep`(전사상 "grab"), `read`, `write` 등. 딥 에이전트는 이런 도구가 9개.
- 이유: "대부분의 작업을 파일 시스템 기반으로 해야 되기 때문입니다." 서브 에이전트 생성 → 작업 전달 → 결과를 메인에 다시 전달하는 '전달' 방식이 핵심 고민.
- 프로세스 간 전달은 ①직접 통신(IPC) ②매개 이용 두 가지. 매개가 관리가 더 쉬움. 멀티에이전트에서는 프로세스를 너무 많이 띄우므로(메인과의 과다 소통, 완료 여부 제어 등) **IPC는 별로 고려하지 않음** → 파일 시스템 기반으로 출발.
- 딥 에이전트뿐 아니라 대부분의 에이전트 시스템이 서브 에이전트 작업을 파일 시스템 기반으로 전달받는다고 함.

**4. 왜 LangChain/LangGraph(딥 에이전트)인가, 그리고 Pi Agent** (20:01~24:59)
- 선택 이유: **가장 예제(레퍼런스)가 많아서**. Claude가 언어 이동을 도와주므로 기술 하나를 특정하는 건 큰 의미가 없고, 자료를 가장 많이 얻을 수 있는 라이브러리를 고르는 게 중요.
- 비교 대상으로 Spring AI, Pi Agent, Pydantic AI 언급("검색하면 20개쯤 나옵니다").
- 단점: **버전 변화가 극심**. 1년 전 블로그 자료는 지금과 완전히 다름.
- Pi Agent: 기본 툴 **4개**(딥 에이전트는 9개). 루프 코드도 훨씬 작음. 수업용으로는 기능이 부족하지만 **개인이 나만의 에이전트를 만들 때 좋은 베이스라인**. 강사가 요즘 가장 기본으로 쓰는 에이전트.
- 확장 사례: omp(Oh My Pi) — 외국 개발자가 공개한 Pi 기반 코딩 에이전트. 도구 31개로 확장, 모델 제공사 60개 이상, 8만 라인 이상 Rust 기반 코어(수치는 전사 불확실).
- 미들웨어 개념(어제 내용)은 다른 루프에서 어떻게 넣고 관리하는지, 직접 만들면 어떻게 할지로 확장해서 생각하면 똑같이 적용 가능.

**5. Auto-Regressive와 컨텍스트 윈도우** (25:07~27:03)
- 모델 특성: Generative Pre-Train + Auto-Regressive. 출력 토큰이 다시 입력으로 들어가 연산이 누적됨.
- 에이전트 개발 = ①도구를 얼마나 적절히 줄까(세부 기술은 보편화되어 크게 중요하지 않아짐) ②**컨텍스트를 어떻게 적재적소에 넣을까**. "이제는 대부분 에이전트 개발자들의 핵심 관건입니다."

**6. KV 캐시는 텍스트 매칭** (27:19~30:26)
- 모델 첫 레이어가 텍스트를 토큰화(벡터/수열)하고 마지막 레이어에서 역토큰화. 입력이 바뀌었다고 인식되는 순간 캐시가 깨짐.
- "토씨 하나 틀리면 안 됩니다. 띄어쓰기 하나까지도 틀리면 안 돼요."
- Claude Code는 알아서 캐싱하지만, 직접 만드는 에이전트는 캐시가 언제·얼마나 되는지, 깨지기 직전은 아닌지 계속 확인해야 함.

**7. 변하는 값은 시스템 프롬프트 뒤에** (30:33~34:21)
- 가장 흔한 실수: 시스템 프롬프트(앞부분)에 날짜·시간을 넣는 것. 예: `2026 1104093300` → 다음 요청에서 값이 바뀌어 캐시 전체가 깨짐.
- 날짜는 안 넣을 수 없으니(모델이 날짜를 알아야 함) **뒤로 넣는다**.
- 사례: Claude Code가 요청에 사용자 정보(이메일)를 넣는데, 이메일 처리 오류로 난수/잘못된 문자열이 앞에 끼면서 값이 계속 바뀌어 캐시가 깨진 일이 있었음.
- 로컬 LLM에서는 더더욱 중요하고, 아니어도 **비용 제어** 관점에서 중요. 컨텍스트를 버리는 것(=비용 감수)도 이유가 있어야 선택.

**8. 스킬·툴이 바뀔 때도 앞부분은 건드리지 않는다** (34:45~38:07)
- 스킬 본문은 나중에 읽으니 변경해도 상관없지만, 스킬 추가/설명 변경은 리스트 입장에서 데이터 변화.
- 강사 설명(리버스로 알게 된 내용, 추정): Claude는 처음 넣은 스킬 리스트를 변경하지 않고, 뒤쪽에 "스킬 8번 변경"처럼 변경 사실을 알림. "일단 캐시를 안 깨는 게 더 중요했어요." (요청 하나가 너무 비싸서)
- 다만 살짝 불안함이 있으므로, Claude Code·Codex 모두 스킬을 바꿀 때는 **세션 교체를 준비**하는 게 좋음.

**9. 대화 세션 vs LLM 호출 컨텍스트** (38:11~39:41)
- 대화 세션: 사용자–AI가 오가는 대화 창(Claude 창 하나).
- 호출 컨텍스트: 한 번의 LLM 요청에 담기는 구성(시스템 프롬프트·스킬·툴). LLM은 매 호출이 새로움.
- 강사 표기 규칙: 세로로 "시스템 프롬프트/스킬/툴"이면 호출 컨텍스트, "사용자/AI/사용자/AI"면 대화 세션.

**10. 멀티에이전트의 출발점: 컨텍스트 격리** (40:03~43:56)
- 100만 컨텍스트도 큰 코드베이스 탐색("이 프로젝트 뭐 하는 건지 알아봐")만으로 Claude가 70% 이상 사용, 잠깐 더 하면 80% 넘어 퀄리티 저하.
- "오늘의 모든 아키텍처 패턴들은 … 모두 다 한 가지 개념인데요. 컨텍스트 격리입니다."
- 비유: 2차 산업혁명 컨베이어 벨트의 **분업**, 전문가의 등장, 백엔드에서 DB 통신을 별도 스레드로 분리하는 것과 같다. "얘도 프로그램입니다."

### 강사 팁·주의사항

- 블로그·딥리서치 자료는 "무조건 **3개월 이내**의 자료만" 볼 것. 3개월 지난 자료는 "그냥 버리셔야 돼요." (모든 라이브러리 공통)
- 라이브러리 선택은 기술 우열보다 **예제·레퍼런스 양** 기준.
- 시스템 프롬프트에 날짜·시간·사용자 정보 등 변하는 값을 앞에 넣지 말 것. 이런 실수가 "비일비재".
- 직접 만든 에이전트는 캐시 적중 여부를 계속 확인할 것(Claude Code처럼 자동 처리되지 않음).
- 루프 실행 중 스킬·툴을 바꾸면 캐시/인식이 불안정할 수 있으니 세션 교체를 준비.
- 컨텍스트는 70~80% 이상 차면 품질이 떨어진다는 전제로 설계.
- (수업 외 소식) Anthropic IPO 페이지·S-1 보고서 공개, 티커 ANT(강사: "클로드 요금이 더 올라가겠구나"), Cerebras 칩(SRAM 대량 탑재, OpenAI와 협업 — GPT 5.3 Spark, $500 고객용 Ultra Fast 모델 서빙), 블랙프라이데이 모델 구독 할인 예상 — 강사는 작년 Z AI GLM 1년권을 약 230불에 샀고 지금은 1200불, "에이전트를 맘껏 돌려볼 수 있었다".
