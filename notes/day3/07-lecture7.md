## 3일차 7강 — Claude Code 꿀팁: 제어·절감·근거 (워크플로우 패널·출력 절감·캐시 관리·회고·인터뷰 스킬)

> 출처: 「3일차 7강 다시보기 (보정).html」(전사·분석), 「3일차 7강 장표 (보정).html」(9장) · 2026-11-04 · 강의 길이 49:02

### 핵심 요약 (3~5줄)
- 강사가 직접 만든 **CLI용 Claude 워크플로우 제어 패널**(mods로 띄움, DAG 그림·보드·DAG 노트·세션 기록)을 시연하며, 멀티 에이전트 작업을 **사람이 보고 개입하고 근거를 남기는 구조**가 "돌아가는 것"보다 중요하다고 강조했다. 회사 계정 말고 **개인 계정에서 먼저** 해보라고 당부.
- 비용 관리: 출력을 줄이는 라이브러리(**케이브맨**, **I have ADHD**), 상태줄(status line)에 **캐시 깨짐** 표시, 캐시가 깨지기 직전 지정 메시지를 보내 1시간 캐시 유지. 잘못 지시했으면 **기다리지 말고 멈추고 정정**.
- 일하는 방식: 코드를 잘 짜는 것보다 **에이전트를 어떻게 잘 시키느냐**가 중요. AD(오르카 → Herdr), Tailscale로 맥 미니·DGX 원격 제어, 계획은 Claude와 짜고 지시는 문서로 다른 에이전트에게.
- 활용법: 릴리즈노트를 Claude에게 묻기, **"내 대화 기록을 분석해줘"로 회고**, **/goal**(목표만 주고 방법은 맡김), **나를 인터뷰하는 스킬**(맷 퍼콕의 그릴링 스킬과 같은 취지).
- Q&A: 디자인 목업은 doop, PC·계정 간 이어가기는 완전하지 않음(캐시 깨짐), 바이너리 분석 도구 REA는 토큰 소모가 막대함(3시간에 주간 한도 약 40%).

### 주요 개념 (개념별 설명, 강사가 강조한 이유 포함)
- **워크플로우 패널 / mods**: Claude 런타임은 왼쪽, 부가 정보를 다루는 창은 오른쪽에 Claude Code의 **mods** 기능으로 띄운다("클로드 코드 mods"로 검색하면 문서가 나옴). 출발점은 "멀티 에이전트가 지금 뭘 하고 있는지가 가장 어렵고, 사람이 뭘 해야 하는지 전달받을 창구가 대화창뿐이면 엄청 불편하다"는 문제의식. 강사가 개발한 라이브러리로, CLI용이라 Claude 앱에서는 "못생기게" 보인다.
- **DAG (방향성 비순환 그래프)**: "우리가 행하는 모든 작업들은 사실상 엔드골이 정해져 있는 경우가 대부분" → 시작과 끝이 있는 작업을 DAG로 그려 보게 했다.
- **MCP와 스킬**: DAG 패널(껍데기)은 **MCP로 제어**하고, DAG 작업 요청을 받는 그 MCP는 **스킬로 호출**한다.
- **보드**: 서브 에이전트·메인 에이전트가 자유롭게 쓰는 게시판 겸 화이트보드. 순수하게 **사람에게 전달하는 용도** — 시간이 지나면 아무도 중간 출력을 안 보므로, 사람이 꼭 필요한 작업을 여기에 쓰게 했다. 텍스트만이 아니라 table, flow diagram 같은 그림 형태로도 제공.
- **세션 기록 (trajectories)**: 한 프로젝트에서 여러 작업을 동시에 돌리므로 세션 간 이동·히스토리 관리, 셀프 임프루빙을 위한 근거로 세션 전체를 기록. jev 모델의 모델 라우팅 판단("Opus가 작업해야 돼 / Sonnet이 작업해야 돼") 내용도 남긴다.
- **DAG 노트**: 작업이 한번 실행하면 2~3시간 돈다 → 지시 당시의 맥락을 **미래의 나에게** 남기는 작은 메모(어디에도 저장되지 않음). 목표·실행 범위는 DAG를 만들 때 LLM이 정리해 주지만 이해 못하는 경우가 많아서 메모를 따로 둔다.
- **판단 기록**: 판단·결정 내용을 기억하게끔 함.
- **출력 줄이기 (케이브맨 / I have ADHD)**: LLM 출력이 점점 보기 불편해지고, 여러 세션을 통제하느라 주저리주저리를 다 이해할 수 없어서. 케이브맨 = "원시인처럼 이야기해라", 토큰을 줄여 줌. I have ADHD도 같은 목적(강사는 케이브맨을 처음 검토했다가 안 쓰고, I have ADHD를 깔고 있음).
- **AD (Agent Development Environment)**: IDE 대신 요즘 부르는 말. 멀티 세션·멀티 에이전트 관리에 능숙하고 브라우저까지 내장. 오르카는 CPU를 너무 많이 먹어서 자원 소모가 적은 **Herdr**로 이사 준비 중(둘 다 터미널 기반, Herdr가 "조금 더 예쁘다").
- **캐시 깨짐 / 상태줄**: LLM API 응답을 확인해 캐시를 계속 측정하고 status line에 "캐시 깨짐" 출력. 캐시가 1시간인데 여러 세션(예: 4개)을 띄우면 1시간도 금방 지나가고, 서브 에이전트로 돌리면 확인할 길이 없어 자주 깨진다. 깨지기 직전(5분, 10분 전) 지정 메시지("작업 잘 진행하고 있어" 같은 쓸데없는 멘트)를 보내면 **캐시는 입력 기반으로 유지**되므로 비용을 제어할 수 있다. 예전엔 훅으로 했지만 지금은 훅 없이 여기서 알림.
- **개발자 역량의 변화**: "더 이상 코드를 잘 짠다라는 건 이제 나의 장점이 아니게 됐습니다. 왜냐면 얘보다 빨리 못 짜요." → 어떻게 잘 시킬지 고민, 시키는 사람이 컨텍스트 롯(context rot)에 빠지지 않게. IDE 테마·단축키를 꾸미던 것의 연장선.
- **박사급 인턴 마인드셋**: "우리에게는 A급 인턴 박사급 인턴이 있고… 얘한테 모든 걸 질문하자." 공식 문서는 안 보니 릴리즈노트도 Claude에게 물어본다.
- **대화 기록 회고**: 스크럼 후 회고처럼 에이전트 사용도 회고. 쓸데없는 멘트로 토큰 낭비, 작업 프로세스 오류 등을 발견. 기록은 홈 밑 `.claude` 폴더의 `history.jsonl`에 남음.
- **/goal**: 목표를 루프로 설정하는 기본 제공 슬래시 명령. 계획 후 실행 단계에서 너무 많이 물어보니 "목표에 도달하기 위한 온갖 방법은 그냥 네가 해". (그래도 아예 안 물어보는 건 아님)
- **인터뷰 / 그릴링 스킬**: "항상 얘가 하는 작업은 제 마음에 안 들거든요" → 내가 진짜 원하는 걸 촘촘히 물어봐 계획표에 넣으면 그대로 할 가능성이 높아진다. 품질은 크게 오르지만 오래 걸림.
- **Tailscale**: 맥북·맥 미니·DGX를 묶는 무료 VPN.

### 실습/데모 내용 (명령어, 파일 구조, 프롬프트, 코드 조각 등 원문 그대로 보존)
- **패널 구조 (장표)**: `Claude 런타임 (왼쪽)` → `DAG 패널 (오른쪽 · MCP로 제어)` → `스킬 (MCP를 호출)`
- **근거를 남기는 네 가지 (장표)**
  - 사람에게 보여 주기: 보드(에이전트가 사람에게 쓰는 게시판 겸 화이트보드), 세션 기록(전체 trajectory와 모델 라우팅 판단)
  - 미래의 나에게 남기기: DAG 노트(2~3시간 도는 작업의 지시 당시 맥락), 목표와 실행 범위는 DAG를 만들 때 LLM이 정리
- **패널 내 서브 에이전트/가이드 파일**: 좋았던 것들을 모아 "코드 아키텍트(아키텍트란 어때야 되는가)", "코드 리뷰 얼만큼 돌려야 되는가 / 어떤 가이드를 주고 돌려야 되는가" 등을 파일로 정리. 오픈으로 공개.
- **잘못된 입력 데모**: 잘못된 데이터가 들어간 채 실행 → "기다린다 / 멈춘다" → "정답은 멈춘다예요". 정정 예: "야 미안해 이거 틀렸다 / 내가 이거 잘못 넣었는데 / 이전 거 무시하고 …"
- **비용 흐름 (장표)**: `잘못 시켰다면 (기다리지 말고 멈춤)` → `정정 (이전 지시를 무시)` → `상태줄 표시 (캐시 깨짐 알림)` → `깨지기 전 메시지 (캐시 1시간 유지)`
- **AD 브라우저**: 에이전트가 자기가 제어하는 별도 브라우저를 띄워 버튼 클릭·기능 테스트 → 개인 크롬을 가져가지 않음. 요소를 클릭해 붙여넣으면 그 내용이 대화에 붙음(예전에 Cursor가 잘했던 기능, "그냥 돔 클릭하는 기술").
- **원격 제어 데모**: 맥 미니·DGX(화면 없는 컴퓨터 두 대)를 Tailscale로 묶고, 오르카가 제공하는 CLI로 에이전트가 AD를 제어해 터미널을 켬. 지시 예: "오르카로 그 코드 좀 켜봐라". 한 탭은 코딩, 다른 탭은 리서치·설계 고도화.
- **릴리즈노트 질문 예**: "클로드 코드에 추가되는 기능은 뭐냐"
- **회고 프롬프트**: `내 대화 기록을 분석해줘` — 기본은 현재 프로젝트 기준으로 찾고, "프로젝트 말고 글로벌에서 찾아라"라고 하면 전역 검색.
  - 대화 기록 위치: 홈 밑 `.claude` 폴더 → `history.jsonl` (윈도우도 대부분 동일). 프로젝트 대화 기록은 프로젝트 밑에 따로 남음.
  - 강사 결과 예: 이 강의 관련 프로젝트만 대상, 23개 세션. 개선 여지로 "확인 질문 반복"("작업 진행 중? 어디까지 진행된다?"), 같은 요청 중복 실행, "남은 거 다 고쳐라", "대그 실패율이 왜 이렇게 높냐", 잡음 세션 등이 나옴.
- **슬래시 명령**: `/goal` (전사상 "고을/골") — 가장 많이 사용.
- **인터뷰 스킬 데모**: 토픽을 줘야 함(예: "에이전트 시스템 설계"). 인터뷰 준비 중 보드에 table / flow diagram 형태 그림이 나오고, `ask user question`으로 질문 시작 → 단계별 문답 후 "문서로 쾅! 남겨줍니다". 인터뷰가 쌓이면 "나의 특성을 뽑아달라"고 할 수도 있음.
  - 발견한 버그: `ask user question`이 뜨는 동안 mods를 건드릴 수 없음(Claude 의도된 동작으로 보이나 불편).
- **Q&A — 디자인 목업**: Figma는 MCP 호출량 제한 등으로 불편 → 오픈 펜슬 / 펜슬 닥 데브를 쓰다 유료 문제로 → 무료 **doop**으로 이동. Claude와 연동하면 Figma처럼 컴포넌트 구성, HTML 기반.
- **Q&A — PC·계정 간 이어가기**: 대화 기록을 동기화/이동해 continue 하는 방법은 있음. 계정이 바뀌면 시스템 프롬프트 앞의 계정 이메일이 바뀌어 세션 자체가 바뀌고, 캐시가 깨져 수많은 컨텍스트를 한 번에 다시 로드해야 함. 강사는 대화를 포기하거나 마지막에 "쥐어짜서" 파일로 떨어뜨려 놓고 그 파일로 계정을 바꿈. VM 공유 폴더에 대화 기록을 두는 구성도 가능하다고 답함. 옵시디언은 사람이 보기 좋게 만든 것이지 어떤 식으로 마크다운을 저장해도 상관없음.
- **REA (Reverse Engineering Anything)**: 바이너리 분석 도구. "설치도 그냥 주소 주고 야 설치를 클로드에 하시면 됩니다." Claude의 바이너리를 Claude로 까보면 숨겨진 기능이 많고 아키텍처를 잘 분석해 줌.
  - 수치: 울트라 200불 계정에서 Claude Code 소스코드 분석을 약 3시간 돌렸더니(약 한 달 전) **주간 한도의 약 40%** 소모.

### 강사 팁·주의사항
- 패널은 강사 본인에게 맞춘 것 — **그대로 쓰지 말고** 업무 특성에 맞게 고쳐 쓸 것.
- **"특히나 회사 계정으로는 하지 마세요 처음에"** — 토큰 낭비가 크고, 크레딧 제한이 있는 상태에선 오류가 많이 나거나 토큰 소모가 상당함. 개인 계정에서 해보고 수정 후 회사로. (강사는 200불짜리 계정을 여러 개 사용)
- 잘못된 입력으로 실행됐으면 **즉시 멈추고 정정**: 기다려 봤자 쓰레기가 나오고, 기다리는 시간이 더 아깝다.
- 캐시가 깨지는 걸 **일단 알려 주게** 만들고, 깨지기 전 메시지로 유지해 비용을 제어.
- 토큰이 아까워서, 계획은 Claude와 짜고 **지시는 문서로 만들어 다른 에이전트에게** 맡긴다.
- 대화 기록 분석은 **촘촘하게 다 분석하진 않아** 일부 놓칠 수 있음 → **일주일 단위 정도** 회고에 잘 맞음. 글로벌로 보면 "더 예민한 얘기"가 나올 수 있음.
- 인터뷰 스킬은 오래 걸리므로 **여러 세션을 병행**(한쪽은 돌고, 한쪽은 인터뷰). "중간은 더 이상 잘 보지 않고 시작과 끝만" 본다.
- 디자인·목업은 눈으로 봐야 하므로 100% 맡길 수 없음 — 사람과 함께 보는 도구 사용.
- PC를 옮겨 다니는 건 불편해서 강사는 한 PC에서 계속 돌리는 편.
- 공개되는 프로젝트가 있다면 REA 같은 도구로 소프트웨어가 뚫릴 수 있으니 **방어도 고민**해야 함.
- REA는 토큰을 "어마어마하게" 먹음 → **개인 계정으로 재미로만**. 회사 계정으로는 일을 못 하게 되고 다 돌지도 못할 것.
- 언급한 사이트는 정리해서 공유 예정. 내일 스킬 수업과 일부 중복. 5시까지 10분 휴식 후 자습 복습.
