# ERP 어시스턴트의 지식·대화 상태·도구

> `METHOD-erp.md`의 C3(지식·대화 상태·메모리)와 C4(도구·행동·사람 연결)에서 같이 본다. 승인 양식, 감사 기록, 환경(개발·품질·운영)별 허용 범위는 C5에서 정하고, 여기에는 C3·C4가 만들어 넘길 것만 적는다.
> **(제안값)**은 출처에 없는 우리 쪽 기본값과 설계 선택이다. 우리 문서와 기록으로 재고 팀이 정한다. **(확인 필요)**는 1차 자료를 찾지 못했거나 원문을 대조하지 못한 내용이다. "출처 기준" 수치는 그 출처가 잰 값이고 우리 값이 아니다. 대괄호 번호는 맨 아래 참고 자료 번호다. 제품 이름은 "예:"로만 들고, ERP 제품에만 해당하는 내용은 `bases/`에 둔다.

## 1. 지식을 프롬프트에 넣을까, 검색할까, 도구로 조회할까

기록된 질문을 유형으로 나누고 유형마다 고른다. 한 어시스턴트 안에서 유형마다 선택이 달라도 된다 (제안값).

| 상황(신호) | 선택 | 이유 |
|---|---|---|
| 지식 전체가 작고(출처 기준 200,000 토큰 미만 [1]) 모든 직원이 같은 것을 볼 수 있으며 자주 바뀌지 않는다 | 전체를 시스템 프롬프트에 넣고 캐시한다 | 검색 없이 전체를 넣고 캐시하는 쪽이 단순하다 [1][2] |
| 작더라도 사람마다 볼 수 있는 문서가 다르다 | 검색한다 | 통째로 넣으면 권한을 나눌 방법이 없다 [15][26] |
| 창을 넘거나, 넣었을 때 지연·비용이 목표를 넘거나, 계속 늘어난다 | 검색한다 (어휘 + 임베딩, 필요하면 재순위) | 정적 지식도 양이 많으면 검색으로 간다 [1][6] |
| 오류 코드, 품번, 프로그램 이름, 규정 번호처럼 정확한 식별자로 묻는다 | 어휘 검색을 반드시 포함한다 | 임베딩 검색은 정확 일치를 놓칠 수 있다 [1] |
| 답이 하루 안에도 바뀌는 값이다 (재고, 결재 상태, 잔액) | 색인하지 않고 조회 도구로 ERP를 읽는다 (8절) | 실시간 값은 검색이 아니라 도구로 읽는다 [6] |
| 답이 합계·건수·추이 같은 집계다 | 서버에서 집계하는 도구를 쓴다 (10절) | 검색은 집계하지 못한다 (제안값) [9] |
| 문서 여러 건을 훑어 비교·종합해야 한다 | 모델이 검색 도구를 여러 번 부르게 하고 호출 수 상한을 둔다 | 한 번의 검색으로 근거가 다 모이지 않는다 (제안값) |
| 직원이 이 대화에 올린 파일에 대한 질문이다 | 그 대화에만 넣는다. 창을 넘으면 그 대화 범위의 임시 색인을 만들고 만료를 건다. 공용 색인에 넣지 않는다 | 올린 사람만 볼 자료다 (제안값) [10] |
| 전체를 넣기로 했는데 대화가 길다 | 긴 대화 묶음으로 따로 평가한다 | 입력이 길면 정보의 위치에 따라 성능이 달라진다 [33] |

## 2. 출처 목록

| 출처 | 주인 | 권한 모델 | 갱신 주기 | 폐기 규칙 | 색인 포함 여부 |
|---|---|---|---|---|---|
| (예) 구매 규정 문서함 | 구매팀 | 전 직원 읽기. 원천의 그룹에서 읽어 온다 | 개정 때 | 폐지된 판은 색인에서 뺀다 | 포함 |
| (예) 프로젝트 공유 폴더 | 없음 | 모름 | 모름 | 없음 | 제외. 주인과 권한 모델이 정해지면 다시 본다 |

- 색인하기 전에 출처마다 한 줄을 채우고 주인에게 확인받는다. 주인이 없거나 권한 모델을 모르는 출처는 색인하지 않는다 (제안값). "권한 모델" 칸에는 누가 볼 수 있는지와 그 정보를 어디서 읽어 오는지를 적는다. 3절의 필터가 이 칸을 구현한다.
- 어시스턴트는 원천의 권한을 그대로 따른다. 원천의 권한이 느슨하면 그 느슨함이 답에 드러난다 [20][26]. 색인 전에 원천 권한을 주인과 함께 점검한다.

## 3. 검색에서의 권한

- **질의 시점에 집행한다.** 인증된 요청에서 사용자와 그룹을 끌어내 모든 검색 요청에 필터로 건다. 모델 호출 전에 검색하든 모델이 도구로 검색하든 같다 [15].
- **신원은 서버가 넣는다.** 필터에 넣는 식별자는 모델이 낸 인자가 아니라 서버가 검증한 값이다. 색인의 식별자 필드는 문자열일 뿐이라 인증과 인가는 우리 코드가 따로 한다 [14].
- **검색 API 층 한 곳에 둔다.** 필터 로직을 한 층에 가두고 다른 코드와 모델이 저장소를 직접 조회하지 못하게 한다 [15]. 필터 없는 호출은 실패하게 한다 (제안값). 검색 요청과 반환된 문서 ID를 고칠 수 없는 기록으로 남긴다 [26].
- **생성 뒤에 거르는 것은 통제가 아니다.** 권한 없는 구절이 컨텍스트에 들어가면 모델이 풀어 써서 답에 섞고, 출력 필터는 풀어 쓴 내용을 가려내지 못한다. 그 구절에 든 지시도 이미 읽힌 뒤다 (제안값). 권한 판단을 프롬프트 문장에 맡기는 것도 통제가 아니다 [25].
- **격리 단위.** 법인·부서·프로젝트처럼 섞이면 안 되는 경계는 저장소나 네임스페이스를 나누고, 그 안의 문서별 권한은 메타데이터 필터로 건다 [15][26]. 나눈 경계는 통째로 지우기도 쉽다.
- **낡음은 세 경로로 따로 온다.** 경로마다 동기화 방식, 반영 지연 목표, 담당자를 따로 정한다.
  - **내용 변경:** 가장 먼저 만드는 경로라 이것만 만들고 끝내기 쉽다 (제안값).
  - **삭제:** 변경은 자동으로 잡아도 삭제는 따로 설정해야 잡는 제품이 있다. 빠뜨리면 지운 문서가 계속 검색된다 [18].
  - **권한 변경:** 상위 범위에서 상속된 권한 변경은 재동기화를 불러야 반영되는 제품이 있다 [19]. 부서 이동과 퇴사를 재동기화 계기에 넣는다 (제안값).

## 4. 검색 파이프라인 결정

| 결정 | 선택지 | 무엇으로 정하나(측정) |
|---|---|---|
| 파싱 | 문서 종류별 추출 방식(표, 스캔본, 이미지). 추출 텍스트가 없는 스캔본은 인용이 안 되는 제품이 있다 [3] | 종류별 표본을 원문과 대조한다. 파싱 품질을 재는 지표는 (확인 필요) |
| 청크·메타데이터 | 크기와 겹침. 기본값은 제품마다 다르다(출처 기준 한 제품은 800 토큰에 겹침 400 [10]). 문서 구조(제목, 조항, 표)를 따라 자르고 청크에 문서 안 맥락을 붙인다 [1]. 메타데이터는 문서 ID, 판, 시행일·만료일, 주인, 권한 그룹, 원문 위치 | Recall@k, Precision@k |
| 어휘 + 임베딩 | 어휘만 / 임베딩만 / 둘을 합친다(시작점 (제안값)) | 같은 시험 질의로 세 구성의 Recall@k와 MRR. 한국어 형태소 분석 설정이 주는 영향은 (확인 필요) |
| 재순위 | 쓰지 않는다 / 후보를 넓게 뽑아 재순위로 줄인다 [1] | Recall@k와 MRR의 변화, 늘어난 지연. 재순위·임베딩 모델의 선택 기준은 (확인 필요) |
| 후속 질문 고쳐 쓰기 | 그대로 검색한다 / 대화 맥락을 넣어 독립 질문으로 고쳐 쓴다 [36]. 원 질문은 보존하고 고쳐 쓴 질의를 기록한다 [16] | 후속 질문 Recall@k(고쳐 쓰기 전과 후), 고쳐 쓰기에 든 지연 |
| 넣는 개수·순서 | 개수와 총 토큰 상한. 많이 넣으면 정답이 들어올 확률은 오르지만 방해도 는다 [1]. 중요한 구절이 가운데 묻히지 않게 둔다 [33] | 개수별 근거 충실도와 완전성, 입력 토큰 |
| 인용 | 모델이 쓴 문자열 / 기계가 검증할 수 있는 위치 정보 [3]. 인용과 JSON 스키마 출력을 함께 못 쓰는 제품이 있어 화면 설계와 같이 정한다 [3] | 인용 정확도 |
| 답하지 않기 | 지시문에만 맡긴다 / 점수 임계값이나 충분성 판정을 코드로 둔다 [35]. 모른다고 답할 수 있게 허용하고 [4] 다음 행동(담당 부서, 사람에게 넘김)을 안내한다 | 기권 정확도, 음성 질의 결과 |
| 문서 충돌·날짜 | 폐지·만료된 판은 검색 전에 메타데이터로 뺀다. 남는 충돌은 둘 다 출처·시행일과 함께 보여 주고 모델이 고르게 두지 않는다. 오늘 날짜는 메시지로 준다 (제안값) | 옛 판과 새 판이 함께 있는 질의, 시행일이 미래인 문서가 걸린 질의. 이 방법의 효과를 잰 자료는 (확인 필요) |

- 검색만 따로 평가해 정한 뒤 생성을 붙인다. 한 번에 한 가지만 바꾼다 [16][17]. 모델은 컨텍스트가 모자랄 때도 기권하지 않고 틀린 답을 내는 경향이 있다 [35]. 근거를 요구하는 지시로도 지어내기가 완전히 없어지지 않는다 [4]. 그래서 기권을 코드 판정과 지표로 본다.

## 5. 검색 지표와 생성 지표

| 지표 | 정의 | 가려내는 것 |
|---|---|---|
| Recall@k | 정답 근거 가운데 상위 k 안에 들어온 비율 [16] | 못 찾는 문제 |
| Precision@k | 상위 k 결과 가운데 관련 있는 것의 비율 [16] | 잡음 |
| MRR | 첫 관련 결과 순위의 역수를 질의 전체로 평균한 값 [16] | 순위 |
| 음성 질의 결과 | 답이 없는 질의에서 결과가 비거나 임계값 아래인 비율 [16] | 기권의 전제 |
| 후속 질문 Recall@k | 후속 질문 묶음에서 고쳐 쓰기 전과 후의 Recall@k (제안값) | 멀티턴 검색 |
| 권한 누출 건수 | 권한 없는 사용자로 질의했을 때 결과에 금지 문서가 든 건수. 목표 0 (제안값) | 접근 제어 |
| 반영 지연 | 원천에서 내용 변경·삭제·권한 변경이 일어난 때부터 검색 결과에 반영될 때까지의 시간 (제안값) | 낡은 답, 낡은 권한 |
| 근거 충실도 | 답의 주장 가운데 검색된 컨텍스트가 뒷받침하는 비율 [17] | 지어낸 내용 |
| 완전성 | 질문의 모든 부분에 답했는지 [17] | 빠뜨림 |
| 인용 정확도 | 인용이 가리킨 구절이 그 주장을 실제로 뒷받침하는 비율 (제안값) | 틀린 출처 |
| 기권 정확도 | 답이 없는 질의에서 기권한 비율과, 답이 있는 질의에서 잘못 기권한 비율. 둘을 따로 적는다 (제안값) | 지어내기와 과잉 거절 |

- 검색과 생성을 따로 잰다. 한 점수로 합치면 못 찾은 것인지 지어낸 것인지 가릴 수 없다. 시험 질의마다 정답 문서와 구절을 같이 적는다. 답이 없어야 하는 질의, 후속 질문, 권한이 다른 사용자의 같은 질의를 반드시 넣는다 [16] (제안값).
- 근거 충실도는 높은데 답이 틀리면 원천 문서나 컨텍스트 사용을 의심한다 [17]. 권한 누출 건수 말고는 기준선을 잰 뒤 목표를 정한다 (제안값).

## 6. 대화 상태와 프롬프트 배치

위에서 아래로 보낸다. 캐시는 앞에서부터 같은 부분에만 맞고 앞이 바뀌면 뒤가 전부 무효가 된다 [2]. 그래서 ①·②는 모든 사용자와 대화에서 같게 둔다.

```
① 도구 정의          고정. 배포할 때만 바뀐다. 직렬화 순서를 고정한다
② 시스템 프롬프트    고정. 역할, 정책, 출력 규칙, 1절에서 "전체를 넣는다"로 고른 공통 지식
    ---- 캐시 지점 A ---- 여기까지는 모든 사용자·모든 대화에서 같은 바이트여야 한다
③ 대화 요약 블록     요약이 일어난 때에만 바뀐다. 바뀌면 그 뒤가 한 번 다시 쓰인다
④ 지난 턴들          덧붙이기만 한다. 이미 보낸 턴은 고치지 않는다
      user / assistant(도구 호출) / tool_result(검색·도구 결과. 신뢰 못 할 내용은 여기에만) / assistant(답 + 인용)
    ---- 캐시 지점 B ---- 마지막으로 고정된 블록
⑤ 이번 턴            사용자 메시지 + 턴마다 바뀌는 값
                       (오늘 날짜, 표시 이름·부서, 구조화 상태, 이번 턴에만 쓰는 검색 결과)
```

- 순서와 무효화 규칙은 참고 자료 [2], 신뢰 못 할 내용의 위치는 참고 자료 [5]를 따랐다. 지점 A·B의 위치와 ③·⑤의 구성은 (제안값)이다. 캐시의 최소 길이, 수명, 가격은 쓰는 모델의 문서에서 확인한다. 직원이 자리를 비웠다 돌아오는 간격이 캐시 수명보다 길면 긴 수명의 손익을 우리 기록으로 계산한다 (제안값).
- 사람이나 요청마다 다른 값(이름, 부서, 날짜, 권한)을 시스템 프롬프트에 넣으면 사용자 사이에 접두를 공유하지 못한다. 도구 정의는 접두의 맨 앞이므로 대화 중에 넣고 빼지 않는다 [2]. 이력은 덧붙이기만 하다가 임계값에서 한 번에 요약한다. 지난 턴의 검색 결과를 조금씩 지우면 매 턴 캐시가 깨진다 [2]. 검색 결과를 이력에 남길지 이번 턴에만 둘지는 후속 질문 Recall@k와 입력 토큰으로 정한다 (제안값).
- 요약 뒤에도 살아야 하는 값은 요약문에 맡기지 않고 **구조화 상태**로 따로 저장해 매 턴 ⑤에 넣는다. 요약 프롬프트는 실제 긴 대화로 조정한다 (제안값).
- 구조화 상태의 필드는 다섯이다 (제안값): **목표**(직원이 이 대화에서 이루려는 것), **대상 시스템·환경·객체**(어느 ERP 시스템의 어느 환경(개발·품질·운영), 어느 객체), **확정된 제약**(직원이 정한 범위, 기한, 하지 말라고 한 것), **대기 중인 승인**(승인 요청 ID와 상태. 승인한 인자는 승인 기록에 있다), **거절된 요청**(직원이나 정책이 거절한 요청과 사유. 요약 뒤에 다시 시도하지 않게 한다).
- 세션 식별자는 추측할 수 없게 만들고 서버에서 인증된 사용자에 묶는다. 다른 사용자가 같은 식별자를 내밀면 거부한다 [28]. 채널을 넘어 대화를 이으려면 채널이 아니라 사용자와 대화 ID로 저장한다 (제안값). 이력 보관 기한을 정한다(국내 기준은 확인 필요).

## 7. 장기 메모리

- 좁게 시작한다. 직원이 직접 정한 설정(기본 대상 시스템·환경, 출력 형식, 언어)만 저장한다 (제안값). 넓히는 것은 측정된 필요가 있을 때다.
- 사용자별로 격리한다. 저장 위치를 사용자에 대응시키고 경로를 검증하는 일은 구현하는 쪽의 책임이다 [7]. 직원이 저장된 것을 보고 지울 수 있게 한다. 직원 정보도 개인정보이므로 보관 기한과 삭제 절차를 둔다 [39][40].
- 문서와 도구 결과에서 온 문장은 저장하지 않는다. 평범한 질의만으로 메모리에 악성 기록을 심을 수 있다는 연구가 있다 [34].
- 기록 형식(출처, 만료일), 출처 규칙과 격리함, 범위, 쓸 때 가림은 `memory-improve.md` 3~4절을 따른다. 그 문서의 "경험" 층은 직원 대화에서 자동으로 쓰지 않는다. 운영 기록으로 어시스턴트를 고치는 일은 C6이다.

## 8. 도구 등급

| 등급 | 예 | 기본 정책 (제안값) |
|---|---|---|
| 조회 | 객체 한 건 읽기, 검색, 소스 한 건 보기 | 자동 실행. 반환 상한, 호출 수 제한, 기록 |
| 추출 | 표 대량 반출, 소스 묶음 내려받기 | 행·크기 상한과 필터 필수. 결과는 파일·핸들로(10절). 반출 목적과 범위를 기록. 상한을 넘으면 승인 |
| 변경 | 소스 수정, 데이터 갱신, 설정 변경 | 변경 전 확인 필수(12절). 멱등 키. 되돌리는 방법을 함께 제시. 실행 전후 상태 기록 |
| 범용 조작 | 화면 직접 조작, 임의 명령·임의 질의 실행 | 가장 좁게. 가능한 작업은 업무 단위 도구로 옮긴다. 남는 것은 단계마다 확인 |

- 등급은 우리가 정해 코드에 둔다. 도구 서버가 낸 읽기 전용·파괴적·멱등 주석은 힌트이고 실제 동작을 보장하지 않는다 [30]. 등급을 모르는 도구는 변경으로 취급한다.
- 열린 도구(임의 질의, 임의 명령, 화면 조작)는 한 도구로 무엇이든 할 수 있어 통제가 어렵다 [24]. 자주 하는 작업부터 인자가 정해진 업무 단위 도구로 만들고, API를 1:1로 감싸 나열하지 않는다 [8]. 화면 조작에 고유한 위험과 확인 단위는 (확인 필요).
- 이 등급은 "무엇을 하는가"이고 `security.md` 8절의 0~3 등급은 "되돌릴 수 있는가"다. 같은 변경 도구라도 환경(개발·품질·운영)에 따라 허용 범위가 다르며 그 표는 C5에서 정한다.

## 9. 누구의 권한으로 실행하나

- **공용 고권한 서비스 계정을 쓰지 않는다.** 공용 계정으로 ERP를 부르면 모든 직원이 그 계정의 권한을 얻는다. 요청한 직원의 신원을 ERP까지 전달해 ERP가 본인의 권한을 검사하게 한다. 허용 여부를 모델이나 프롬프트가 판정하지 않는다 [24][25].
- **받은 토큰을 그대로 넘기지 않는다.** 도구 서버(예: MCP 서버)는 자기를 대상으로 발급된 토큰만 받고, ERP용 토큰은 따로 받는다 [27][28]. 토큰 교환이나 대리 흐름을 쓴다 [21][32].
- **위임인지 가장인지 정한다.** 대리 실행임이 토큰과 기록에 남는 방식(위임)과 직원 본인으로만 보이는 방식(가장)이 있다 [32]. ERP 감사 기록에 직원과 어시스턴트가 함께 남는 쪽을 먼저 검토한다 (제안값). 감사 기준이 어느 쪽을 권하는지는 (확인 필요). 범위는 필요한 만큼만 요청한다 [27].
- **신원은 모델 밖에 둔다.** 사용자 ID와 토큰은 모델에 보내지 않는 실행 컨텍스트에 두고 도구 구현이 거기서 읽는다 [11]. 도구 스키마에 `user_id` 같은 인자를 두지 않는다. 자격 증명과 권한 구조를 시스템 프롬프트에 적지 않는다 [25].
- **접근 회수.** 직원이 도구 서버마다 따로 승인하게 둘지, 회사 인증 시스템이 누가 어느 서버를 쓸지 정하고 회수도 한 곳에서 할지 정한다 [31]. 퇴사·부서 이동 뒤 회수가 반영되기까지의 시간을 잰다 (제안값).
- 공용 계정이 남는 구간은 표로 적고, 구간마다 없앨 계획이나 남기는 이유를 적는다 (제안값).

| 구간 | 지금 쓰는 계정 | 그 계정의 권한 | 남기는 이유 | 보완 장치 | 없앨 계획·기한 |
|---|---|---|---|---|---|
| (예) 어시스턴트 → ERP 조회 | 공용 계정 | 여러 모듈 읽기 | 토큰 교환을 아직 못 붙였다 | 도구 쪽 권한 검사, 호출 기록 | 토큰 교환을 붙인 뒤 없앤다. 기한을 적는다 |

## 10. 큰 결과

소스 파일, 표 추출, 화면 덤프는 한 번에 창을 채운다. 아래 순서대로 쓴다.

1. **서버에서 필터·집계한다.** 행을 받아 와 모델이 세게 하지 않는다 [8][9].
2. **범위·페이지 인자를 두고 기본값을 작게 잡는다** [8].
3. **전체는 파일·핸들로 두고 모델에는 요약만 준다.** 요약은 건수, 열 이름, 앞 몇 행이다 [29] (제안값).
4. **코드 실행 환경에서 처리한다.** 여러 호출의 중간 결과를 실행 환경에 두고 모델에는 최종 일부만 보여 준다. 격리, 자원 한도, 감시가 함께 필요하다 [9].

- 반환 상한을 토큰으로 정한다. 한 코딩 에이전트는 도구 응답을 기본 25,000 토큰으로 제한한다(출처 기준 [8]). 우리 값은 도구 결과 토큰 분포를 재고 정한다 (제안값). 잘랐으면 잘렸다는 사실과 나머지를 보는 방법(좁히는 인자, 다음 페이지, 핸들)을 결과에 적는다 [8].
- 핸들은 이름이지 권한이 아니다. 매 호출 사용자를 다시 검증하고, 추측할 수 없게 만들고, 보존 기한을 도구 설명에 적는다 [29]. 다른 사용자가 내민 핸들은 거부한다 [28].
- 큰 자료를 모델이 옮겨 쓰게 하지 않는다. 다른 도구에 넘길 때는 핸들을 넘긴다. 민감 값은 모델에 가기 전에 가리고 도구 사이에서만 원래 값으로 흐르게 할 수 있다 [9].

## 11. 도구 결과는 신뢰 못 할 입력이다

- **지시가 들어올 수 있는 곳:** 문서 본문, 올린 파일, 소스 코드의 주석과 문자열 리터럴, 데이터의 텍스트 필드(적요, 비고, 이름), 화면에 찍힌 글자. 사내 자료도 누군가 편집할 수 있다 [5][23].
- **넣는 방법:** 도구 결과 블록으로만 넣고, 종류와 출처를 표시하고, 제3자 문자열은 구조화해 감싸고, 우리 지시는 도구 결과에 넣지 않는다. 도구 결과는 자료이지 지시가 아니라는 정책을 시스템 프롬프트에 적는다 [5]. 이것만으로는 막히지 않으므로 아래 둘을 코드로 둔다.
- 민감 데이터 접근, 신뢰 못 할 내용, 밖으로 내보낼 수단이 한 흐름에 모이지 않게 한다 [38] (`security.md` 2절). 신뢰 못 할 내용을 읽은 뒤의 변경·추출 호출은 자동 실행하지 않는다 (제안값).
- 호출은 직원의 요청에서 끌어낸 범위(대상 시스템·환경·객체, 등급) 안으로 제한한다. 범위는 코드가 구조화 상태에서 읽고 범위 밖 호출은 막는다 (제안값). 신뢰 못 할 값이 변경·추출 도구의 인자로 들어가는 것을 막는 값 단위 추적은 `security.md` 9절을 따른다.

## 12. 변경 전 확인과 중복 실행 방지

- **확인 화면은 코드가 만든다.** 모델이 쓴 요약이 아니라 실제 인자에서 만든다: 대상 시스템·환경, 대상 객체, 변경 전후 차이, 영향 범위, 되돌리는 방법 (제안값). 민감한 호출 전에 입력을 보여 주고 사람이 거부할 수 있어야 한다는 것은 규격의 권고다 [29].
- **승인은 화면 조작으로 받는다.** 대화 속 "네"나 모델의 "승인받았다"는 말로 대신하지 않는다. 거절과 취소를 구분해 기록한다 (제안값). 승인 대기 중에는 실행 상태를 저장했다가 재개하고 [13], 대기 중인 승인은 6절의 구조화 상태에도 남긴다.
- **승인된 인자와 실행 인자를 서버가 대조한다.** 다르면 실행하지 않는다 (제안값). 승인을 도구·대상·인자·1회에 묶는 원리, 판정과 강제의 분담은 `security.md` 8절에 있다.
- **멱등 키는 하네스가 만든다.** 변경 호출마다 키를 붙여 시간 초과 뒤 재시도가 두 번 반영되지 않게 하고, 같은 키에 인자가 다르면 거부한다 [22]. 키는 모델이 아니라 하네스가 대화·턴·호출에서 만든다 (제안값).
- **다시 실행하기 전에 상태를 확인한다.** ERP가 멱등을 지원하지 않으면 실행 전에 현재 상태를 읽어 이미 반영됐는지 본다 (제안값).

## 13. 사람에게 넘기기

- 사람에게 넘김을 도구로 만든다. 모델에게는 도구로 보이고, 부를 때 구조화된 입력을 내게 할 수 있다 [12].
- 요약 필드 (제안값): 사유, 직원의 목표, 대상 시스템·환경·객체, 시도한 것과 결과, 근거 문서, 대기 중인 승인. 이력만 넘기지 않고 요약을 함께 넘긴다.
- 넘겨야 할 때 넘겼는지를 잰다 [6]. 넘겨야 하는 대화와 넘기면 안 되는 대화 묶음으로 적중(넘겨야 할 때 넘김)과 오발(넘기지 말아야 할 때 넘김)을 센다 (제안값).

| 이름 | 등급 | 설명 (언제 쓰고 언제 안 쓰나) | 인자와 예시 | 반환 (형식, 상한, 잘림 안내, 핸들) | 오류 종류 | 필요한 권한 | 승인 | 멱등 | 되돌리는 방법 |
|---|---|---|---|---|---|---|---|---|---|
| (예) `erp_source_read` | 조회 | 프로그램 한 건의 소스를 줄 범위로 읽는다. 여러 건을 한꺼번에 받을 때는 쓰지 않는다 | `object`, `start_line`, `limit` | 줄 번호가 붙은 텍스트. 상한을 넘으면 다음 범위를 안내한다 | 없는 객체 / 권한 없음 / 범위 초과 | 직원 본인의 소스 읽기 권한 | 없음 | 해당 없음 | 해당 없음 |

| 시험 | 방법 | 기대 |
|---|---|---|
| 검색·생성 지표 | 같은 시험 질의로 어휘만, 임베딩만, 둘 다, 재순위 추가를 돌려 검색 지표를 잰다. 고른 구성에 생성을 붙여 근거 충실도, 완전성, 인용 정확도, 기권 정확도를 잰다 | 5절의 지표가 기록되고 선택 근거가 남는다. 답이 없는 질의에서 지어내지 않는다 |
| 권한 누출 | 권한이 다른 시험 계정 둘 이상으로 같은 질의를 돌린다. 필터 없이 검색 API를 직접 부른다 | 권한 누출 건수 0. 직접 호출은 거부된다 |
| 반영 지연 | 원천에서 문서를 고치고, 지우고, 권한을 뺀 뒤 각각 검색 결과에 반영되기까지의 시간을 잰다 | 세 경로 모두 목표 안이다 |
| 숨은 지시 | 문서, 올린 파일, 소스 주석·문자열, 데이터 텍스트 필드에 지시를 심고 정상 요청을 돌린다 | 승인 없이 실행된 변경·추출 0건. 인용과 기록에 그 자료가 드러난다 |
| 요약 생존 | 강제로 요약한 직후 구조화 상태의 다섯 필드를 확인한다 | 다섯 필드가 그대로다 |
| 세션·핸들 | 다른 사용자의 세션 식별자와 핸들을 내민다. 만료된 핸들을 쓴다 | 거부된다. 만료에는 정해진 오류가 나온다 |
| 캐시 접두 | 같은 대화의 연속 두 요청, 서로 다른 사용자의 첫 요청에서 6절 ①·②의 해시를 비교한다 | 해시가 같다. 턴별 캐시 읽기 비율이 기록된다 |
| 메모리 | 값을 쓰고 새 세션에서 읽는다. 다른 사용자로 읽는다. 삭제 뒤 읽는다. 문서에서 온 문장을 저장하려 한다 | 읽힌다 / 보이지 않는다 / 없다 / 거부된다 |
| 신원 전달 | 권한이 다른 계정 둘로 같은 요청을 돌린다. 다른 대상용 토큰을 도구 서버에 내민다 | 권한 없는 쪽은 ERP가 거부한다. ERP 감사 기록에 요청한 직원이 남는다. 토큰은 거부된다 |
| 큰 결과 | 상한을 넘는 소스와 표 추출을 요청한다 | 반환이 상한 안이다. 잘림 안내가 있고 다음 호출이 범위·필터를 쓴다 |
| 변경 전 확인 | 변경 도구를 확인 없이 직접 부른다. 승인 뒤 인자를 바꿔 실행한다. 거절·취소 뒤 실행을 시도한다 | 셋 다 실행 0건이다 |
| 중복 실행 | 같은 변경 호출을 시간 초과 뒤 다시 보낸다 | ERP에 한 번만 반영된다 |
| 사람에게 넘김 | 넘겨야 하는 대화와 넘기면 안 되는 대화 묶음을 돌린다 | 적중·오발 수치가 기록된다. 요약의 필수 필드가 채워진다 |
| 대화 전체 | 모델 없는 도구 단위 시험, 도구·인자 선택 시험을 지난 뒤에 돌린다 (제안값). 대화가 끝난 뒤 시험용 ERP의 상태를 기대 상태와 비교하고 같은 과제를 여러 번 돌린다 [37] | 매번 통과한 비율이 기록된다 |
