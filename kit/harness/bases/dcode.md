# 기반 참고: dcode로 Coding Assistant 만들기

> dcode(deepagents-code)를 기반으로 인수 기준(`../CRITERIA.md`)을 채울 때 보는 문서다. 단계 설명은 `../METHOD.md`에 있고, 여기에는 dcode에서만 해당하는 내용을 적었다.
> 근거는 수업 저장소의 `Day08/dcode-analysis/`(dcode 0.1.69, SDK deepagents 0.7.14, 2026-09-14 스냅샷)다. 경로는 dcode 모노레포 루트 기준이고, **줄 번호는 한국어 해설 주석이 들어간 사본 기준이라 원본과 다를 수 있다.** 직접 확인하지 못한 것은 "확인 필요"로 적었다.

## 1. 한눈에 보기

dcode가 이미 해 주는 것과 비어 있는 것을 먼저 구분한다. 비어 있는 세 곳이 과제의 본체다.

| 인수 기준 | dcode에 이미 있는 것 | 비어 있는 것 (만들 것) |
|---|---|---|
| 1 코드 품질 | 엄격한 린트 설정(ruff 전체 규칙, google docstring, 상대 import 금지), `make lint` / `make format` | 새로 쓰는 코드가 같은 검사를 통과해야 한다 |
| 2 계획·리뷰·승인 | 도구 단위 사람 승인, `/goal`의 수락 기준 초안과 채점, 파일로 정의하는 서브에이전트 | **계획 모드가 없다.** 계획 양식, AI 리뷰, 계획 승인 게이트, 범위 검사 |
| 3 메모리·자기개선 | `AGENTS.md`를 읽어 주입, `/remember`, 에이전트 이름별 독립 메모리 | **검색이 없다**(전문을 대화 시작 때 한 번 주입). 경험 저장소, 검색·주입, 개선안 생성·검증·채택 |
| 4 모니터링 | LangSmith 연동, 모델 재시도 이벤트, 비용·토큰 집계, 훅용 대화 기록, 체크포인트 DB | **단계 단위 기록이 없다.** 요청별 계획·리뷰·코드·테스트·결과 기록, 요약 지표, 조회 도구 |

## 2. 환경과 빌드 (S0에서 정할 것)

| 결정 | 내용 | 근거 |
|---|---|---|
| 작업 위치 | WSL 안, 수업 폴더 밖의 별도 경로 | `Day07/dcode_task.md`, `Day06/task.md` |
| 저장소 구조 | **모노레포 구조를 유지한다.** `libs/code`가 `../deepagents`, `../acp`, `../partners/*`를 경로로 참조한다. `libs/code`만 떼면 빌드가 깨질 수 있다(확인 필요) | `libs/code/pyproject.toml`의 uv sources |
| 가상환경 | **수업 저장소의 공용 환경과 섞지 않는다.** dcode는 `deepagents==0.7.14`로 고정이고 수업 환경은 0.7.32다. `libs/code`의 자체 lock으로 별도 환경을 만든다 | `libs/code/pyproject.toml:30` |
| Python | 3.12 이상 | `libs/code/pyproject.toml:13` |
| 모델 | `Day07/dcode_task.md`는 OpenRouter 경유, OpenAI·Anthropic·Google 모델 금지, 테스트 모델로 GLM-5.3-Flash·DeepSeek-V4.1-Flash·Qwen3.8을 들었다. **최종 과제에도 같은 규칙인지는 확인 필요** | `Day07/dcode_task.md` |
| 출발 소스 | 수업 저장소의 해설 주석판에서 시작할지 원본에서 시작할지 정한다. 주석판은 한국어 주석이 수천 줄이라 린트에 걸릴 수 있다(확인 필요) | `Day08/dcode-analysis/README.md` |

```bash
cd libs/code
make bootstrap                 # 개발 환경 (또는 uv sync --group test)
uv run deepagents-code         # 소스로 실행. 소스를 고치면 다음 실행에 반영된다
make lint                      # 린트 + 타입 검사
make format                    # 포맷
make test                      # 단위 테스트 (make test TEST_FILE=tests/unit_tests/test_x.py)
dcode -n "요청"                # 화면 없이 한 번 실행. 매번 새 대화, 파일 상태(메모리·스킬·설정)는 유지
dcode -n "요청" -S "pytest,uv,git"   # 화면 없는 실행에서 셸은 허용 목록이 있어야 켜진다
```

- OpenRouter를 쓰려면 `langchain-openrouter` 패키지와 `OPENROUTER_API_KEY`가 필요하다. 소스 빌드에서 추가 패키지를 함께 설치하는 정확한 명령은 문서에 없다. **직접 돌려 보고 README에 적는다.**
- `/auth`로 저장한 예전 키가 환경 변수의 키보다 먼저 쓰인다. 모델이 엉뚱하게 잡히면 이것부터 본다.
- 디버그: `DEEPAGENTS_CODE_DEBUG=1`이면 대화별 로그가 `/tmp/deepagents_debug/`에 남는다.

## 3. 끼어들 수 있는 자리

| 방법 | 어디에 두나 | 쓰기 좋은 곳 | 주의 |
|---|---|---|---|
| **미들웨어** (소스 수정) | `libs/code/deepagents_code/agent.py`의 `create_cli_agent`(2570줄 근처)가 만드는 `agent_middleware` 목록에 추가. 새 모듈은 `deepagents_code/` 아래 | 기록, 지표, 계획 게이트, 메모리 검색·주입, 개선안 생성 | 서버 프로세스에서 돈다. `Path.cwd()`를 쓰면 `make lint`가 실패한다(경로는 실행 맥락에서 받는다). 단위 테스트를 쓸 수 있다 |
| **훅** (소스 수정 없음) | `~/.deepagents/hooks.json` 또는 `{프로젝트}/.deepagents/hooks.json` | 계획 게이트(실행 전 검사), 입력 제출 때 메모리 주입 | 이벤트 12종(`PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop` 등). 프로젝트 훅은 신뢰 승인이 필요하고, 화면 없는 실행에서는 `--trust-project-hooks`가 필요하다. 종료 코드 2가 차단이다. 도구 이름은 `execute→Bash`, `write_file→Write`, `edit_file→Edit`로 맞춘다 |
| **스킬** | `{프로젝트}/.deepagents/skills/<이름>/SKILL.md` | 계획 작성 절차, 개선안 작성, 기록 조회 리포트 | 목록은 대화당 한 번만 로드된다. `allowed-tools`는 강제되지 않는다. `/skill:<이름>`으로 직접 부를 수 있다 |
| **서브에이전트** | `{프로젝트}/.deepagents/agents/<이름>/AGENTS.md` (머리말에 `name`, `description`, 선택 `model`) | 계획 리뷰어(독립 컨텍스트, 다른 모델 지정 가능) | 머리말로 도구·미들웨어를 설정할 수 없다 |
| **메모리** | `~/.deepagents/<에이전트>/AGENTS.md`, `{프로젝트}/.deepagents/AGENTS.md`, 루트 `AGENTS.md` | 항상 지킬 규칙 | **대화당 한 번만 로드**되고 **검색 없이 전문 주입**이다. `auto_save`가 켜져 있으면 모델이 직접 고친다 |
| **목표·채점** | 화면에서 `/goal`, `/rubric`. 화면 없는 실행은 `--rubric "기준"` 또는 `--rubric @파일` | 완료 조건을 채점에 연결 | 화면 없는 실행에는 목표 리뷰 화면이 없다 |

**어느 쪽으로 구현하나.** 평가 기준 1이 Python 코드 품질이고 평가자가 소스를 빌드해 실행하므로, 핵심 기능은 **소스 안의 미들웨어**로 만드는 쪽이 맞다(코드 품질의 대상이 생기고 단위 테스트로 증명할 수 있다). 훅은 소스를 안 고치고 빨리 시험해 볼 때 쓴다. 이 선택은 권고이고, 근거와 함께 `design/decisions.md`에 적는다.

### 3. 메모리·자기개선 [10]
| 항목 | 할 일 | README 확인 방법 |
|---|---|---|
| 3-1 저장·유지 | 규칙은 `AGENTS.md`, 경험은 별도 파일(예: `.deepagents/memory/experiences.jsonl`). 작업이 끝나거나 실패할 때 기록 | 세션 A에서 저장 → `dcode -n`(새 대화)에서 남아 있음 |
| 3-2 검색·활용 | 요청으로 경험을 검색해 조금만 주입한다. **시스템 프롬프트가 아니라 메시지로** 넣어야 캐시가 안 깨진다. 주입한 항목을 계획과 기록에 남긴다 | 비슷한 작업 → 계획에 "참조한 경험" 표시 |
| 3-3 개선안 생성 | 도구 오류, 테스트 실패, 채점의 수정 필요 판정을 모아 개선안(규칙·스킬·프롬프트 변경안)을 파일로 만든다. 바로 적용하지 않는다 | 일부러 실패시킨 작업 → 개선안 파일 |
| 3-4 전후 검증·반영 | 고정 작업 몇 개를 현재 버전과 후보로 각각 돌려 비교한다. `-a/--agent 이름`으로 메모리를 분리하면 깔끔하다. 회귀가 없을 때만 반영 | 전후 비교표, 탈락안은 미반영, 채택안이 다음 작업에서 쓰임 |

- **반영 효과는 새 대화에서 보인다.** 메모리는 대화당 한 번만 로드된다. 같은 대화에서 고치고 같은 대화에서 확인하면 안 보인다.
- **`auto_save`를 끄는 것을 검토한다.** 켜져 있으면 모델이 `AGENTS.md`를 직접 고쳐 "검증 후 반영"을 건너뛴다. 끄는 것은 프롬프트만 바꾸는 약한 제어라, 필요하면 실행 전 검사로 직접 편집도 막는다.

| 단계 | 먼저 확인할 것 | 끝났다는 기준 |
|---|---|---|
| S0 | 2절의 결정 사항. 깨끗한 환경에서 `uv run deepagents-code`가 뜨고 고른 모델로 한 번 응답하는가 | 빌드·실행 명령이 README 초안에 있다 |

| S6 | 검색·주입 → 개선안 → 전후 비교 | 개선 한 바퀴가 기록에 있다 |
| S8 | README에 항목별 확인 방법. 깨끗한 환경에서 그대로 돌려 본다 | `criteria-check` 표의 모든 항목이 "실행해서 확인"이다 |

## 6. 함정

1. 서버 프로세스 코드에서 `Path.cwd()`를 쓰면 린트가 실패한다. 서버 하나가 여러 작업 폴더를 맡기 때문이다.
2. 메모리와 스킬 목록은 대화당 한 번만 로드된다. "다음 작업에 반영"은 새 대화로 보인다.
3. 화면 없는 실행(`-n`)에서는 셸에 허용 목록(`-S`)이, 프로젝트 훅에 `--trust-project-hooks`가 필요하다. README의 확인 명령에 빠뜨리지 않는다.
4. 화면 없는 실행에는 목표 리뷰 화면이 없다. 계획·리뷰를 `-n`으로 보이려면 `--rubric @계획파일`과 리뷰어 서브에이전트를 조합한다.
5. 로컬 셸에는 경계가 없다. 모든 승인을 끄는 모드(YOLO)나 `-S all`로 시연하지 않는다.
6. 슬래시 명령을 소스에 추가하면 명령 목록 문서를 다시 만들어야 린트가 통과한다(`make commands-catalog`). 스킬을 `/skill:<이름>`으로 부르는 쪽이 간단하다.
7. dcode는 실행한 폴더의 `AGENTS.md`, `.agents/skills`, `.claude/skills`도 읽는다. 개발용 Claude 세팅과 제품이 섞이지 않게, 시연은 별도 작업 폴더에서 한다.
8. 자동 검토 모드(Auto)의 판정 모델이 금지된 회사 모델로 잡히지 않는지 확인한다. 리뷰어와 채점 모델도 허용된 모델로 지정한다.

## 7. 공식 문서와 실제 코드가 다른 곳

| 문서 | 실제 |
|---|---|
| `~/.deepagents/<에이전트>/memories/`에 자동 메모리가 쌓인다 | 그런 코드가 없다. `AGENTS.md`를 편집 도구로 고친다 |
| 확장으로 넣은 미들웨어는 `/reload`로 반영 | `/restart`가 필요하다 |
| 채점 반복 한도에 닿으면 "수정 필요"로 끝난다 | "최대 반복 도달" 상태로 바뀐다 |
| 스킬 탐색 계층 4~6개 | 실제 8개 |
| 훅 이벤트 목록 | `PostToolUseFailure`가 문서에 빠져 있다 |

더 자세한 분석(확장, 플러그인, MCP, 보안 메모)은 수업 저장소 `Day08/dcode-analysis/analysis/` 00~09 문서에 있다.
