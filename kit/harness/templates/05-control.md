## 자산과 신뢰 경계
- 에이전트가 읽을 수 있는 것 (저장소, 시크릿, 사내 시스템):

- 누구의 계정·토큰으로 도는가, 그 권한 범위:
- 신뢰 못 할 입력이 들어오는 길 (저장소 문서, 이슈·댓글, 웹, 도구 응답, 메모리):
- 세 가지 능력(비공개 데이터 / 신뢰 못 할 입력 / 외부 통신·상태 변경) 중 뺀 것과 방법:
- 셋이 다 필요한 행동과 그때 사람이 승인하는 방법:

## 계획·리뷰·승인
양식, 상태 전이, 리뷰 기준은 `harness/reference/plan-gate.md`를 따른다. 여기에는 우리 구현의 위치와 값만 적는다.

- 계획 파일 위치와 형식 검사 명령:
- 리뷰어 구성 (독립 컨텍스트, 읽기 전용 도구, 받는 입력, 판정 형식, 라운드 상한):

- 실행 전 게이트가 확인하는 것: [ ] 승인 상태  [ ] 계획 본문 해시 일치  [ ] 수정 대상 범위  [ ] 보호 경로  [ ] 변경 종류
- 승인을 무효로 만드는 조건:

- 요청당 사람 승인 횟수 (측정값, 측정 방법):

## 격리
- 파일 쓰기 범위:
- 읽기를 막은 자격증명 경로 (직접 나열):
- 네트워크: 기본 차단 여부, 허용 목록과 항목별 이유 (넓은 도메인은 유출 경로다):

## 완료 기준
- [ ] 필수 규칙마다 강제 장치가 둘 이상의 층에 있고 차단 시험 기록이 있다
- [ ] 승인 기록을 에이전트가 만들거나 고칠 수 없고, 실행 전 게이트가 승인 상태와 수정 대상 범위를 함께 확인한다
- [ ] 보호 경로 목록이 있고, 계획에 넣어도 수정이 막힌다
- [ ] 검사기 실패·시간 초과·깨진 입력이 차단으로 끝난다(모델 판정의 실패는 검토나 차단). 그렇게 만들 수 없는 검사는 CI에 같은 것이 있다
- [ ] 차단 뒤 실제로 실행된 호출이 0건이고, 검사 없이 실행되는 경로(서브에이전트 포함)가 없음을 시험했다
- [ ] 도구를 거치지 않는 길(들어오는 메시지, 모델로 나가는 내용, 최종 답변, 메모리 쓰기)마다 장치나 대응하지 않는 이유가 적혀 있다
- [ ] 모델이 판정하는 검사는 라벨 세트로 놓친 비율·과잉 차단 비율·검토율을 쟀다 (모델 판정을 쓰지 않으면 "해당 없음")
- [ ] 층별 방어 표의 "못 막는 것"과 다음 층이 빈칸 없이 채워졌다
- [ ] 위협 점검표에 항목마다 대응과 시험 결과가 있다. 대응하지 않기로 한 항목은 이유가 있다
- [ ] 레드팀 시험이 명령 한 줄로 다시 돌고, 게이트 이벤트가 기록에 남는다
- [ ] 평가에서 정책 위반이 0건이고, 그 판정이 게이트와 독립된 코드에서 나온다
- [ ] 막지 못하는 우회 경로가 표로 남아 있고 보완책이 있다
- [ ] 요청당 사람 승인 횟수가 측정됐다
