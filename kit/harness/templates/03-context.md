## 코드 탐색
- 찾는 방법 (기본: 파일 목록·문자열 검색·범위 읽기):
- 더한 보조 수단과 그 근거가 된 측정 (심볼 색인 / 저장소 지도 / 의미 검색):
- 서브에이전트로 보내는 조건 (질문이 분명 / 읽을 양이 많음 / 원문을 메인이 다시 쓰지 않음):

## 프롬프트 배치와 캐시
```
[도구 정의] → [시스템 지시·지침]            ← 세션 중 바꾸지 않는다 (캐시 접두)
[요청] [변동값: 날짜·주입한 메모리·강제 로드한 스킬 본문 — 메시지로 한 번 붙이고 지우지 않는다]
[대화: 뒤에 붙이기만]
```
- 요청마다 달라지는 값이 고정 구역에 들어가지 않는지 확인한 방법 (연속 두 요청의 해시 비교):
- 직렬화 고정 방법 (도구 정의 순서, 키 순서):
- 도구를 상황별로 제한하는 방법 (정의를 빼지 않고 호출을 막음 / 지연 로드):
- 캐시 수명과 최소 길이, 수명보다 긴 공백이 생기는 지점 (예: 사람 승인 대기):

## 완료 기준
- [ ] 지침 계층, 겹칠 때의 규칙, 합계 상한, 담당자가 정해졌고, 상시 로드 지침이 상한 안이다
- [ ] 탐색 방식(검색 수단, 격리 조건)이 정해졌고 재현율 수치가 있다
- [ ] 시스템 프롬프트와 도구 정의가 세션 중 바뀌지 않음을 해시로 확인했다
- [ ] 컨텍스트 줄이기 정책(임계값, 최소 비움량, 생존 목록)이 있고 압축 생존 시험을 통과했다
- [ ] 규칙 저장소와 경험 저장소가 따로 있고, 종류별로 누가 쓰고 누가 고치는지가 적혀 있다
- [ ] 작업 종료·실패 때 경험이 기록되고, 프로세스를 끝낸 뒤 새 세션에서 같은 길로 읽힌다 (쓰기 이벤트와 왕복 확인 결과)
- [ ] 저장 전 검사의 거부 시험 기록이 있고, 로드량·항목 길이·건수 상한과 만료·정리 담당자가 있다
- [ ] 평가 회귀가 없고 세션 시작 로드량·캐시 읽기 비율·컨텍스트 최대 사용량이 기록됐다
