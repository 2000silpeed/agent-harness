# S7. 모델·비용·속도 최적화

> 원칙: 유지 기준을 먼저 적는다. 한 번에 하나만 바꾸고 켜고 끌 수 있게 만든다. 품질을 걸지 않는 변경부터 한다.
> 단위는 호출당·토큰당이 아니라 **통과한 작업 1건당 비용**(실패와 재시도에 쓴 비용 포함)과 작업 1건의 전체 시간이다.
> 최소 버전: S0 목표를 이미 채웠으면 "목표와 유지 기준", "기준선"만 채우고 변경 기록에 "더 줄이지 않는 근거"를 적어 닫는다.

## 기준선 (요청 종류별)

작업 시간 ≈ 호출 수 × 첫 토큰까지 시간 + 출력 토큰 ÷ 출력 속도 + 모델 밖 시간(도구 실행, 대기열, 재시도). 어느 항이 큰지 먼저 본다.

| 요청 종류 | 통과율 | 통과 1건당 비용 | 전체 시간 p50 / p95 | 첫 토큰 시간 | 호출 수 | 입력 / 출력 토큰 | 캐시에서 읽은 비율 | 재시도 수 | 도구 실행 시간 |
|---|---|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |  |  |

## 검토 순서 (위에서부터. 해당 없으면 이유를 적는다)

| # | 레버 | 확인할 것 | 품질을 거나 | 적용 여부와 이유 |
|---|---|---|---|---|
| 1 | 캐시 | 고정 내용(도구 정의, 시스템 지시, 지침)이 앞에 있고 바뀌는 값(날짜, 요청 ID, 주입한 메모리)은 뒤의 메시지에 있다. 대화 중에 도구 목록과 모델을 바꾸지 않는다. 적중을 사용량 필드나 서빙 지표로 직접 확인한다. 적중이 0이면 연속 두 요청의 프롬프트를 비교한다 | 아니다 |  |
| 2 | 입력 | 안 쓰는 도구 빼기, 도구를 필요할 때 찾게 하기, 프롬프트에 박힌 조각 지식을 스킬로 빼기, 예전 모델에 맞춰 쓴 과잉 지시 지우기 | 아니다 |  |
| 3 | 루프 | 오류 뒤 같은 호출 반복, 묶을 수 있는 연속 호출(스크립트 하나로), 규칙으로 끝낼 수 있는 판단을 코드로 | 아니다 |  |
| 4 | 출력 | 응답 형식 정하기, 도구 호출 사이의 설명 줄이기 | 아니다 |  |
| 5 | 일괄 처리 | 평가 실행이나 야간 작업처럼 아무도 기다리지 않는 일을 일괄 처리로 돌리기 | 아니다 |  |
| 6 | 추론 강도·예산 | 같은 모델에서 단계별로 훑어 점수-비용 표를 만든다. 낮은 강도로 돌리고 확인되는 실패만 높은 강도로 다시 돌리는 구성도 후보에 넣는다 | 건다 |  |
| 7 | 모델 교체 | 분류·선택·예/아니오 단계부터. 큰 모델의 낮은 강도와 작은 모델을 통과 1건당 비용으로 비교한다. 판단 단계는 출력을 선택지로 강제한다 | 건다 |  |
| 8 | 여러 모델·서브에이전트 | 위를 다 해도 목표에 못 미칠 때만. 독립 작업을 동시에 돌리거나 한 컨텍스트에 안 들어가는 일일 때 이득이다. 서브에이전트는 접두가 달라 부모의 캐시를 쓰지 못할 수 있어 비용은 오를 수 있다 | 건다 |  |

- "건다"인 변경은 아래 점수-비용 표가 있어야 채택한다.
- 직접 서빙이면 더 본다: 접두 캐시 적중, 대기열, 컨텍스트 상한, 양자화 (`serving-plan` 스킬).
- 모델이 바뀌면 추론 강도를 다시 훑는다. 이전 설정을 그대로 옮기지 않는다.
