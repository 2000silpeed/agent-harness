# S6. 메모리 기반 자기개선

> 형식·정책·판정 절차의 설명은 `harness/reference/memory-improve.md`, 실행 절차는 `self-improve-loop` 스킬에 있다. 저장소 구조와 쓰기 정책은 S3(`design/03-context.md`)에서 정한 것을 쓴다.
> 최소 버전: 손잡이 1개, 후보 1개, 사례 분할 없음(방향성 판정), 사람 승인, 라운드 1회. 숫자 칸은 팀이 정한다.

## 조회와 활용

| 항목 | 정한 것 |
|---|---|
| 경험 저장소 위치와 기록 형식 (S3에서 정한 것) |  |
| 찾는 방식 (범위 필터 + 키워드 / 임베딩을 더했으면 근거 수치) |  |
| 조회 시점 (요청 직후 / 실패 직후) |  |
| 주입 전 확인 (근거가 지금 코드와 맞는가, 출처 신뢰 등급, 만료) |  |
| 주입 개수와 토큰 상한 |  |
| 주입 위치 (시스템 프롬프트가 아닌 메시지로 한 번) |  |
| 계획의 "참조한 경험" 구역 양식 (항목 ID, 달라진 점. 없으면 "없음") |  |
| 남기는 이벤트 (조회: 질의·후보 ID·주입한 ID·토큰 수 / 작업 뒤: ID별 도움·해로움·안 씀) |  |
| 주입을 끄는 방법 (대조 실행용) |  |

## 판정 순서 (고정. 위에서부터 보고 걸리면 멈춘다)

1. **판정 불가:** 하네스 해시 불일치, 개선안 입력 오염, 평가 완료율 미달, 응답의 모델이 설정과 다름, 현재 버전에 고칠 실패 없음, 흔들림 폭이 최소 효과 이상
2. **기각:** 후보 실행에 정책 위반이 있거나 금지 경로를 건드렸다
3. **보류:** "평가 회귀가 없다"를 만족하지 못했다
4. **기각:** 읽기용만 오르고 판정용은 그대로다. **보류:** 판정용 개선이 최소 효과에 못 미친다
5. **보류:** 가드레일 상한 초과, 또는 바뀐 항목이 읽히고 인용된 기록이 없다
6. **보류:** 승인자가 승인하지 않았다
7. **보류:** 반영 전 최종 확인 실패 (승인받은 diff 그대로를 현재 버전 위에 적용, 하네스 해시·금지 경로 재검사, 개발용 평가 전체에서 2·3 재확인)
8. **채택:** 위를 모두 지났다. 커밋 하나로 반영하고 버전 표시를 올린다
9. 그 밖은 **보류**

## 검증 기록

| 확인 | 결과와 기록 위치 |
|---|---|
| 세션 A에서 남긴 경험이 새 프로세스의 세션 B에서 주입되고 계획에 인용됐다 |  |
| 주입을 끄고 같은 작업을 돌린 결과와의 차이 |  |
| 근거가 낡은 항목과 외부 입력에서 나온 항목이 주입되지 않았다 |  |
| 일부러 실패시킨 작업에서 개선안이 나왔고, 그 시점에 대상 파일은 바뀌지 않았다 |  |
| 금지 경로를 건드린 후보가 거부됐다. 하네스 파일을 한 글자 바꾸면 해시 검사가 멈춘다 |  |
| 같은 버전을 다시 돌려 잰 흔들림 폭 |  |
| 탈락한 후보가 반영되지 않았다 (버전 표시 그대로) |  |
| 채택분이 새 세션에서 읽히고 인용됐다 |  |
| 되돌리는 명령을 실제로 실행해 이전 버전으로 돌아갔다 |  |
| 반복된 실수를 더 강한 층으로 옮긴 사례 (경험 → 규칙 → 스킬 → 훅 → 테스트) |  |

인수 기준 3-4의 "통과한 개선안을 다음 작업에 반영"까지 보이려면 채택이 한 번은 있어야 한다. 고칠 수 있는 실패를 하나 준비해 둔다.

## 완료 기준
- [ ] 기억 → 조회 → 계획 인용이 새 세션에서 기록으로 확인됐고, 주입을 껐을 때와의 차이가 적혀 있다
- [ ] 개선 설정(손잡이, 고칠 수 없는 것과 막는 장치, 사례, 최소 효과, 승인자)이 결과를 보기 전에 커밋돼 있다
- [ ] 금지 경로 변경과 하네스 변조가 막히는 시험 기록이 있다
- [ ] 개선 라운드가 한 번 이상 기록됐다 (채택·보류·기각·판정 불가 중 무엇이든, 사유와 함께)
- [ ] 채택한 변경마다 전후 표, 회귀 결과, 승인자, 버전, 되돌리는 명령, 새 세션에서 쓰인 기록이 있다 (채택이 없으면 "채택 없음"과 사유)
