- 심각도 기준 (무엇이면 즉시 멈추나):

사고가 나면
1. 멈춘다: 스위치를 끄거나 이전 태그로 고정한다.
2. 알린다: 누구에게, 어디로.
3. 해당 요청 ID의 기록을 보존한다.
4. 적는다: 관찰 사실 / 원인 / 평가가 못 잡은 이유.
5. 그 사례를 평가셋에 넣는다.
6. 같은 일이 지침으로 안 막혔다면 더 강한 층(스킬 → 훅·권한 → 테스트·CI)으로 옮긴다.
7. 다시 켜는 조건을 확인하고 켠다.

## 평가셋으로 되먹임

주간 회고 순서: 기록 읽기 → 실패 분류 → 승격 후보 고르기 → S6 라운드 입력 → 더 강한 층으로 옮길 것 → 메모리 정리(만료, 해로움 표시, 중복).

| 기록 (요청 ID) | 고른 이유 (반복됨 / 재현 가능 / 정답을 정의할 수 있음) | 정답을 단 사람 | 넣은 곳 (개발용 / 최종 확인용) | 평가셋 버전 |
|---|---|---|---|---|
|  |  |  |  |  |

- 새로 승격한 사례는 아직 못 푸는 것일 수 있다. 회귀 판정에 쓰는 묶음에 바로 넣지 않고 표시해 두었다가 안정적으로 통과하면 옮긴다.
- 최종 확인용은 한 번 쓰면 닳는다. 쓴 만큼 운영 기록에서 새로 채운다.
- 승격한 사례는 `golden-dataset` 스킬로 동결하고 버전을 올린다.
