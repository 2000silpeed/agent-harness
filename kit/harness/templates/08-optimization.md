# P8. 최적화·개선

> 원칙: 동작이 바뀌면 안 된다(도구 호출 순서 포함). 모든 변경은 토글로 켜고 끈다.

|---|---|---|---|---|---|---|---|
| 1 | 컨텍스트 / 구조 |  |  |  |  |  |  |

## 검토한 항목
- [ ] 도구 수 줄이기
- [ ] 프롬프트 축소와 동적 제어
- [ ] 스킬 도입 지점
- [ ] 서브에이전트 분리(지연 기준)
- [ ] 작은 모델로 내리기
- [ ] 판단 구간을 디시전 모델로 교체

## 기록 기반 개선
| # | 근거 기록 (trace·평가 결과) | 개선 대상 (프롬프트 / 스킬 / 메모리) | 개선안 | 효과 측정 | 회귀 검증 | 반영 여부 |
|---|---|---|---|---|---|---|

## 게이트 (모두 체크해야 다음 단계)
- [ ] 변경·개선안마다 before/after 수치가 있다
- [ ] 변경 후 P7 평가를 다시 돌렸고 회귀가 없다
