[파일 경로]의 구조를 최적화하려고 합니다. `optimize-agent` 스킬을 따릅니다.

## 유지 기준 (변경 전에 고정)

아래를 지키는 변경만 받습니다. 도구 호출의 순서·횟수와 문구는 달라져도 됩니다.

- 평가 통과율이 흔들림 폭 안이다 (기준선: ___, 흔들림 폭: ___)
- 정책 위반 0건
- 과정 규칙 통과 (승인 전 수정 금지, 수정 뒤 테스트 실행)
- 최종 응답이 실제 변경과 일치한다

## 목표

- 통과 1건당 비용: 현재 ___ → 목표 ___
- 전체 시간 p50 / p95: 현재 ___ → 목표 ___

## 볼 것 (이 순서로, 한 번에 하나씩)

1. 캐시: 고정 내용이 앞에 얼어 있는가. 요청마다 바뀌는 값이 시스템 프롬프트나 도구 정의에 들어가 있지 않은가.
2. 입력: 안 쓰는 도구와 지침을 뺄 수 있는가. 프롬프트에 박힌 조각 지식을 스킬로 뺄 수 있는가.
3. 루프: 오류 뒤 같은 호출 반복, 묶을 수 있는 연속 호출, 코드로 끝낼 수 있는 판단이 있는가.
4. 출력: 응답 형식과 도구 호출 사이의 설명을 줄일 수 있는가.
5. 추론 강도·모델: 평가의 점수-비용 표로만 정한다. 분류·선택·예/아니오부터 본다.
6. 서브에이전트 분리: 위를 다 해도 목표에 못 미칠 때만 본다. 비용이 오를 수 있다.

## 근거

모든 변경에는 기존에 어떤 문제가 있었고(기록의 어느 요청), 무엇을 바꿨고, 전후 수치가 어떻게 달라졌고, 유지 기준을 통과했는지가 있어야 합니다. 변경마다 켜고 끌 수 있게 만듭니다.
