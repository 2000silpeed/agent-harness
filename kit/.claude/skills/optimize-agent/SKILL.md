---
name: optimize-agent
description: 동작하는 에이전트의 비용과 지연을, 미리 적은 유지 기준을 지키면서 줄인다(캐시 → 입력·루프·출력 정리 → 일괄 처리 → 추론 강도 → 모델 교체 → 여러 모델·서브에이전트 순). 변경마다 켜고 끌 수 있게 만들고 통과 1건당 비용의 전후 수치를 design/07-optimize.md에 남긴다. S7 단계, "더 빠르게/싸게" 요청 시 사용. 프롬프트·스킬 내용을 고쳐 품질을 올리는 일은 self-improve-loop가 맡는다.
---

<rules>
- **유지 기준을 먼저 적는다.** `design/07-optimize.md`의 "목표와 유지 기준"을 변경 전에 채운다: 평가 회귀가 없다(`harness/reference/eval.md`의 규칙 그대로), 정책 위반 0건, 과정 규칙 통과, 최종 응답과 실제 변경의 일치. 도구 호출의 순서와 횟수가 그대로일 필요는 없다.
- **단위는 통과한 작업 1건당 비용과 작업 1건의 전체 시간이다.** 호출당·토큰당 수치로 판정하지 않는다. 실패와 재시도에 쓴 비용도 넣는다.
- **품질을 걸지 않는 변경을 먼저 한다**(캐시, 입력·루프·출력 정리, 일괄 처리). 품질을 거는 변경(추론 강도, 예산, 모델, 서브에이전트)은 평가셋으로 만든 점수-비용 표가 있을 때만 적용한다.
- 변경은 하나씩, **토글**(환경변수나 설정 플래그)로 켜고 끌 수 있게 만든다.
- 변경마다 "기존 문제(근거 기록) → 무엇을 바꿨나 → 전후 수치 → 유지 기준 통과 여부"를 남긴다. 근거가 없거나 효과가 흔들림 폭 안이면 되돌린다.
- 남이 잰 수치는 근거가 아니다. 우리 평가셋으로 다시 잰다.
- 이 작업을 하는 코딩 도구는 가능하면 새 세션에서, 구현할 때보다 높은 추론 수준으로 돌린다. 대상 에이전트의 모델 설정과는 별개다.
</rules>

<procedure>
1. 유지 기준과 비교 조건(평가셋 버전, 반복 수, 캐시 상태)을 적고 사용자 확인을 받는다.
2. 요청 종류별 기준선을 잰다: 통과율, 통과 1건당 비용, 전체 시간 p50/p95, 첫 토큰 시간, 호출 수, 토큰, 캐시에서 읽은 비율, 재시도 수, 도구 실행 시간.
3. 기록에서 낭비를 찾아 "최대로 줄일 수 있는 양"과 함께 적는다. 작은 것은 버린다.
4. 아래 체크리스트를 위에서부터 본다. 변경 하나마다 평가를 다시 돌려 유지 기준을 확인한다. 응답에 찍힌 모델이 설정과 같은지도 본다.
5. 토글을 꺼서 이전 수치로 돌아가는지 확인한다.
6. S0 목표에 닿았거나 남은 레버의 예상 효과가 작으면 "더 줄이지 않는 근거"를 적고 끝낸다.
</procedure>

<checklist>
품질을 걸지 않는 것
1. 캐시가 실제로 맞는가. 고정 내용(도구 정의, 시스템 지시, 지침)은 앞, 바뀌는 값(날짜, 요청 ID, 주입한 메모리)은 뒤의 메시지. 대화 중에 도구 목록과 모델을 바꾸지 않는다. 적중을 사용량 필드나 서빙 지표로 직접 확인한다.
2. 도구 수를 줄일 수 있나(안 쓰는 도구 빼기, 비슷한 도구 합치기, 필요할 때 찾게 하기, 도구 출력 줄이기)
3. 프롬프트를 줄일 수 있나(예전 모델에 맞춰 쓴 과잉 지시 지우기, 조각 지식을 스킬로 빼기)
4. 루프에 낭비가 있나(오류 뒤 같은 호출 반복, 스크립트 하나로 묶을 수 있는 연속 호출, 코드로 끝낼 수 있는 판단)
5. 출력을 줄일 수 있나(응답 형식 정하기, 도구 호출 사이의 설명 줄이기)
6. 아무도 기다리지 않는 일(평가 실행, 야간 작업)을 일괄 처리로 돌릴 수 있나

품질을 거는 것 (점수-비용 표가 있어야 한다)
7. 같은 모델에서 추론 강도를 낮출 수 있나. 모델을 나누기 전에 먼저 훑는다.
8. 더 작은 모델로 처리할 수 있는 구간이 있나. 분류·선택·예/아니오부터 보고, 판단 구간은 판단 전용 모델로 바꾸고 출력을 선택지로 강제한다.
9. 서브에이전트로 떼는 것이 나은가. 독립 작업을 동시에 돌리거나 한 컨텍스트에 안 들어가는 일일 때만 이득이다. 부모의 캐시를 쓰지 못할 수 있어 비용은 오를 수 있다.

직접 서빙이면 `serving-plan` 스킬로 접두 캐시 적중, 대기열, 컨텍스트 상한, 양자화를 다시 본다.
</checklist>
