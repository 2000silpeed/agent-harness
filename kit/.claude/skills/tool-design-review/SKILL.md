<checklist>
**정의**
- [ ] 설명문이 충분하다: 무엇을 하는지, 언제 쓰고 언제 쓰지 않는지, 인자의 뜻, 제약. 한 줄짜리 설명은 결함이다(짧아야 하는 것은 스킬 설명과 상시 로드 지침이다)
- [ ] 인자에 타입과 설명, 입력 예시가 있다. 이름으로 실수를 막는다(`user`가 아니라 `user_id`)
- [ ] 복잡한 중첩 구조가 없다
- [ ] 비슷한 도구가 합쳐져 있다. 사람이 봐도 어느 것을 쓸지 헷갈리지 않는다. API를 1:1로 감싸지 않았다
- [ ] 도구 정의가 세션 중에 바뀌지 않고, 직렬화 순서가 고정돼 있다(캐시 접두)

**편집 도구**
- [ ] 모델이 줄 번호·줄 수·이스케이프를 세지 않아도 된다
- [ ] 일치가 0곳이거나 2곳 이상이면 조용히 넘어가지 않고 무엇이 문제인지 알린다
- [ ] 문법을 깨는 편집은 적용하지 않고 오류와 앞뒤 코드를 돌려준다
- [ ] 작업 폴더 밖 경로는 거부한다
- [ ] 쓸 모델로 적용 성공률을 쟀다

**반환**
- [ ] 범위·필터·페이지로 필요한 만큼만 돌려주고 기본값이 작다. 코드 읽기는 요약이 아니라 범위를 지정한 원문이다
- [ ] 응답 토큰 상한이 있고, 잘랐으면 잘렸다는 사실과 나머지를 보는 방법을 알린다
- [ ] 검색 결과가 상한을 넘으면 일부를 쏟아내지 않고 좁히는 방법을 돌려준다
- [ ] 테스트 실행은 요약과 실패 항목만 돌려주고 전체 로그는 파일 경로로 준다
- [ ] 출력이 없으면 "성공했고 출력 없음"이라고 적는다
- [ ] 식별자는 뜻이 있는 것(경로, 이름)이다

**오류**
- [ ] 빈 결과, 실행 오류, 연결 실패, 시간 초과를 구분한다. 실패를 빈 결과로 숨기지 않는다
- [ ] 모델이 고칠 수 있는 오류(잘못된 인자, 일치 없음)는 고치는 방법과 올바른 입력 예시를 준다
- [ ] 모델이 고칠 수 없는 오류(연결 실패, 권한 없음)는 재시도하지 말고 보고하라고 알린다. 숨기지 않는다
- [ ] 하네스가 자동 재시도한 일시 오류는 끝난 뒤 결과와 횟수를 알리고 기록에 남긴다

**실행**
- [ ] 오래 걸리는 작업은 요청 확인 → 진행 → 완료로 나눠 처리한다
- [ ] 순서가 중요하면 도구가 현재 단계를 확인하고, 어긋나면 거절하고, 다음에 할 일을 알려준다
- [ ] 여러 호출을 스크립트로 묶는 방식은 의존하는 호출이 3개 이상이거나 큰 결과를 집계할 때만 쓴다. 스크립트 안의 호출도 실행 전 검사를 거친다
- [ ] 변경 요청은 무조건 재시도하지 않는다(멱등성)

**MCP**
- [ ] MCP가 정말 필요한가: 명령줄 도구가 없거나, 인증을 서버가 맡아야 하거나, 여러 클라이언트가 같이 쓴다. 명령줄 도구가 있으면 셸로 쓰고 사용법은 스킬에 적는다
- [ ] 연결 뒤 실제 노출되는 도구 수와 정의 토큰을 쟀다. 많으면 자주 쓰는 것만 상시 로드하고 나머지는 필요할 때 찾게 한다
- [ ] 외부 서버가 주는 도구 주석(읽기 전용 등)을 믿지 않는다. 서버를 들이기 전에 읽고 버전을 고정한다
- [ ] 서버가 사용자별 권한을 검사한다. 목록 필터만으로는 권한 통제가 아니다
- [ ] DB 접근에는 가드레일을 둔다(쓰기 검토, 삭제 차단, 원시 SQL 직접 실행 금지)

**테스트**
- [ ] 모델 없는 단위 테스트, 모델이 포함된 도구 선택·인자 평가, 전체 평가가 분리돼 있다
- [ ] 목록 조회 성공에서 멈추지 않고 실제 호출·오류·거부 경로까지 테스트했다
- [ ] 지표가 있다: 도구별 오류율, 잘못된 선택 비율, 편집 실패율, 같은 호출 반복 횟수, 결과 토큰 분포
- [ ] 설명문·스키마는 한 번에 하나씩 바꾸고 선택 시험을 다시 돈다(한 도구의 설명이 다른 도구의 선택률을 바꾼다)
</checklist>
