name: project-kickoff
description: 새 에이전트 프로젝트를 시작할 때 사용자를 인터뷰해 design/00-brief.md(목표·완료 정의·성공 지표·평가 기준 체크리스트·개발 환경)를 채운다. 프로젝트 시작, 요구사항 정리, "뭘 만들지" 논의, P0 단계에서 사용. 이미 브리프 게이트를 통과했다면 쓰지 않는다.
---

<purpose>
막연한 아이디어를 "완료"가 정의된 작은 프로젝트로 바꾼다. 답을 추측해서 채우지 않고 사용자에게서 끌어낸다(4일차 `requirements-interview` 스킬과 같은 원칙).
</purpose>

<procedure>
1. `bash harness/scripts/start-phase.sh 00`으로 브리프를 만든다.
2. 질문은 **한 번에 하나**만 한다. 이미 답한 항목은 다시 묻지 않는다. 가능하면 선택지를 2~4개 제시한다.
3. 질문 순서:
   - 누가, 어떤 상황에서 쓰나? 지금은 그 일을 어떻게 하나?
   - AI가 **완전히 대체**할 수 있는 가장 작은 조각은 무엇인가?
   - 결과가 어떻게 나오면 "끝났다"고 말할 수 있나?
   - 성공을 무엇으로 재나? (성공률·지연·비용 목표값)
   - 쓸 수 있는 데이터, 권한, 모델, 예산, 마감은?
   - 하면 안 되는 일(쓰기·삭제·외부 발송)은?
4. **완료 기준 검사:** "잘 되면", "깔끔하게" 같은 기준은 받지 않는다. 실행 결과로 참/거짓을 가릴 수 있는 문장이 될 때까지 다시 묻는다.
5. 최종 프로젝트(dcode Coding Assistant)라면 브리프의 "평가 기준 체크리스트" 14행과 "개발 환경"을 함께 채운다. 근거 자료는 `harness/PLAYBOOK.md` 첫 절과 `harness/reference/dcode.md`다.
6. 범위가 크면 줄이자고 제안한다. 뺀 부분은 "이번에 안 하는 것"으로 옮긴다.
7. 다 채우면 요약해서 보여주고 확인을 받는다. 확인 뒤에만 게이트를 체크한다. 브리프를 바꾸면 그 이후 단계의 승인은 다시 받는다.
</procedure>

<anti_patterns>
- 질문 여러 개를 한꺼번에 묻기
- 사용자가 말하지 않은 목표값이나 제약을 지어내기
- 브리프가 끝나기 전에 아키텍처나 코드 이야기로 넘어가기
</anti_patterns>
