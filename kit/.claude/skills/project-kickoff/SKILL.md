name: project-kickoff
description: 코딩 에이전트 구축을 시작할 때 사용자를 인터뷰해 design/00-brief.md(대상 작업·기반·모델·완료 정의·성공 지표·금지 행동)를 채운다. 프로젝트 시작, 요구사항 정리, "뭘 만들지" 논의, S0 단계에서 사용. 브리프 완료 기준을 이미 통과했다면 쓰지 않는다.
---

<purpose>
막연한 목표를 "완료"가 정의된 작은 프로젝트로 바꾼다. 답을 추측해서 채우지 않고 사용자에게서 끌어낸다.
</purpose>

<procedure>
1. `bash harness/scripts/start-phase.sh 0`으로 브리프를 만든다.
2. 질문은 **한 번에 하나**만 한다. 이미 답한 항목은 다시 묻지 않는다. 가능하면 선택지를 2~4개 제시한다.
3. 질문 순서:
   - 누가, 어떤 저장소·언어에서 쓰나. 지금은 그 일을 어떻게 하나.
   - 에이전트에게 **완전히 맡길 수 있는** 가장 작은 작업은 무엇인가. 하나만 고른다.
   - 기반은 무엇으로 할까. `harness/bases/`에 그 기반의 참고 문서가 있으면 먼저 읽는다. 후보마다 소스 수정 가능 여부, 끼어들 지점, 사내 모델 연결, 라이선스를 확인한다.
   - 코드가 회사 밖으로 나가도 되는가. 안 되면 어떤 모델을 어떤 장비에 올릴 수 있나(`serving-plan` 스킬).
   - 결과가 어떻게 나오면 "끝났다"고 말할 수 있나. 성공률·지연·비용 목표값은.
   - 에이전트에게 절대 맡기지 않을 행동은.
4. **완료 기준 검사:** "잘 되면", "깔끔하게" 같은 기준은 받지 않는다. 실행 결과로 참/거짓을 가릴 수 있는 문장이 될 때까지 다시 묻고, 확인 방법을 옆에 적는다.
5. 범위가 크면 줄이자고 제안한다. 뺀 부분은 "이번에 안 하는 것"에 적는다.
6. 기반 후보를 설치하기 전에 구성(스킬·에이전트·훅·MCP)과 위험을 먼저 분석해 표에 적는다.
7. 다 채우면 요약해서 보여주고 확인을 받는다. 확인 뒤에만 완료 기준을 체크한다.
</procedure>

<anti_patterns>
- 질문 여러 개를 한꺼번에 묻기
- 사용자가 말하지 않은 목표값이나 제약을 지어내기
- 브리프가 끝나기 전에 설계나 코드 이야기로 넘어가기
</anti_patterns>
