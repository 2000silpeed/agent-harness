---
name: agent-eval
description: 동결된 시나리오 평가셋으로 에이전트를 실행해 Outcome/Trajectory/Final Response(스킬이면 Activation 포함)로 채점하고, 평가기를 반례로 검증하고, baseline과 candidate를 같은 조건에서 비교해 design/07-eval.md를 채운다. P7 단계, 프롬프트·스킬·모델을 바꾼 뒤 "나아졌나" 확인, 회귀 테스트에 사용. 평가셋 만들기는 golden-dataset이 맡는다.
---

<principles>
- 최종 답이 같아도 과정이 다르면 같은 성공이 아니다. Outcome / Trajectory / Final Response를 따로 본다(5일차 1강·교재).
- 에이전트 출력은 환경에서 읽은 결과(최종 상태, 궤적, 응답, 실행 상태)로 받는다. 자기 보고를 최종 상태로 쓰지 않는다. `expected_output`은 에이전트에 보내지 않는다.
- 명확한 사실은 코드, 의미 판단은 LLM Judge, 분류·예/아니오는 판단 모델, 이견은 사람이 맡는다.
- 정책·부작용 위반은 필수 관문이다. 다른 점수의 평균으로 상쇄하지 않는다.
- 판정 상태는 PASS / FAIL / INSUFFICIENT_EVIDENCE / EVALUATOR_ERROR / INFRA_ERROR. 누락을 분모에서 지우지 않는다.
- 비교는 조건(데이터 버전, 환경, 모델·프롬프트·commit·예산, 평가기 버전, 반복)을 잠그고 하나만 바꾼다. 승인 기준은 결과를 보기 전에 적는다.
- 평가 코드와 정답은 에이전트가 고칠 수 없는 곳에 둔다.
</principles>

<procedure>
1. **평가기 먼저 검증:** 고의로 변형한 반례로 평가기를 돌린다. 순서만 바꾼 정상 → PASS, 승인 단계 제거·다른 대상 쓰기 → FAIL, 증거 삭제 → INSUFFICIENT_EVIDENCE, 빈 정답 → EVALUATOR_ERROR. 하나라도 어긋나면 평가기부터 고친다.
2. **Judge rubric:** "0~1점 매겨라"만 쓰지 않는다. 등급(나쁨·보통·좋음)마다 관찰 가능한 기준, 최저·최고 점수, 출력 형식(JSON: 판정·이유·근거 단계)을 고정한다. 같은 조건으로 여러 번 돌려 흔들림과 점수 쏠림을 보고, 사람 라벨과 비교해 false pass를 잰다(5일차 3강).
3. **실행:** 유료 실행 전에 규모(시나리오 수 × 반복 × 버전 ≈ 호출 수)를 한 줄로 알린다. 매 시도마다 초기 상태를 복원한다. 실행 기록은 관측 플랫폼과 `eval/results/<버전>-<날짜>.jsonl`에 남긴다.
4. **채점:** 축별로 따로 기록한다. 궤적은 milestone, 도구 이름 Precision/Recall, 순서·정책, 반복·복구를 하나로 합치지 않는다. 순서 규칙은 같은 대상의 모든 쓰기 시도(실패·차단 포함)에 적용한다.
5. **실패 분석:** 최초 실패 지점을 찾고 Evidence(식별자, 관찰 사실, 위반 기준, 원인 가설, 수정 제안, 검증 계획)를 쓴다. 수정 지점을 매핑한다: 도구 설명 / 스키마·검증 코드 / 실행 가드 / 오류 계약 / 중단 조건 / 정답 기준. 모든 것을 시스템 프롬프트로 고치지 않는다.
6. **비교 보고:** 성공률, pass@k, pass^k, 평가 완료율, 정책 위반 수, slice별 개선·회귀, p50/p95 지연, 통과 1건당 비용. 반복 실행을 독립 사례로 세지 않는다.
7. **판정:** 미리 적은 승인 기준 순서대로 본다(판정 유효성 → 정책·부작용 0건 → 목표 개선·중요 slice 무회귀 → 신뢰성·예산 → holdout). 근거가 부족하면 보류다.
</procedure>

<cost>
모든 요청을 평가하지 않는다. 온라인은 샘플링, 배치는 "체크 필요" 표시된 기록 위주로 고르고 예상 비용을 먼저 계산한다(5일차 3·4강).
</cost>

<when_to_rerun>
모델, 스킬·프롬프트·도구 계약, 평가기·정답 기준이 바뀌었을 때, 운영에서 새 실패 기록이 생겼을 때 다시 돌린다. 기준이 바뀌면 두 버전을 모두 새 기준으로 다시 채점한다.
</when_to_rerun>
